## 4. 已核实的代码地雷

### 4.1 `save()` 当前会清空未传字段

`src/host/memory-store.ts` 同名更新路径当前：

- `pinned: params.pinned ?? false`
- `tags: params.tags ?? []`
- `source/confidence/personaTags` 也按本次入参重写

降级内存路径会保留 `pinned`，但 `tags/source/confidence/personaTags` 仍会被重置。实现时 SQL 与 fallback 两条路径必须共用同一合并语义。

### 4.2 现有 `content_hash` 不能直接拿来做跨名去重

当前 `contentHash(type, name, content)` 包含：

```text
type + lower(name) + normalized(content)
```

名称不同则 hash 不同，所以不能靠它实现“跨名称同内容去重”。建议新增独立 `dedupe_hash`：

```text
type + normalized(content)
```

并保留旧 `content_hash` 语义，避免静默改变既有兼容行为。

### 4.3 当前没有容量上限

> **已关闭（M10-7.3，`af608ab`）**：`MAX_MEMORIES=500`、确定性软归档、复活容量治理、全 pinned 拒绝与 SQL/fallback 同口径均已落地。以下内容保留为原始设计约束记录。

全仓不存在 `MAX_MEMORIES`。新增容量上限时，必须使用软归档而不是硬删，并保证：

1. pinned 永不淘汰。
2. project 非 pinned 先淘汰。
3. user 非 pinned 在需要时按最旧淘汰。
4. 全部不可淘汰时返回明确错误，不能悄悄丢数据。
5. SQL 与 fallback 排序必须一致。

### 4.4 `memory.select` 不能直接塞进同步发送链路

- `prepareOutgoingBody()` 与 `formatMemoriesBlock()` 是同步调用链。
- 宿主 RPC 是异步。
- 当前没有 `memory.select`。
- 因此 M10-8B 必须先设计预取/缓存/降级方案，PM 审核后才能实现。

### 4.5 `search()` 与 FTS5 已存在

不要重复造检索。`search()`、`memories_fts`、trigram、LIKE 兜底都在 `memory-store.ts`。

### 4.6 注入预算现状

> **已关闭（M10-8A，`0e8e4c6`）**：40 行 + 1800 token 双预算与宿主/页端共享 helper 已落地；以下内容保留为原始缺口记录。

- 40 行常量：`MEMORY_INJECT_LIMIT=40`。
- 宿主与页端共用该常量。
- 只有行数预算，没有 token 预算。
- 排序已在 `sortRows()`：`pinned → user → updated_at`。

### 4.7 `shell_exec` 工具面

- `shell.ts` 当前只对硬编码 `CMD_BUILTINS` 加 `cmd /c`。
- `.cmd/.bat` 没有按扩展名路由，`npx` 等会 `spawn-failed ENOENT`。
- PowerShell cmdlet 直接 spawn 也会 ENOENT，错误没有可操作提示。
- 安全红线不变：`shell:false`；禁止管道、重定向；只有明确识别出的 `.cmd/.bat` 才允许走 `cmd /c`，且参数仍要拒绝 cmd 元字符。

## 6. 目标模式执行协议

db 在目标模式中按以下循环工作：

1. 读取当前任务卡与相关源码。
2. 跑最小基线测试，确认“修前是红还是绿”。
3. 写最小实现。
4. 补正控 + 负控测试。
5. 跑专项测试。
6. 跑 typecheck。
7. 按 PM 要求决定是否跑全量/gate。
8. 报告证据，等待 PM 验收后再开始下一张卡。

### 6.1 强制停止条件

- 任务卡与源码事实不一致。
- 必须改任务卡未列文件才能完成。
- 既有测试期望与任务卡冲突，且无法证明旧期望错误。
- 需要改用户配置、真实数据库数据、QA 报告或另一个仓。
- 当前工作树出现自己未做的意外改动。

### 6.2 汇报模板

