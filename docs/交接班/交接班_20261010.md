## 1. 产品目标（已与用户定稿，勿改方向）

对标 Trae/Workbuddy/Qoder 的**编码智能体**：自然语言下指令，宿主多步自主执行（读/写文件、跑命令），用户不敲命令。

- 入口：Studio 专用对话面板（第二个 Tauri 窗口加载 `http://127.0.0.1:8756/agent`）；主窗口仍是 chat.deepseek.com（当模型引擎）。
- 模型引擎：**MVP 用 chat.deepseek.com 网页当后台模型（零成本）**，官方 API 引擎留占位（M3 再做）。
- 任务形态：Trae 式“打开文件夹”进项目编码，打开目录即权限边界（工作区）。
- 权限三档随时切换：① `workspace`（仅工作区，shell/越界硬拒绝）② `auto`（风险审批，默认）③ `full`（放开）。

## 2. 架构与数据流（务必看懂，否则会重复踩坑）

```
[主窗口 chat.deepseek.com]  ←(WebView2/Tauri)→  注入 entry.js
   │  模型回复里吐 XML 工具标签 <local_file_read>…</local_file_read>
   │  main-world-interceptor 解析 → host.sendToolCall()
   │  host-client(页内) ──ws://127.0.0.1:8756/studio──► [常驻 Node 宿主 :8756]
   │                                                              │
   │  (chat-insert/send 也经此通道派发回页面执行)                  │ invokeTool() 走完整授权链
   │                                                              │ + 同意闸门 + 宿主能力(file/shell)
   │  ◄── tool-call-result ───────────────────────────────────────┘
   │  interceptor 把结果 reinject 进下一轮请求（续跑）
   │
[智能体面板窗口 http://127.0.0.1:8756/agent]
   agent-panel.ts ──ws://127.0.0.1:8756/agent-ws──► [宿主 AgentChannel]
   发 send/stop/set-policy/set-workspace/pick-folder，订阅 AgentLoop 事件流
```

**关键点**：聊天页 ↔ 宿主的 `ws://127.0.0.1:8756/studio` 是**跨源**（https 公网页 → 本机 ws），受 Chromium **专用网络访问（PNA）** 限制，这是 `no-host` 的唯一真凶。面板窗口 ↔ `/agent-ws` 是**同源**（均 127.0.0.1:8756），不受 PNA 限制——所以面板能连、聊天页连不上。

## 3. `no-host` 根因与本次修复（最重要）

### 根因
Chromium（WebView2 ≥122）对“公网页连本机”的 WebSocket，会先发 **OPTIONS 预检**，并要求：
- 预检响应带 `Access-Control-Allow-Private-Network: true`
- **实际握手响应（101）也带该头**

旧代码只在 `server.ts` 处理了 OPTIONS 预检（`/studio` 已在 `WS_PREFLIGHT_PATHS`），但 `ws` 库发 101 时**默认不带** PNA/CORS 头 → 握手被静默断开 → 页端 `host-client` 永连不上 → `sendToolCall` 直接返回 `no-host`（见 `src/desktop/host-client.ts` 第 157-159 行）。

### 本次已做的修复（2026-10-10，已 typecheck + 重打包，但**未真机验证**）
文件 `src/host/page-runtime.ts`：
- 新增 `isPnaAllowedOrigin(origin)`（白名单 = `https://chat.deepseek.com` 或本机 host）。
- 在 `WebSocketServer` 上挂 `wss.on('headers', ...)`，对放行 origin 的握手补 `Access-Control-Allow-Origin` + `Access-Control-Allow-Private-Network: true` + `Vary: Origin`。

```bash
# 验证改动已落入打包产物
grep -c "Access-Control-Allow-Private-Network" src-tauri/inject/entry.js   # 应 > 0
```

> 注意：`server.ts` 第 84-98、182-198 行的 OPTIONS 预检处理**保留不动**（预检仍需要）。两处缺一不可。

## 6. 已知限制 / 架构风险（提前告知新 agent，避免白费力）

1. **回复完成检测是启发式**：`web-engine.ts` 靠“文本稳定 2 次（各 1.5s）”判断是否结束，长任务/流式输出可能误判。模型偶尔忘 XML 格式 → `RAW_TOOL_TAG_RE` 纠偏重试 1 次。
2. **web-engine 易碎**：chat.deepseek.com 改版/风控/限流/掉登录即断。M3 的官方 API 引擎是兜底（接口 `src/host/engine/model-engine.ts` 已定义，仅留占位）。
3. **PNA 是 web-engine 方案的硬约束**：跨源连本机 ws 必须持续维护 PNA 头（预检 + 101）。若未来把聊天页也搬成本地面板，此问题自动消失。
4. **工作区 safety**：`file.ts` 用 `realpath` 防软链逃逸；越界仅 `full` 档或用户同意才放行（见 `policy.ts`）。
5. **Diff 审查卡片是 M2**（MVP 用简单允许/拒绝弹窗）。

## 10. 环境坑速记（避免重复踩）

- `execute_command` 实为 PowerShell：`cd /d` 会报错，用 `cmd /c "cd /d <dir> && ..."` 或 `Set-Location`。
- 长任务（vitest / cargo）用 `cmd /c "start \"\" /min cmd /c \"... > log.txt 2>&1\""` 后台跑，再 `ping -n N & type log.txt` 轮询——10s 监控会截断前台长命令。
- `vitest` 的 `include` 只收 `tests/desktop/**`，host 层测试要放 `tests/desktop/`。
- cargo 链接慢是常态（debug 链接 5~10 分钟，link.exe ~1GB 内存，CPU 低但持续推进=正常）。
- 端口 8756 被占用时，先 `for /f "tokens=5" %a in ('netstat -aon ^| findstr :8756 ^| findstr LISTENING') do @taskkill /F /PID %a` 释放，再 `tauri:dev`。
