## 1. T9-1（P0，先做）· tool-bridge flaky 根治

**现象**：`tests/desktop/tool-bridge.test.ts` 全量并行下偶发失败，QA 实测单跑 13/13 绿（142ms），全量红。这是 gate 阻塞级的唯一已知红点。

**根因（PM 已定位，直接确认后修）**：

`tests/desktop/tool-bridge.test.ts:175`

```ts
host.connect();
// 等待 ws 连接建立
await new Promise((r) => setTimeout(r, 50));
```

用固定 50ms 睡眠等连接。并行负载下连接建立超过 50ms，`sendToolCall` 就落到 `no-host` / 超时分支 → `:178` 断言红。这不是产品缺陷，是测试基建竞态。

**修法**：`src/desktop/host-client.ts:331` 已提供 `onConnected(callback)`，改为事件等待 + 有界兜底（例如 `Promise.race([connected, timeout(2000) 后 reject 带明确信息])`）。同类固定 sleep 若在本文件其他用例存在，一并替换。

**硬要求**：

- 只改测试基建/用例等待方式，**不放宽任何断言、不删用例、不调大全局 timeout 掩盖**。
- 若确实需要超时兜底，超时必须显式失败并带「ws 连接超时」信息，不能静默继续。

**判据（全部要原始输出）**：

2. 单文件连跑 20 轮，20/20 通过（脚本里 `if ($LASTEXITCODE -ne 0) { exit }`）。
