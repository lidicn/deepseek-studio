## 2. 本轮交付详情（两个修复，都已真机验证）

### 2.1 v0.31 账号身份锁（commit `e6176e7`）

**问题**：用户报「4 账号开 5 窗口，某账号在两窗口都登了」。DeepSeek 风控盯「同一账号多窗口并发」= 封号判据（设计稿 §6 铁律「1 槽位 : 1 账号 : 1 窗口」）。

**根因（非直觉）**：单实例进程锁正常；profile-path 层 guard（`plan_bot_windows`）也够；**真正漏洞是 hello 协议只带 botId 不带账号身份**，宿主无从知道哪个窗口登了哪个 DeepSeek 账号 → 无法阻止「同账号登进两个不同 profile」。

**修复**：
- **注入层**（`src/desktop/host-client.ts`）：hello 上报 `accountFingerprint`——读 `localStorage['userToken']`（每账号稳定唯一），SHA-256 取前 16 字节 hex。**不外泄原始 token**（指纹只用于去重判定，不做安全断言）。storage 事件监听 userToken 变更（登出/换号）→ 重 hello 上报最新指纹。
- **宿主**（`src/host/page-runtime.ts`）：hello 登记指纹后查重——已有 trusted 页同指纹 → 该连接标 `untrusted`（复用现有不可信降级：dispatch/consent 一律拒绝）+ 推 `account-duplicate-block`。
- **页侧**（`src/ui/account-block.ts`）：`showAccountBlockOverlay` 全屏红底阻塞覆盖层（无 Esc/点外关闭，fail-closed），挡住 DeepSeek 交互直到用户关窗/换号。
- **协议**（`src/host/protocol.ts`）：hello 加 `accountFingerprint?`（向后兼容）；`HostToPageMessage` 加 `account-duplicate-block`。
- **enforcement 留 TS 层**（注入层阻塞覆盖层 + 宿主 fail-closed），不依赖 Rust 关窗——因 Rust↔Node sidecar 无通用命令通道。

**真机验证（2026-10-16）**：两 bot 窗口登同一账号 → 第二个弹阻塞覆盖层；宿主 stdout 见 `account-lock DUPLICATE`；不同账号互不影响。

**关键坑**：
- bundle 必须从仓库根 `node esbuild.inject.mjs` 重建 entry.js（入口 `src/desktop/entry.ts`）。entry.js 是 minified，grep userToken 返回 0 是正常的（旧注入根本不读账号身份）。
- ChatRoomEvent union（`types.ts`，CB 拥有）无 `system-alert` kind → 告警只走 console.warn，别用 `as ChatRoomEvent` 强转不存在的 kind。
- `desktop-entry.test.ts` 的 `document.addEventListener is not a function` 是**预先存在**的 jsdom shim 失败（基线同红），非本次引入。

详见内存 `account-identity-lock-v031.md`。

### 2.2 v0.32 聊天室回复不落 UI（commit `ebfc1b4`）

**问题**：用户报「@all 显示专家讨论中，窗口2/3 专家有发言但没落到聊天室 UI；问『有谁在』所有专家长篇大论」。

**根因链**：
`autoContinueWithPow` + `autoContinueNudge`（`src/inject/main-world-interceptor.ts`）的 `onreadystatechange` 在**每轮**无条件把 `loopState.autoReplyText` 推给宿主（`onAssistantReply`）。但工具回合的 autoReplyText 是 SSE 提取的纯文本——**仍含 `<shell_exec>…</shell_exec>` 原始工具标签**（`SseTextStreamExtractor.feed` 返回 visible 含标签，parser 的 clean 输出未被用于累积）。宿主 AgentLoop 见 content 含原始标签且 `toolCalls=0`（`forward()` 增 `toolCallCounter` 早于 `waitForNextReply` 取 `counterStart` 的竞态）→ 触发 `RAW_TOOL_TAG_RE` 格式纠偏循环 → 纠偏耗尽**永不 emit `{type:'assistant'}`** → `chat-room-runtime` 的 temp listener 捕不到 assistant 事件 → `rawReplyMap` 空 → 回合不完成 → **0 个 chat-room-event** → 专家回复不落 UI。

**修复**（两处推送点对称改，`main-world-interceptor.ts` ~938 / ~1065）：
1. 前置 `const hadTools = loopState.autoReplyHadTools`（forward 在工具回合置 true）。
2. `onAssistantReply` 调用门在 `!hadTools`（工具回合是中间态，拦截器已 forward+自动续跑，宿主不该拿半截文本）。
3. 推送前 `stripRawToolTags(reply).trim()`（新增 helper + `RAW_TOOL_TAG_GLOBAL_RE`），剥空则跳过推送。
4. 删 `autoContinueWithPow` nudge 分支重复的 `const hadTools` 声明。

**真机验证（2026-10-16）**：`chat-repro.cjs` 发 `@all 有谁在` → 旧 bundle 0 chat-room-event / 新 bundle 4（3 chat-bot-reply + 1 round-complete）。三专家回复正常落聊天室。

**残留行为问题（非渲染 bug，CB 范畴）**：问「有谁在」专家回 700~1400 字长篇（引用 AutoForge 目录、硬约束信封展开）。属 `mention-router.ts` / `instructions.ts` / persona prompt 调优，**CB 拥有不改**。可立工单给 CB 调「闲聊→简短应答」。

详见内存 `v032-chat-room-reply-not-rendering.md`。

## 5. 运行环境（真机当前状态）

### 5.1 进程拓扑
- **DeepSeek Harness.exe**（5 个，PID 3480/40500/5984/15640/31540）：**用户的独立程序，千万不要杀**。这是各 bot 窗口的载体。
- **deepseek-studio.exe**（1 个）：Tauri 主进程，注入 entry.js，创建 bot 窗口。
- **node sidecar**（1 个）：`tsx` 跑 host TS，监听 **127.0.0.1:8760**（HTTP API + WS）。

### 5.2 端口
- **8760**：sidecar HTTP + WS（`/agent-ws` bot 通道、`/studio` 页面通道、`/api/v0/chat/completion` POW 续跑）。
- **8762**：Lever-Hub API（旁支）。
- **9223**：CDP 调试端口（Studio Tauri WebView2，需 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223` 启动才开）。**9222 = 用户日常 Chrome，不是 Studio**。

### 5.3 启动 / 重启 Studio
```bash
# 杀（保留 DeepSeek Harness！）
taskkill //PID <deepseek-studio.exe PID> //F
taskkill //PID <8760 node PID> //F      # 先 netstat -ano | grep 8760 | grep LISTENING 找 PID

# 带 CDP 重启（debug exe，从仓库根跑）
cd "E:/NAS/deepseek-studio"
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223" src-tauri/target/debug/deepseek-studio.exe
```
**铁律**：改了 `src-tauri/inject/entry.js` 后必须 **taskkill Studio + 重启**才加载新 bundle——CDP `Page.reload` 或 F5 重新执行的是**旧固定脚本**（`initialization_script` 在窗口创建时固化为字符串）。见内存 `cdp-debug-tauri-webview2.md`。

### 5.4 构建
- **JS bundle**：`node esbuild.inject.mjs`（**必须从仓库根目录跑**，不是 src-tauri）。产物 `src-tauri/inject/entry.js`。
- **Host TS**：sidecar 用 `tsx` 直接跑，改了即生效（重启 sidecar）。
- **Rust**：`cargo build`（改 `main.rs` 才需要；profile guard 已在 v0.31 落地，6 单测绿）。
