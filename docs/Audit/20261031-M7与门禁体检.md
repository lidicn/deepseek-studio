## 四、建议（只写建议，不动手）

> 按影响/成本排序。每条都标了"若做，先做什么验证"，避免直接接线把红引进来。

**R1（对应 S0-1，收益最高）把 CI 改成调用 gate，而不是抄清单。**
给 `tools/gate/run.ts` 加 `--profile ci|local`（或 `--ci` 开关）：CI 只跑 `npm run gate -- --ci`，本地跑默认全量。差异用 profile 显式表达（例如 `upstream-drift` 需要读 `E:\NAS\deepseek-pp`，CI 上必须跳过；`e2e` 需要真机 CDP，CI 上跳过）。同时**必须先裁定 `security` 的口径**：要么两边都阻塞（会长期红，需先清零），要么两边都信息级（会丢失一个真实闸）。这条不裁定，合并清单只会把冲突搬进 gate。
先验证：`git grep -n "security" .github/workflows/ci.yml tools/gate/run.ts` 确认现状后，由 PM 拍口径。

**R2（对应 S0-2）把 `tools/**` 纳入类型检查，但要先量再接线。**
推荐 `tsconfig.tools.json`（`extends` 主配置，`include: ["tools/**/*.ts"]`，`types: ["node"]`）+ `npm run typecheck:tools`，先作为**信息级**跑一轮拿到错误数，再决定是否进阻塞级。理由：`tools/eval/run.ts` 的联合类型缺失已证明"一定能报错"，一次性升阻塞会让 gate 立刻红、逼人放宽——这正是要避免的。
先验证：`npx tsc --noEmit -p tsconfig.tools.json 2>&1 | Select-String "error TS" | Measure-Object -Line`（本卡按纪律**未**执行）。

**R3（对应 S0-3）`eval:golden` 进 gate 阻塞级，41 s 可接受。**
它是纯函数、不触网、确定性 100%（本次 40/40），是现有尺子里最该进闸的一条。若嫌 41 s 长，可先做信息级观察一轮，但不宜长期停在门外。
先验证：`npx tsx tools/eval/run.ts`（本次已跑，40/40，41 175 ms）。

**R4（对应 S1-4）doc-drift 二选一：要么做成真检查，要么改名降级。**
建议**先做可机械验证的那一半**：扫 `docs/**/*.md` 里出现的 `src/...` 路径与 `tools/...` 路径，断言文件存在；这比"4 个符号存在"有价值得多，且不会误报。设计稿是否进计划是用户的决定，但"设计稿里引用的文件路径已不存在"是纯事实，与计划无关。
若不做，至少把 CI 步骤名改成 `symbol-existence`，避免"doc-drift 绿"被当成文档结论。
先验证：`rg -o "src/[A-Za-z0-9_./-]+\.ts" docs --no-filename | Sort-Object -Unique | Measure-Object -Line` 看要断言多少条（本卡未执行，属建议范围）。

**R5（对应 S1-5）漂移检测补"适用性"，并把锚点文档数字改对。**
① 在每条漂移后加一列判定：`死移植` / `本地重写（上游改动不适用）` / `上游改动可能适用` —— 前两类不进待办清单，只有第三类进，噪音立刻自解释（F2 §4.2 的剩余部分）。
② `上游快照锚点-UPSTREAM.md`：`7 → 5` 件、`260/374 → 414/543`，并把"锚点唯一真相在文件头，本文档只是索引"写明（现在两处数字都在漂）。
③ `markdown.ts` 的"本地改动回灌上游"单独开工单，别挂在漂移检测里。
先验证：`git -C E:\NAS\deepseek-pp\src log --oneline 187f6227..HEAD -- core/inline-agent/prompt.ts | Measure-Object -Line`。

**R6（对应 S1-6）e2e runner 加断言，否则这一步该删。**
最小改法：fixture 增加 `expect: { stopReason: "..." }`，runner 比对失败即 `exit 1`。本次实测 `empty-response` 也算绿，说明当前 fixture 连"跑通"都没证明。
先验证：`npx tsx tools/e2e/runner.ts tools/e2e/fixtures/simple-task.json`（本次已跑，见 §2.5 旁证 / §2.2）。

**R7（对应 S2-7）`gate-info.log` 按大小/日期轮转，保留最近 N 次。**

**R8（对应 S2-8）tmp-cdp 收编成 `tools/e2e/cdp/`。**
最小集：`client.mjs`（connect/send/evaluate/listContexts/navigate/screenshot）+ `probe-dom.mjs`（选择器漂移探测，来自 `tmp-cdp3`）+ `send-message.mjs`（React 兼容发送，来自 `tmp-cdp4`）。统一用 Node 内建 `WebSocket`，URL 匹配参数化。收编后再谈把"真机冒烟"接进 gate——**不要**在 CI 上跑（无 CDP）。

**R9（对应 S2-9）向用户要真实 API key，拿到后跑一次真机 api-engine 冒烟，再决定 api-engine 是否进 eval 覆盖面。** 在此之前，任何"api-engine 可用"的结论都不成立。
