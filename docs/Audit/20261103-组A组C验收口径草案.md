## 组 A · MCP 连接生命周期（5 条一次收口）

**范围文件**：`src/host/mcp-controller.ts`（唯一）。
**涉及**：R2-04（testConnection 无 finally）、BUG-036（connect 失败只 delete 不 kill）、BUG-027（并发 connect spawn 两份）、BUG-038（两处 5000ms 超时无 clearTimeout）、BUG-039（tools/list 不查 res.ok）。
**现状证据**（20261103 复核，施工前基线）：
- testConnection `:1088`/`:1104` 超时 reject → `:1110` catch 返回，无 finally kill（仅 `:1092`/`:1107` 显式 kill）；
- connectStdio 统一 cleanup `:691-705` 只摘监听 + `connections.delete(:704)`，不 `proc.kill()`；
- connect `:626` / connectStdio `:649` 无 connecting 去重；
- `:1088`/`:1104` 两个 `setTimeout(...,5000)` 的句柄从未 clearTimeout；
- testHttpConnection `:1149` tools/list 直接 `json()`，未查 `res.ok`（对照 `:1130` initialize 已查）。

### A-1 R2-04 · testConnection 全路径 finally kill

- **修法要点**：stdio 分支整体包 `try { … } finally { killTree(proc) }`（killTree 实现自定：`proc.kill()` 即可，进程已退出时 kill 无害）。**所有** return/throw 路径都必须经过 finally。
- **验收断言（行为级，打真实入口 `testConnection`）**：
  1. 假服务器：`node -e "process.stdout.write(JSON.stringify({jsonrpc:'2.0',id:0,result:{}})+'\n'); setInterval(()=>{},1e6)"`——响应 initialize、**不响应** tools/list、保活不退出。
  2. 把 `:1088`/`:1104` 的 5000ms 抽成可注入常量（如 `export const TEST_STEP_TIMEOUT_MS = 5000`，测试注入 100ms），触发 tools/list 超时。
  3. 断言：`testConnection` 返回 `ok:false`；且**返回后 1s 内** spawn 出的子进程已退出（测试里对 spawn 加 wrapper 记录 pid，轮询/监听 exit）。
- **负控**：把 finally 中的 kill 删掉 → 上述用例红（进程 1s 内仍存活）。

### A-2 BUG-036 · connectStdio 失败路径 kill

- **修法要点**：`cleanup()`（`:691-705`）追加 `try { proc.kill(); } catch {}`——exit/error 两条腿共用，进程已退出时无害。
- **验收断言（行为级）**：假服务器同上（永不响应 initialize）→ `connect(serverId)` 超时失败 → 断言 spawn 出的子进程 1s 内退出。
- **负控**：删 cleanup 里的 kill → 用例红。

### A-3 BUG-027 · 并发 connect 去重

- **修法要点**：`private connecting = new Map<string, Promise<McpServerConnection | null>>()`；`connect()` 先查表命中即返回同一 Promise；settle（成功或失败）后从表移除（`finally`）。
- **验收断言（行为级）**：`Promise.all([connect(id), connect(id)])` 并发两次 → spawn 恰好 **1 次**、两次拿到同一连接实例。spawn 计数用 `vi.mock('node:child_process')` 截获（mock 只替换进程边界，入口仍是真实 `connect`）。
- **负控**：去掉去重 → spawn 计数 = 2 → 红。

### A-4 BUG-038 · 两处 5000ms 超时无 clearTimeout

- **修法要点**：`:1088`/`:1104` 的 setTimeout 句柄存变量，settle（resolve 或 reject）时 `clearTimeout`；随 A-1 的 finally 兜底再清一次。
- **验收断言（确定性，不依赖 wall-clock）**：`vi.useFakeTimers()` 下走一遍失败路径 → `vi.getTimerCount()` 为 0（无残留定时器）；成功路径同样断言。
- **负控**：删 clearTimeout → getTimerCount > 0 → 红。

### A-5 BUG-039 · tools/list 补 res.ok

- **修法要点**：`:1149` 前补 `if (!toolsRes.ok) return { ok:false, error: \`HTTP ${toolsRes.status}: ${toolsRes.statusText}\` }`（与 `:1130` initialize 同型）。
- **验收断言（行为级）**：本地 http fixture——initialize 返 200、tools/list 返 **500** → `testHttpConnection` 返回 `ok:false` 且 error 含 `HTTP 500`；fixture 全 200 → 现有成功路径不回归。
- **负控**：删 res.ok 判断 → fixture 500 时用例红。

- 既有 mcp 相关测试（`host-side-tools.test.ts`、F11 掩码用例、BUG-037 的 SSE 用例）全绿；**BUG-037 工作树修复不许回退**。

## 组 C · api/server.ts（4 条一次收口）

**范围文件**：`src/api/server.ts`（限流器若抽模块，新文件放 `src/api/` 内）。
**涉及**：TD-10（params 零校验，=BUG-023）、TD-12（限流桶只增不删，=BUG-021）、TD-13（audit ?limit= 空串 clamp 到 1，=BUG-025）、BUG-024（readBody 超限不 destroy/drain）。
**现状证据**（20261103 复核）：`server.ts:679` params 直通；`:399-413` buckets 只 set 不清；`:626-627` `Number('')=0`→clamp 1（`:826` 同型）；`:1015-1020` 超限只 reject。

### C-1 TD-10 · /v1/tools/execute params 形态校验

- **口径（最小收口，逐工具 schema 不在本卡）**：`body.params` 必须是 plain object（非 null、非数组）；序列化体积上限（建议 1MB，独立于 10MB body 上限）；违规 → 400 `bad_request`。
- **验收断言**：
  1. `params` 为 `null` / `[]` / `"str"` / `42` → 400；
  2. 合法 object → 行为不变（既有 execute 用例全绿）；
  3. 超限 params（>1MB）→ 400/413，不进 toolExecutor。
- **负控**：删形态校验 → 用例 1 红。

### C-2 TD-12 · 限流桶回收

- **口径**：惰性过期（请求命中时清该 key）+ 兜底 sweep（`setInterval(...).unref()`）或容量上限（超上限清最旧）；**限流行为本身不变**（超限仍 429）。
- **验收断言**：限流器抽成可注入小类或导出测试口径（如 `_rateLimiterSize()`，标注 test-only）→ 伪造超过上限的 key 数后 `size` 有界；既有超限 429 用例不回归。
- **负控**：删 sweep/上限 → size 无界 → 红。

### C-3 TD-13 · limit 解析统一

- **口径**：统一 `parseLimit(raw: string | null, fallback: number, min: number, max: number)`——`null` / `''` / 非有限数 → fallback；数值 clamp [min,max]。`server.ts:625`（audit）与 `:826` 两处都换用。
- **验收断言**：`?limit=`（空串）→ 50；`?limit=abc` → 50；`?limit=0` → 1；`?limit=99999` → 500；`?limit=25` → 25。
- **负控**：回退 `Number('')` 直算 → 空串用例红。

### C-4 BUG-024 · readBody 超限 destroy

- **修法要点**：超限分支（`:1015-1020`）与超时分支在 reject 前先 `req.destroy()`。
- **验收断言（行为级）**：起真实 server fixture，POST 超过 10MB 的 body → 客户端连接被服务端**提前关闭**（socket error/close，客户端不等 30s 写完）；正常大小 body 不受影响。
- **负控**：删 destroy → 客户端能一直写完（连接不提前关）→ 用例红。
