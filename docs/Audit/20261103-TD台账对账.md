## 六、TD-08 调用点判断依据（resolveWithinExisting 该用在哪，20261103 Gate 按 PM 裁决 4 出具）

生产调用点全量（grep `\.resolveWithin\(` = 4 处 + 1 处代理透传）：

| 调用点 | 操作语义 | 判定 | 理由 |
|---|---|---|---|
| `src/capabilities/file.ts:48`（`target()` 共用解析） | **read / list / write 三操作共用** | **按操作分流**：read、list → `resolveWithinExisting`；write → 保持原语义 | read/list 的目标不存在是必然失败（现在只会报更模糊的错）；write 的核心语义就含「新建文件」，改成 Existing 会把 file.write 新建文件全废——正是 PM 说的"不能一刀切"的那个点。实现上给 `target()` 加操作参数或拆两个解析入口 |
| `src/capabilities/edit-engine.ts:203` | 对**既有文件**做替换编辑 | **Existing** | edit 的语义是改文件不是建文件；新建走 file.write。目标不存在时现在会滑到后面才失败（或误报 outside-workspace），提前报 `target-not-found` 更准 |
| `src/capabilities/search-files.ts:131` | 搜索根目录 | **Existing** | 根不存在无法枚举；顺带把现在的报错从 `outside-workspace` 区分出 `root-not-found`（TD-01 修复后的回归保护） |
| `src/capabilities/test-runner.ts:122` | 测试运行 scope 目录 | **Existing** | scope 不存在 vitest 必然失败，早失败并报 `scope-not-found` |
| `src/host/workspace.ts:231`（MutableWorkspaceContext 代理） | 透传 | 无需单独处理 | 变体加在 `createWorkspace` 返回对象上（`:193` 旁），代理自动获得 |
| （新调用点）R2-06 project.create 修复时 | mkdir 前的路径校验 | **Existing**（对父目录） | R2-06 的修法本就该卡工作区边界；用 Existing 顺带堵「路径不存在也 mkdir 到任意深」的语义 |

**判定原则一句话**：目标「不存在即操作必然失败」的调用点用 Existing；「不存在是合法输入（要创建）」的调用点保持原语义。全仓现 4 个生产调用点里，3 个整体 Existing、1 个按操作分流，无一处需要为 Existing 牺牲现有功能。

**验收建议**（给未来的 TD-08 卡）：`resolveWithinExisting` 对不存在目标返回 null 并由调用方报 `target-not-found`；负控 = 把 file.write 的解析也换成 Existing → 新建文件用例红（锁住"按操作分流"这个设计）。
