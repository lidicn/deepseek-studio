## 一、term-state.ts 新增 E 节：三组频率指标

沿用 Verify《20261102-chat-frequency-测量.md》的既定口径（同一数据源同一分组键，数字可直接对照）：

- **分组键**：`turnId` = 一次用户消息触发的全部请求；**轮数 = turn.end 事件数 ≈ 请求数下界**（HTTP 重试/截断重发在 interceptor 内无 trace 打点，真实请求数 ≥ 轮数，报告中明确标注）。
- **间隔口径**：同 turnId 相邻 turn.end 的 `ts` 差；**>30min 记跨时段、剔出连发统计**；缺 `ts`/倒挂单列为异常对，不污染最小值。
- **判读铁律（写死在报告节里）**：字节类只回答成本（Σ bodyBytes），频率类只回答请求表面积（E1/E2/E3），两者不互相推论，**不合成「所以被限流」类结论**。

| 组 | 实现 | 输出 |
|---|---|---|
| E1 每任务请求数分布 | 全部 .jsonl 的 turn.end 按 turnId 全局分组（跨文件同任务合并），线性插值分位 | 任务数、事件总数、P50/P90/max、>10 任务数与占比 |
| E2 同任务相邻间隔(ms) | 同任务按 ts 排序取相邻差 | 会话内样本数、跨时段对、异常对、P50/P90、min/max、≤5s「快速重发对」数与占比 |
| E3 重试占比（可测口径） | 截断类终态（truncated / continuation-truncated / truncated-tool-tag）轮之后同任务仍有后续轮 → 该轮记一次截断重发 | 含重发任务数、重发轮数/有归属轮总数占比；**retryable HTTP 重试 = 数据源缺失，缺报不编数** |

导出面（可单测）：`collectTurnEvents` / `quantile` / `buildFrequencyReport` / `CROSS_SESSION_MS` / `FAST_RESEND_MS`；退出码语义不变（频率节不参与 0/1/2 判定）。
