## D-1 · TD-05 健康判定加进程存活

- **修法要点**：把「健康」收敛为组合谓词——`probe_health() && 子进程仍存活`。子进程存活判定用现成的 `child.try_wait()`（`:151` force_kill 里已在用）：`matches!(child.try_wait(), Ok(None))` = 还活着。实现上 probe_health 是自由函数拿不到 child，建议收敛成 `SidecarSupervisor` 的方法或 `fn is_healthy(child: &Child) -> bool`（内含 probe + try_wait），监控循环（`:520-560`）与 restarts==0 特例分支都改用同一谓词——**特例分支的语义保持**（「端口有人应答但 health 超时」仍按现口径处理，只是前置条件加"宿主进程还活着"）。
- **验收断言（Rust 单测，cargo test）**：
  1. 子进程活着 + probe 通过 → is_healthy = true；
  2. 子进程已退出 + 端口仍被无关进程应答 → is_healthy = **false**（这正是缺陷场景：现在会误判健康、不清理不重启）；
  3. 子进程已退出 + 端口无人应答 → is_healthy = false。
- **负控（必须能转红）**：把 is_healthy 里的 try_wait 分支删掉（退回纯 probe）→ 用例 2 红。
- **测试落点**：`src-tauri/src/sidecar.rs` 内 `#[cfg(test)]` 模块（仓库现有 Rust 测试惯例）或 `cargo test --manifest-path src-tauri/Cargo.toml`。行为级真机复验归 Verify（不在本卡）。

- **修法要点**：`config-loader.ts:112` 换成 `parsePort(raw: unknown, fallback = 8760): number`——非有限数 / 非整数 / `<1` / `>65535` → 回落 fallback（与同函数 `isPolicyMode` 的 fail-safe 风格一致）；合法值原样通过。**sidecar.rs 的 HEALTH_PORT 常量不动**（TD-06 裁决）。

## D-3 · TD-09 sidecar 日志保留上限

- **修法要点**：
  1. `spawn_child` 落运行日志前调 `retain_logs(log_dir, keep = 20)`——只删 `sidecar-*.log` 里最旧的，保留最近 20 个（按文件名里的 epoch_ms 排序即可）；
  2. `write_crash_log`（`:432-449`）给 crash.jsonl 加大小上限：超过 2MB 时 rotate 成 `crash-<epoch_ms>.jsonl` 再继续（同样受 retain 约束）。
- **验收断言（Rust 单测）**：
  1. tmpdir 造 25 个 `sidecar-*.log` → `retain_logs(dir, 20)` 后剩 **20 个**且删的是最旧 5 个；
  2. crash.jsonl 写入超 2MB → rotate 触发、新条目落新文件；
  3. 目录里混有其他文件（非 `sidecar-*.log`）→ 不被误删。
- **负控（必须能转红）**：删 `retain_logs` 调用 → 用例 1 红（25 个全在）。
