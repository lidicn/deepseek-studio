## 2. 严格按回复单落地的关键决策

- **单连接复用（方案 A）**：`ChatMessageStore`/`SnapshotStore` 构造时传入 `MemoryStore`，复用 `getDb()` 的同一 `DatabaseSync`；新表 `chat_messages` 与 `chat_snapshots`（含 CAS 租约字段 `lease_token`/`lease_expires_at`）。降级模式双方各自内存数组，`getDb()=null` 时自动走内存实现。
- **id 格式**：`msg-<base36时间戳>-<6位随机>`。随机段每位取 `[0,36)` 下标，**保证恰好 6 个 base36 字符**（直接 `byte.toString(36)` 是变长，已踩坑修正）。
- **participantId = persona 名**（如 `audit-expert`），非 botId。
- **摘要器留桩**：`defaultStubSummarizer` 可注入；`ContextEngine`/`RoomSummaryService` 均以构造参数注入 `ChatSummarizer`，v0.27 你接真实 `ModelEngine`。
- **systemPrompt**：v0.26 只放 `summary`；预留 `personaInjector` 钩子（`buildContext` 可选入参），非空时 `systemPrompt = personaInjector({...})`。
- **per-room 压缩锁**：`_compressLocks: Map<roomId, Promise>`，串行化同房间压缩；无新消息可压时不调 summarizer（并发下第二个调用零调用）。
- **CAS 租约**：`SnapshotStore.claim/commit/release/recoverExpiredLease`，`commit` 以 `version===expectedVersion && lease_token===token` 双重校验，防并发覆盖。
- 消息不加 FTS5；不导出聚合门面（四类各自独立，你从 desktop-host 直接调用）。
