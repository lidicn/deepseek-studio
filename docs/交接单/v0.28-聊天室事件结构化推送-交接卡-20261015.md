## 一、本批次 CB 已交付

### Task A — onBotReply 结构化推送（核心，CB 数据/算法层完成）

**目标**：让 UI 拿到「干净、带 roomId、可直接渲染」的聊天室事件，与引擎层原始事件（AgentLoopEvent）解耦，支撑多房间事件隔离。

**方案 B（采纳）**：新开 `ChatRoomEvent` 类型，**不走 `AgentLoopEvent`**。由接线层在 `desktop-host` 的 `onBotReply`/`onSummary` 回调里经 `agentListeners`/`agent-channel` 单独 broadcast。

改动文件：

1. `src/host/bot/types.ts`（新增，契约）
   - `ChatRoomBotReplyEvent`：`kind:'chat-bot-reply'` + `roomId / persona / botId / senderType / content / messageId / timestamp`
   - `ChatRoomSummaryEvent`：`kind:'chat-summary'` + `roomId / summary / throughMessageId / timestamp`
   - `ChatRoomEvent` 联合类型（UI + 多房间隔离的唯一事件源）
2. `src/host/bot/chat-room-runtime.ts`
   - `BotReplySink` 签名改为 `(event: ChatRoomBotReplyEvent) => void`
   - 新增 `SummarySink` + `onSummary` 选项
   - `handleUserMessage` 每条 bot 回复落盘后，构造**完整** `ChatRoomBotReplyEvent`（含 `messageId`/`timestamp`）经 `onBotReply` 推出
   - 摘要落快照成功后（`summaryService.getSummary(roomId).status==='success' && lastMessageId`），经 `onSummary` 推出 `ChatRoomSummaryEvent`

> CB 只在数据/算法层把**数据准备好**（payload + 摘要结果包装成结构化事件）。**emit 归 Claude（接线层）**——`desktop-host.ts:710` 当前是 no-op，需接线广播。
