### Q5 systemPrompt 形态 → 字符串 + personaInjector 钩子

`ChatContext.systemPrompt` 是 **string**。v0.26 只放房间摘要：

```ts
systemPrompt = summary  // 房间摘要文本
```

已在契约里预留 `PersonaInjector` 钩子（types.ts）：

```ts
export type PersonaInjector = (ctx: {
  agentName: string; roomName: string; agentDescription: string;
  memberNames: readonly string[]; summary: string;
}) => string;
```

`ContextEngine.buildContext` 接受可选 `personaInjector`。v0.26 传 undefined 时 systemPrompt 只含 summary；v0.27 我传入 `buildAgentInstructions` 实现后，systemPrompt = personaInjector({ ..., summary }) 的返回值。

**你现在不需要预留 persona/room/成员信息字段在 ChatContext 里**——这些通过 buildContext 的入参传入（已在签名里：roomName/agentDescription/memberNames 都是可选入参）。

### Q6 字段语义 → 以 types.ts 为准

你拟的草稿与我的契约一致。以 types.ts 为准。关键确认：

- `ChatMessage.senderType: 'user' | 'main-bot' | 'sub-bot'` ✅（三态，你的草稿对）
- `StructuredMention: { type: 'all' | 'agent'; participantId?: string }` ✅
- `ChatContextSnapshot` 字段与 Ekko `GroupRoomSummary` 对齐 ✅

**一个细节**：`participantId` 在 `@前端专家` 时填什么？填 persona 名（如 `'audit-expert'`），还是 botId（如 `'bot-S1'`）？

**答**：填 **persona 名**。理由：聊天室里 bot 的身份是人设（「前端专家」），不是槽位号。同一槽位换人设后，@旧人设名不应命中。persona 名是稳定的语义身份，botId 是运行时实例标识。`resolveMentions` 的 `participants` 参数应该传 `[{ name: personaName }]`。

### Q7 id / timestamp 约定

- **id**：`msg-<base36时间戳>-<6位随机>`，与你的 `Memory.id`（`mem-...`）同款生成法。
- **timestamp**：`Date.now()`（毫秒）。
- 不用 uuid v4（保持与 Memory 一致风格，且 base36 时间戳天然有序，利于按时间排序）。
- 不用房间内自增（多写入者并发时自增会冲突，时间戳+随机更稳）。

- ChatMessageStore 构造时传入一个指向临时文件的 MemoryStore。
