## 1. 需要你拍板的疑问（★ 为阻塞项）

### ★Q1 RoundOrchestrator 的回复从哪来？（最关键）

契约 `planRound({trigger, room, participants})` 入参**不含任何回复文本**，但返回的 `ConversationRound.contents`（各 persona 净回复）和 `pendingHandoff`（需解析回复里的 @接力）都**依赖真实回复文本**。纯算法不能自己调 bot。

我的方案：**构造时注入 `generateReply` 回调**，v0.27 由你接 WebEngine，v0.27a 测试用桩。拟签名：
```ts
type ReplyGenerator = (persona: string, ctx: {
  trigger: ChatMessage; room: RoomConfig;
  priorContents: Record<string, string>;   // 本轮已产生的净回复（后者读前者）
  participants: readonly Participant[]; spokenOrder: readonly string[];
}) => Promise<string>;
new DefaultRoundOrchestrator({ router, handoffParser, participantResolver, generateReply, maxDepth })
```
请确认：① 注入方式用**构造参数**可以吗（契约定死 planRound 入参，不宜加字段）？② `generateReply` 的入参 ctx 你 v0.27 接线时需要哪些？够不够？

### ★Q2 maxDepth 的语义：波数还是跳数？

我理解为 **maxDepth = 单次 planRound 内执行的「回复波数」上限**：
- 默认 `maxDepth:1` → 只跑第 0 波（路由 targets），其回复解析出的接力目标**不执行**，直接进 `pendingHandoff`。
- 这与验收示例一致：`@前端专家` → 仅「前端专家」回复 → `pendingHandoff=['backend-expert']`（后端本轮不答）。
- `maxDepth:2` → 追加执行第 1 波（pendingHandoff 里的人真的回），第 1 波再解析出的接力才进 `pendingHandoff`。

请确认这个语义（波数）对不对，还是你要的是「跳数」（默认 1 = 允许 1 次 A→B 接力在本轮执行）？两者实现与测试写法不同，想一次对齐。

### ★Q3 两轮编排怎么驱动？（任务#6）

`planRound` 是单轮，任务#6 却要「A 提点 B → B 回」**两轮**单测。但 `pendingHandoff` 是**输出**，而 `planRound` 入参只有 `{trigger, room, participants}`，没有「从 pendingHandoff 续轮」的入口。

我的方案：保持契约不变，两轮 = **调用方连续调两次 planRound**（第 2 轮用一个能路由到 B 的 trigger；生产环境由你 v0.27 接线层决定第 2 轮 trigger）。
请确认：① 这样保持 planRound 契约为最小集、不加 `seed/pendingHandoff` 入参，可以吗？② 还是你希望 RoundOrchestrator **额外提供一个**（契约外的）便捷方法如 `planFollowUp(prevRound, ...)` 来续轮？（若要，属于契约新增，我走 PR + description。）

## 2. 次要疑问（我有默认取值，你若不同意请纠正）

- **Q4 HandoffParser 净内容是否也剥离「未注册」的 @名？** 我默认：净内容剥离**所有** @标记（含未注册名和 @all），让存储/显示的文本干净；未注册名只进 `unresolved` 上报，不出现在净内容里。若你希望未注册 @名**保留在净内容**里（方便用户看到拼错的名字），告诉我。
- **Q5 MentionRouter：@具体名指向非房间成员时？** 我默认：该提及被过滤掉，`targets` 只保留房间成员；若过滤后为空但**确实发生过 @具体**，仍返回 `mode:'mention'` + 空 targets（不回退到 @all/none）。你若希望「@的人都不在房 → 回退主持人/none」，告诉我。
- **Q6 ParticipantResolver.has 语义？** 我默认 `has(name, room) = room.memberPersonas.includes(name)`（只看房间成员配置，不管是否注册）；`resolve` 才要求「在房 + 已注册」否则 undefined；`all` 按 memberPersonas 顺序返回**已注册**成员。认可吗？
- **Q7 集成测试范围？** 我计划加一个可选集成测：串 `ContextEngine.buildContext(personaInjector = createAgentInstructionBuilder().build)` + 四个新类，验证「人设指令注入 + 路由 + 接力」端到端。这会 `import` 你的 `instructions.ts`（只读消费，不改）。你希望我加这个集成测，还是严格只做四类的独立单测？
