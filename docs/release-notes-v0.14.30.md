# v0.14.30 发版说明

发布日期：2026-11-23（tag `v0.14.30`；本版修复**关掉 MCP 后 agent 仍宣称有那些工具**的问题——注入层的 MCP 工具清单此前只在启动时拉一次，运行期永不刷新）

## 这版修了什么

### 1. 关掉 MCP 后，模型仍然说「有这些 MCP 工具」（`954b641`）

**现象**：把 MCP 服务器（例如 TVPilot、AutoForge）在设置里关掉后，**设置本身是写进去了**（盘上 `enabled:false`），宿主也不再提供这些工具；但 agent 的回答里仍然照常列出那些工具，和设置直接矛盾。

**根因**：注入层给模型准备的「可用工具清单」**只在启动时拉一次，之后永不刷新**。日志里只有一条：

```
[interceptor] loaded 69 MCP tools for prompt injection (attempt 4)
```

启动之后，页面注入进系统提示的就一直是这 69 个工具，与之后在设置里做的任何开关变更无关。

**修复**：把技能侧早已验证过的那套机制**同构搬到 MCP 工具清单**：
- **5 秒 TTL**：TTL 内复用缓存，不额外发请求；
- **发送点有界等待**：过期后在发送前拉一次，最多等 150ms，超时用旧清单继续发，**不阻塞发送**；
- **打字预热**：用户开始输入就异步拉，按下发送时通常已新鲜，当轮即用新清单；
- **并发复用**：同一时刻最多一个 `mcp.list` 在飞；
- **成功才更新**：拉取失败保留旧清单、不抛、不假清空，并留一条诊断日志供真机排查；
- 启动期首拉逻辑一字未动，运行期刷新接在同一份状态变量上，**不留两套清单**。

**效果**：关掉 MCP 后**不用重启、不用刷新页面**，下一轮对话的注入块里就不再出现被关服务器的工具；重新打开后同样即时恢复。

### 2. 技能侧本轮无需改动（写清查过）

技能侧此前已有同一套机制（TTL＋打字预热＋宿主变更广播），本轮核对无缺陷；上一批（v0.14.29）已把设置弹窗的「技能」页开关补齐并经真机复验通过。

## 已知限制（沿用 v0.14.28／v0.14.29）

- **剩余额度百分比做不了**：上游响应里只有布尔 `is_exhausted` ＋ 恢复时刻，没有剩余量数字，Studio 侧也没有额度查询接口。只做「撞墙时友好提示＋恢复时刻」，**不编数字**。
- **额度墙只识别纯 JSON 响应体**：若上游包进 SSE 帧（页面端 fetch 那条路）会漏判；现场实测撞墙走 XHR（纯 JSON），已在代码注释写明。
