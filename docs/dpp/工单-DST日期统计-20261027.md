# 工单 · DST 日期统计缺陷（dpp 席位执行）

> 日期：2026-10-27 ／ 提出：用户报告 + PM 只读核实背书
> 仓库：`E:/NAS/deepseek-pp/src`（git 根即 `src`，当前 HEAD `b5a8b75`，累计 797 提交）
> 纪律：PM 不改 dpp 代码（只读快照约定）。本文件仅为工单与验收判据。

## 1. 缺陷

`core/usage/stats.ts:137-142` `getRecentDayKeys()` 用固定 `DAY_MS = 24*60*60*1000` 做「减一天」：

```ts
const today = dayKeyToTimestamp(toLocalDayKey(now));      // 今天本地 00:00
return Array.from({ length: rangeDays }, (_, index) => (
  toLocalDayKey(today - (rangeDays - index - 1) * DAY_MS)  // 跨 DST 日会偏移 ±1h
));
```

本地时区在 DST 切换日只有 23h（春）或 25h（秋），毫秒减法跨过切换点后不再落在目标日 00:00，`toLocalDayKey()` 于是产错日期串。

## 2. PM 实测复现（TZ=America/Los_Angeles，node 直跑）

**春季**（2024-03-10 调时，now=2024-03-11 本地 00:00，rangeDays=7）：

```
buggy: 03-04,03-05,03-06,03-07,03-08,03-09,03-11   ← 03-10 整天消失；03-04 被错纳入窗口
fixed: 03-05,03-06,03-07,03-08,03-09,03-10,03-11
```

**秋季**（2024-11-03 调时，now=2024-11-04，rangeDays=7）：

```
buggy: 10-28,10-29,10-30,10-31,11-03,11-03,11-04  ← 11-03 重复；11-01/11-02 双双漏掉
fixed: 10-29,10-30,10-31,11-01,11-02,11-03,11-04
```

## 3. 对原报告的修正（重要，否则验收会假绿）

原报告称秋季重复，但**未给窗口长度**。实测 `rangeDays=4` 与 `rangeDays=3` 在 LA 下均为干净序列，不重复——多出的那 1 小时要累计两次才溢出。

因此验收用例必须用 **7 或 30**（`UsageRangeDays` 的合法值即 7/30，见 `normalizeUsageRangeDays`）。若按 4 写用例，测试会「通过」而缺陷仍在。

## 4. 修复方案

改日历运算，且**单一真源**导出复用（勿在 store.ts 另写一套）：

```ts
/** 本地日历加减天（由 Date 自行处理 DST 与月末进位）。 */
export function addLocalDays(timestamp: number, deltaDays: number): number {
  const base = new Date(normalizeTimestamp(timestamp, Date.now()));
  return new Date(base.getFullYear(), base.getMonth(), base.getDate() + deltaDays).getTime();
}

function getRecentDayKeys(rangeDays: UsageRangeDays, now: number): string[] {
  return Array.from({ length: rangeDays }, (_, index) =>
    toLocalDayKey(addLocalDays(now, index - (rangeDays - 1))));
}
```

同根因连带项：`core/usage/store.ts:113` `const cutoff = Date.now() - RETENTION_DAYS * DAY_MS;` 跨 DST 时保留边界偏 1 小时，影响小但改法同上（`addLocalDays(Date.now(), -RETENTION_DAYS)`）。修完后 `stats.ts:11` 的 `DAY_MS` 若再无引用应一并删除，避免留第二个时间单位真源。

`dayKeyToTimestamp()`（`stats.ts:117-121`，用 `new Date(y, m-1, d)`）本身正确，可作为换算基准。

## 5. 验收判据（三条都要）

1. 春季：`getRecentDayKeys(7, Date(2024,2,11))` 含 `2024-03-10`、不含 `2024-03-04`
2. 秋季：`getRecentDayKeys(7, Date(2024,10,4))` 无重复项，且含 `2024-11-01`、`2024-11-02`
3. 不变量：任意 rangeDays 下 `dayKeys.length === rangeDays` 且 `new Set(dayKeys).size === rangeDays`，且逐日严格递增（同时挡住漏天与重复两个方向）
4. 连带：`calculateCurrentStreak` 与 heatmap 在上述两个锚点下不出现同日双格；`activeDays` 不因重复项虚增
