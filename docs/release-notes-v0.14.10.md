### 本版本修复了「聊天页连不上宿主」这个致命问题

v0.14.8 装版后，聊天页里所有工具调用都返回 `no-host`、审批档位保存失败、MCP 配置读不到、技能扫不出来。**根因已定位并在本版修复。**

**① 命令权限缺失（致命）** — `studio_request_grant` 与 `studio_open_mcp_settings` 两条命令从未被 Tauri 的权限清单放行，调用在 IPC 层就被拒绝。更糟的是：拒绝发生在命令体执行**之前**，所以宿主侧所有失败日志都被绕过——表现为「彻底静默」，比上一个版本更难排查。现在两条命令已放行，并新增一道机器守卫：**任何注册命令若未在权限清单中放行，门禁直接判红**（这道守卫在修复前会精确点名这两条）。

**② 配置路径分裂（致命）** — 桌面外壳与宿主子进程曾各自读取不同位置的 `config.json`，两者的密钥不同 ⇒ 一边签发的连接凭据另一边永远验不过。现在路径由单一点解析，两侧同源同值。

**③ 首启不迁移用户配置（重要）** — 首次启动时，配置迁移要求目标目录已存在，而没有任何环节在其之前创建它 ⇒ 必然跳过，用户的 MCP 服务器配置搬不过来。现在外壳在启动宿主前先创建该目录。**你的既有配置不会被覆盖**：混合状态下只补搬缺失的文件，已有的保持不动（这一条被明确写进代码禁令与测试，因为「顺手改成覆盖」会把正在生效的配置换成旧密钥，等于重新制造缺陷②）。

**④ 失败不可见（重要）** — 取凭据失败时，页面现在会显示**真实原因**而不是笼统的「宿主不可用」，并区分三种情形：权限未放行 / 凭据未取得导致裸连 / 返回格式违反契约。排查时一眼可辨。

### 其他修复与加固

- **MCP 密钥不再被当真实凭据写入**：若表单回填了掩码占位符而磁盘上没有对应原值，过去会把占位符本身写进配置——那等于**伪造了一个凭据**，之后认证必然失败且日志看不出原因。现在改为拒绝写入并给出一句可执行的提示（「请在表单里重新填写该项的真实值」）。
- **5 处关键写入改为原子替换**（工作区索引、授权白名单、执行镜像、编辑回滚、报告摘要）。授权白名单写坏会导致「你批准过的工具全部消失」，编辑回滚写坏则是在已损坏之上叠加损坏——回滚路径的可靠性要求不低于主路径。
- **PoW 难度设了安全上界**：该值原本完全来自服务端且无上界校验，异常大的值会让求解循环长期占住页面主线程导致卡死。非法值（超上界、非整数、非有限、非正）现在在进入求解循环之前即被拦截，并给出「难度非法」而非「算不出来」的可区分错误。
- **「诊断与关于」页补上版本号**：此前版本号只在「通用 / 连接」页显示，而用户查版本号的自然去处是诊断页。

### 安全口径变化（请阅读）

连接凭据的粒度从「**一个窗口一张**」改为「**一次连接一张**」。安全强度**未削弱**：每张凭据仍然 60 秒过期、一次性使用、绑定目标受众、且仅可用于建立连接。改动的目的是消除「凭据过期后退避变慢 / 重连复用死凭据」这一类故障。

MCP 设置的编辑界面改走独立原生窗口，该窗口**只走本地 HTTP + 令牌、不持有任何桌面外壳权限**，聊天页内的「Studio 设置」弹窗保持只读——明文密钥不再暴露在站点脚本可及的 DOM 里。

### 已知问题

- 更新弹窗上的说明文字是 `Release v0.14.10` 这样的泛化串，不显示本正文（修复需调整发版工作流，排在下一版）。
- 启动时可能短暂出现一个 PowerShell 窗口（子进程隐藏标志尚未全覆盖，属观感问题，不影响功能）。
- 从 v0.14.8 直接升级的用户：若首次启动后仍看不到 MCP 服务器列表，请**完全退出并重新启动一次**（缺陷③ 的迁移在目录已建立后即可正常完成）。

### 升级方式

直接安装本版本的 `DeepSeek++ Studio_0.14.10_x64-setup.exe` 即可，**无需卸载、个人配置与数据不会丢失**。已装 v0.14.8 且在线升级通道可用的用户，也可在应用内点「立即重启并更新」。

### 完整性校验

安装包附带 minisign 签名（`.exe.sig` / `.msi.sig`），`latest.json` 中的 `url` 指向本版本的 setup.exe。签名公钥随应用内置，更新器在安装前会本地验签。
