# DeepSeek++ Studio v0.14.21

一句话：本版最重要的一条是**账号密码登录真的能用了**——你手上 0.14.20 装版仍然登不进去，这条必须升级才有。另外把「上游一抖整轮就没反应」「工具失败了却说不清」「MCP Header 填了不生效」「没让你记的事被写进记忆」这几处反复出现的毛病一起收了。

## 一、账号密码登录修好（本版头号修复）

现象：在登录页填手机号／邮箱＋密码，点登录，页面回一句「网络异常，请检查你的网络状况」。**那句话不是我们报的错**——站点自己的兜底文案，所以我们这边的日志里一直查不到出处。

真因：我们注入层在拦截网络请求时，往请求对象上写了自己的状态字段。站点的设备指纹 SDK 会**逐个检查请求对象上多出来的字段**，一旦发现就判定环境被改过，于是**拒绝下发设备标识**，登录请求里那个字段变成空值，服务端直接回 422（缺参数），页面就落成那句「网络异常」。

修法：注入层改到**不在请求对象上留任何自有字段**（状态全部移到外部映射表），并且对非聊天类接口直接早退、不做任何改写；同时把被接管的原型方法补上原生外观。

验证：同一份安装包、同一份配置、同一份假凭据的对照实验——修复前该字段为空、接口 422；修复后字段有值、接口 200 并回「密码错误或账户不存在」（这才是假账号应有的结果）。真人真账号的口令登录也已实测通过。

## 二、上游服务抖动不再把整轮打死

之前你遇到过这几类：「执行未完成／上游服务器暂时不可用」「连续几轮 empty-reply，只显示'模型这一轮没有输出任何可见内容'」「工具调用被网络中断截断，本轮不会自动重试」。本版做了三件事：

1. **把可重试的失败归类成可重试**：上游以提示帧形式返回的错误（`event: hint` 里的错误类型、生成错误／限流）现在计入首轮重试预算，不再当硬失败直接结束；
2. **被截断的工具调用**（参数写到一半断流）现在也走首轮重试，而不是报一句「请重新发送该请求」就停下；
3. **轮次超时是真的取消在途请求**：以前超时只是本地结束，迟到的回复还会窜回来污染下一轮；现在每轮带世代号，迟到的直接丢弃并留诊断记录。

另外一条判停修复：模型说「我去 grep 一下日志」然后被截断时，以前会被当成「已经交付完了」，现在能识别出来它其实还没做完（未闭合的代码块、以及一批英文动作词都纳入了判定）。

## 三、工具失败时，终于说人话

以前工具执行失败，模型收到的可能是空串、`unknown`，或者一句笼统的「超时」，于是它转述给你的是错的方向。现在：

- 失败结果统一带**工具名＋可读原因**（`summary`／`detail`／`error.message` 三层），不再有空白；
- **审批超时不再谎称「超时未返回」**：真实原因是「需要用户审批，但本次未获批准（拒绝或等待超时）」，并明确提示模型「等用户在审批窗口选择，不要重复调用同一工具」——因为重复调用只会再等一次；
- 审批界面不可用时会说「已按 fail-closed 拒绝，请打开 Studio 窗口」，而不是含糊失败；
- 真的执行超时也会写清楚「这不是审批问题」；
- 单轮工具结果加了 **64KB 预算**，保新弃旧、边界截断，不再因为一次超大输出把整轮撑爆。

## 四、MCP：Headers 改成「名称／值」两栏

以前是一整行文本，填 `Authorization=Bearer xxx`（或冒号写法）会被**静默丢掉**——测试连接没有任何反应，你根本不知道是哪一步没进去。现在拆成名称栏＋值栏，鉴权头按你填的字面发出。

## 五、记忆：没让你记的事，不写进记忆

本版起，长期记忆写库必须有**宿主侧证据**（你这一轮消息里确实出现了「记住／记一下／别忘了」这类明确指令）。证据判定在宿主侧完成，不在模型侧——模型声称「用户要求过」不算数。实测过这种情况：模型的思考里写着「用户明确要求记住项目约定」，而用户原话里根本没有「记住」二字，这类请求现在会被拒并留审计记录。

配套一条：清空／删除记忆的确认流程也收紧了，拒绝时返回真实原因。

## 六、聊天交互四处

- 断线重连不再把会话锁死（重连锁死修复）；
- 重新发送时会**清掉上一条没写完的气泡**，不再留半截原文；
- 空输入框按 Enter 不再报「发送成功」的假结果；
- 发送重试只重试「把文字填进输入框」这一步，**发送动作只做一次**（以前重试会把消息发两遍）；
- 单窗口场景不再被误判成「多账号重复」，误判出现的遮挡层现在可以撤销。

## 七、安全与授权

- **远程调试口在发行版默认关闭**（此前 release 形态可能带着调试口）；
- 局域网配对码的比较改用**定长时间比较**，比较前先判长度（原写法对不等长输入会直接抛异常）；
- **保存记忆不再共用一格授权**：`memory.save` 改为按「记忆名」逐条授权。以前所有保存动作落在同一个授权格裡，你同意保存 A，就等于顺带放行了保存 B——现在不会了；
- 授权契约加了一条反向锁：标注为特权、却写着「不需要审批」的工具，不允许出现在模型可用清单里；
- **自动更新在安装之前会弹一个系统级确认框**（是／否），选「否」直接终止，且这一步在任何下载状态之前返回。

## 八、改过端口的用户：安装版现在起得来了

以前端口在 TypeScript 侧是可配的（环境变量 → 配置 → 默认 8760），Rust 侧却写死成常量，两边各一套口径。后果是：你在配置文件里改了端口，宿主绑到新端口、外壳仍去探 8760，**安装版直接起不来**，而且按报错提示去改端口只会更起不来。本版把 Rust 侧统一成同一条解析链（含逐条对齐的合法性判定：非法值回落默认、不 panic；环境变量一旦存在就独占整链），并替换了全部 9 处写死点（就绪探活、占用检测、进程树清理、启动冲突文案、退出码提示、关闭兜底、环境变量注入、聊天室地址、各类窗口 URL）。默认路径不变：不设环境变量、配置里没有端口时仍是 8760。

## 九、更新与发布链路

- 发布后若 GitHub 把草稿绑成了合成标签，工具会**先尝试重绑标签再判定成败**，不再一遇到就直接撤稿；
- 构建产物新鲜度检查补齐成对称两道：改注入层要重建注入包、改宿主侧要重建宿主包，不一致就拦在提交前。

## 诚实说明

1. **登录这条必须升级**：修复在 0.14.20 之后完成，你手上的 0.14.20 装版仍然无法用账号密码登录。
2. **在线更新仍是全量下载安装包**，不是增量包（体量决定升级耗时，这一点本版没改）。
3. **工作区没配置时，文件类工具只会返回「工作区未配置」**，拿不到真实文件结果——本版未改这个语义。请在设置里把工作区指向你的项目目录，文件工具与相关审批链才走得通。
4. **记忆库的历史读数是空的**：我们核过发行版本机的记忆库，三张表都是 0 行。也就是说此前「似乎总在写记忆」的观感并没有真的落库；本版保证了「该写的能写、不该写的不写」，但**不会把过去的对话补写成记忆**。
5. 记忆写入与登录这两条的端到端，我们是在源码构建的实例上验证的；**发行版的端到端复验正在进行**，如果升级后仍出现「填了密码还是报网络异常」，请把你看到的原文告警文本发回来——那属于要逐个核实的情况。
6. **「重复工具调用」的封顶这一项，真机上还没被触发过**。背景：某轮出现同一条回复流里同一工具签名被反复投递上千次、工具一次都没执行；本版加了封顶（同签名最多重投 3 次后终局停止）与宿主侧的重复拒绝提示。加完之后我们在源码构建实例上重跑那句会触发它的指令，**读数是一条重复投递都没出现**——所以准确说法是「那种洪水形态未复现、工具执行恢复正常」，而不是「封顶已实战生效」。封顶本身的三条分支由单元测试与负控保证。
7. **升级会覆盖安装包目录里的注入与宿主两份文件**。我们发现 0.14.20 的部分安装（含开发自测机）这两份文件曾被开发构建产物覆盖过，出现「exe 是一个版本、脚本包是另一个版本」的混搭状态——那种状态下口令登录必然失败，且失败原因与本版修的那个缺陷同源。**正常在线升级即可自愈**，不需要卸载重装；如果你长期手动替换过安装目录的文件，请以本次升级后的全新包为准。

建议从 0.14.20 直接升级。
