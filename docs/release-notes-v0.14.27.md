# v0.14.27 发版说明

发布日期：2026-11-20（tag `v0.14.27`；本版修的是出资人点名要的两件事——**skill／MCP 加 UI 开关**与**撞额度墙时要友好提示、不要报错**，全部经独立真机复验）

## 这版修了什么

### 1. 撞上 DeepSeek 免费额度墙，Studio 报「连接中断」并自动重试（`8d12790`）

**现象**：额度用完时，上游其实回了一个 **HTTP 200** 的正常响应——外壳里套着业务码 `biz_code:29`、`is_exhausted:true`、恢复时刻 `reset_at`，还自带一整套提示文案（标题／描述／按钮）。但 Studio 的分类器**只看 HTTP 状态码**，200 就当成功，于是把这条响应当成「回复流不完整」，报「模型回复未完整接收（连接中断）」，还自动重试 2 次——两次撞同一堵墙。

**用户感受**：明明是「今天额度用完了、明天 1 点恢复」，看到的却是「连接中断，正在重试」，等半天重试完还是那句报错。

**修复**：
- 分类器在 200 分支里**读业务码**：识别出额度墙 ⇒ 新判定 `quota-exhausted`，**不重试**（重试撞同一堵墙没有任何意义）；
- 提示里**明示恢复时刻**（优先用上游文案里自带的「将于 … 恢复」，解析不出才用 `reset_at` 换算本地时间）；
- **透传上游的提示文案**（标题／描述／按钮），不自己硬编码；
- 读取层逐层下探（`data` → `data.biz_data` → 顶层）——上游真实形态把 `quotas`／`alert` 放在 `data.biz_data` 里，只读 `data` 层会漏判。

**边界（已知不修）**：只识别**纯 JSON** 响应体。若上游把额度墙包进 SSE 帧（页面端走 fetch 那条路），本版会漏判——现场实测撞墙走的是 XHR 路径（`responseText` 是纯 JSON），风险大于收益，本版不修，已在代码注释里写明。

### 2. 技能面板的开关是假开关（`8d12790`）

**现象**：技能面板上点开关，**只改了内存里一个变量**——不落盘、不通知宿主，下次开窗又全亮；而且注入面根本不看这个变量，**12 个技能每轮全量注入**。用户以为关掉了，实际一直在注入。

**修复**：
- 关掉的技能**落盘**（配置键 `disabledSkills`）；全部开回来时**整键删除**，不留空数组；
- `skill.list` 每枚带 `enabled` 回显，面板看到的与磁盘一致；
- 注入面 `selectExplicitSkills` **按 enabled 过滤**——关掉的不再进注入；
- 开关一改就**广播** `skills-changed` 到页端，下一轮立即生效，不需要重启；
- 未知技能 id 按集合落盘、不报错（面板与宿主扫描天然有竞态，按集合落盘对两边都安全）。

### 3. MCP 服务器没有开关，69 个工具全量注入（`8d12790`）

**现象**：`mcp-servers.json` 里没有 per-server 的 `enabled` 字段，`listServerIds()` 返回全部服务器，注入面把 **69 个 MCP 工具全量塞进提示词**——开着的关不掉，空着也占上下文。

**修复**：
- 支持 per-server `enabled`（**缺省＝启用**，只有显式 `false` 才算禁）；
- **模型面过滤**：禁用的服务器不进 `mcp.list`、工具不进注入、调用被拒（回 `mcp-server-disabled: …`）；
- **管理面全量回显**：设置里仍能看到所有服务器和它们的开关状态（两源不混用）；
- **禁用的服务器不 spawn、不 connect**——不是连上了再过滤，是压根不连；
- 改配置时 `enabled` **缺省继承原有值**：只改 url／header 不会把禁用的服务器静默重开。

## 已知限制

**剩余额度百分比做不了**（不是没接，是上游没给）：撞墙响应里只有布尔 `is_exhausted` ＋ 恢复时刻，**没有任何剩余量／总量／百分比字段**。Studio 侧可见的 13 个上游 API 路径里也没有额度查询接口，全文搜 `remaining`／`balance`／`quota`／`limit` 命中 0 枚。所以本版只做「撞墙时友好提示＋恢复倒计时」，不做「还剩百分之多少」——**不编数字**。
