# DeepSeek++ Studio v0.14.18

一句话：这是 **0.14.12 之后的第一次正式更新**。除了之前说明过的聊天界面显示修复，本版新增了「手动检查更新」入口，并修好了发布流程自身最后一处会误杀发布的问题。

## 一、设置面板「诊断」页新增「手动检查更新」

以前检查更新是**进程内一次性缓存**：只要程序开着，就不会再查第二次，不重启就看不到新版本。现在这个按钮会**强制重新查一次**，不重启也能立刻看到结果——这也是我们在正式安装版上验证「更新卡首弹」的前置。

## 二、发布流程的修复（不影响已安装版本的功能）

- **取数改走「发布编号」通道**：以前靠标签名反查发布对象，而标签在没绑上时会被 GitHub 换成 `untagged-…` 这样的合成编号，靠它取数必然失败——这就是 0.14.13–0.14.17 连续失败的同一处根因。
- **新增一条硬判据**：发布对象必须**真正绑在 git 标签上**——`tag_name` 等于版本号、页面地址形如 `/releases/tag/vX.Y.Z`；不满足即 fail-closed，把发布打回草稿，不在公开面留下错误页面。
- **出错时不再靠猜**：失败会把五个关键字段（清单版本、标签名、发布名、分支名、发布编号）一起写进公开注解。

## 三、把「发布」这一步的规范写进了项目说明

从本版起，发布允许由项目负责人在出资人授权下用令牌完成，但必须同时满足两条硬判据：**绑定正确**（上面那条）与 **Latest 指针推进**；任何一条不满足都视为失败并撤回草稿。

## 四、关于 0.14.13–0.14.17

那四个版本号**仍未产出可用的安装包**，原因已在 0.14.17 的说明里逐条写明（解压位置、脚本写法、回读只查一次、查找只查一次），本版维持该口径、不重复展开。

## 诚实说明

本版的界面改动（手动检查更新入口）**已通过自动化测试**（含负控：摘掉强制参数即红），但**尚未在正式安装版上手工逐项走过**。如果你点了按钮没有反应、或者提示文字不对，请把当时的界面文字发给我们——这属于要逐个核实的情况。

建议从 0.14.12 或更早版本直接升级。
