## 3. M10 · 记忆系统改造（2026-10-23 立项）

> 依据：`docs/调研报告/Studio-记忆系统评审与开发方向-20261023.md`（43,646 B，八节）
> 一句话：**现有优先级建议是错的**——不该先接 `search()`，该先补治理与边界。
> 理由：23 条 / 1,843 token，全量注入本就在预算内，相关性排序在这条曲线上收益≈0；
> 当前真正的失效模式是「注入了不该被信任的记忆」「删掉的记忆还在注入」「最久没更新的被静默丢弃」，这三件与打分无关。

### 3.1 基线读数（2026-10-22 23:30 快照，本次复核仍未变）

| 项 | 读数 |
|---|---|
| 库 | `~/.config/deepseek-studio/memories.db`，1,744,896 B ≈ 1.66 MiB |
| 记忆行数 | 23（`project` 10 / `user` 13），有效/失效 = 23/0 |
| FTS 索引 | 23 行，与主表一致，无漂移 |
| 治理字段 | `source` NULL 23/23、`confidence` NULL 23/23、`persona_tags_json='[]'` 23/23、`pinned=1` 0 条 |
| 内容规模 | 合计 3,483 字符 ≈ 1,843 token（最短 10 / 最长 515 / 均值 151.4） |
| 写入速率 | 扣掉 10-12 那次 12 条批量导入，有机写入 ≈ 1.1 条/天 |
| 存储层 | `src/host/memory-store.ts` 533 行，FTS5 trigram；`invalidate()` / `restore()` 已实现但 `src/` 零调用方 |
| 注入层 | `main-world-interceptor.ts` `formatMemoriesBlock` 用 `list().slice(0, 50)`，**无排序、无预算、无单条截断、无不可信边界** |

### 3.2 路线（按依赖排序，不按时间）

**P0 · 立刻做（小改动、可机械判定）**

| 编号 | 事项 | 改动面 | 为什么是 P0 |
|---|---|---|---|
| M10-1 | `memory.delete` 风险档 `read` → `privileged` | `tool-definitions.ts:215` | 硬删、不可回滚、当前免同意 |
| M10-2 | 处置 `src/inject/execution-policy.ts`（零 importer 死代码，且把 `memory_delete` 标成 HIGH_RISK，与真实闸门相反） | 删除该文件 | 会持续误导后来者 |
| M10-3 | `memory.delete` 补广播 | `desktop-host.ts` 删除成功后重推 `list()` | 不补则被删记忆注入到重启为止 |
| M10-4 | 注入内容加不可信边界（envelope） | 新增 `src/inject/untrusted-memory.ts` + 改 `formatMemoriesBlock` | P1/P2 一切选择逻辑的前置；dpp 有事故先例 |

**P1 · 一致性 + 写入语义**

| 编号 | 事项 | 关键点 |
|---|---|---|
| M10-5 | 启用软失效，先修重名口径 | `memory-store.ts` 重名匹配去掉 `invalid_at IS NULL`；命中已失效行走 `restore` 而非新建；`memory.delete` 改 `invalidate` 并提供 purge |
| M10-6 | 治理字段只落 `source` | 宿主赋值（`user`/`agent`/`curator`/`import`），不接受调用方传入；`confidence`/`personaTags` 暂不写 |
| M10-7 | `save()` 改合并语义 + 容量上限 + 跨名去重 | `pinned`/`tags` 未传时保留原值；`contentHash` 命中返回既有 id；新增 `MAX_MEMORIES` |

**P2 · 按触发条件启动（不是按排期）**

| 编号 | 事项 | 触发条件 |
|---|---|---|
| M10-8 | 注入选择：第一步只加预算 + 确定性排序（`pinned → updated_at`，`user` 优先）；第二步才接 `search()`（新增 `memory.select` 宿主预选，**不做 `memory_search` 工具**） | 有效记忆 > 35 条 或 注入块 > 2500 token（按 1.1 条/天，约 2 周后） |
| M10-9 | 记忆抽取：只做候选池（`memory_candidates`，不入注入），用户 approve 才落正式表 | 必须 M10-4 + M10-6 + M10-8 第一步全部到位 |
| M10-10 | `memory_log` 审计与回滚（`before_json` 只存 hash + 前 200 字，防膨胀） | 需要回答「某条记忆何时由谁改过」时 |
| M10-11 | 多 workspace 隔离：`user` 类全局 + `project` 类加 `project_id` | 产品语义拍板后（改晚要迁移） |

### 3.4 待拍板（6 条，均已给建议）

1. `memory.save` 要不要也从 `read` 提到 `insert`？→ **不提**（upsert 非破坏性；提了等于废掉模型主动记忆）。
2. `memory.delete` 改软删还是一步到位？→ **两步走**：先加同意闸门（M10-1），再改 `invalidate`（M10-5）。
3. 注入选择接在哪？→ **宿主预选**（`memory.select`），不加 `memory_search` 工具。
4. 记忆按人还是按项目？→ **`user` 全局 + `project` 按项目**（M10-11）。
5. 是否接受一次 prompt 面变更（M10-4 envelope）？→ 需你确认「可以改 prompt 措辞 + 做一轮真机抽检」。
6. `execution-policy.ts` 删还是接？→ **删**（M10-2）。
