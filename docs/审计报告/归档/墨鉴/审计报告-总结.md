## 三、几个「看似 bug 但已核实正确」的坑（供后人省时间）

1. **FTS JOIN 写法**：`JOIN memories_fts f ON f.rowid = m.rowid WHERE memories_fts MATCH ?` —— 用 SQLite trigram 实测合法且能命中；把 MATCH 换成别名 `f MATCH` 才报错。当前写法是对的。
2. **`likePattern` 转义**：`\ % _` + `ESCAPE ''`，实测正确。
3. **`toFtsQuery` 去双引号**：不是转义而是删除，但足以防 FTS5 语法注入。
4. **`mergeUpdateGovernance` 的 `??`**：正确实现「未传保留 / 显式传值（含 false/[]）覆盖」，SQL 与 fallback 共用同一函数无分叉。
5. **`readBody` 编码**：先 `Buffer.concat` 再整体 `toString('utf-8')`，多字节字符跨 chunk 不会乱码（与 BUG-002 的截断不同）。
6. **MCP env 白名单**：只透传 PATH/HOME/TEMP 等系统变量，宿主 token 不会泄漏给 MCP server。
7. **`shell: isCmdBatch`**：仅 Windows 下 `.cmd/.bat` 才开 shell，其余直接 spawn —— 与 shell.ts 的 `shell:false` 红线一致。
8. **CORS fail-closed**：非本地 origin 一个头都不写，PNA 预检白名单限死两个 WS 路径。
