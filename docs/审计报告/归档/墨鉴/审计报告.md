## 二、缺陷详情

### BUG-001（P1）limitToolPayload 单位混用，中文载荷上限失效

位置：`src/shared/studio-execution.ts:238-255`

```ts
if (serialized.length <= limit) {        // UTF-16 码元数
  return ...;
}
return {
  truncated: true,
  originalBytes: byteLength(serialized), // UTF-8 字节
  preview: truncateUtf8(serialized, limit), // UTF-8 字节
};
```

同一函数内用了两把尺：判定看字符数，截断和计数看字节数。`STUDIO_TOOL_PAYLOAD_LIMIT = 16 * 1024` 是字节语义。

触发：工具参数或结果含中文。16000 个汉字 = 16000 码元，判定为“未超限”原样返回，实际约 48000 字节。

影响：单条执行记录体积上限被放大近 3 倍；纯英文内容判定正确，形成中英文不对称。落盘体积与回读成本失控，却看不到 `truncated` 标记。

修法：判定改为 `byteLength(serialized) <= limit`，或统一按字符计数。

### BUG-002（P2）truncateUtf8 在字符中间切断

位置：`src/shared/studio-execution.ts:228-232`

```ts
return new TextDecoder().decode(bytes.slice(0, limit));
```

`limit` 落在三字节汉字的中间时，`TextDecoder` 默认非 fatal 模式会输出替换字符（U+FFFD）。

影响：截断预览末尾出现乱码方块；该 preview 若再被序列化写入记录，乱码永久留存。

修法：回退到最近的合法字符边界后再 decode；或 decode 后清理尾部的 U+FFFD。

---

### BUG-003（P2）appendExecutionEvent 的 updatedAt 可倒退

位置：`src/shared/studio-execution.ts:270-278`

```ts
session.updatedAt = event.at;
```

无单调性保护。事件补写、历史水合、系统时钟回拨都可能让 `at` 小于当前 `updatedAt`。

影响：索引按 `updatedAt` 排序错乱；若存在按时间淘汰的 LRU，可能误删刚写入的新会话。

修法：`session.updatedAt = Math.max(session.updatedAt, event.at);`

---

### BUG-004（P1）配置重写丢失 chatRooms / chatRoomMaxDepth / apiEngine

位置：`src/api/main.ts:147-153`

```ts
if (!stored.token || !stored.secret) {
  const toWrite: Record<string, unknown> = { host, port, token, secret };
  if (workspaceRoot) toWrite.workspaceRoot = workspaceRoot;
  if (policyMode) toWrite.policyMode = policyMode;
  fs.writeFileSync(cfgPath, JSON.stringify(toWrite, null, 2), { mode: 0o600 });
}
```

触发条件：首次运行，或 `stored` 缺 token/secret。

影响：用户已配置的 `chatRooms`、`chatRoomMaxDepth`、`apiEngine`（baseURL / apiKey / model）被静默清空，重启后聊天室模式与 API 引擎消失。

旁证：第 146 行注释写着“v0.13 修复：写入时保留 workspaceRoot/policyMode”，说明作者已知该风险，但只补了两个字段，其余仍会丢。

修法：`{ ...stored, host, port, token, secret }`，只覆盖必要字段。

### BUG-005（P1）注释承诺不覆盖损坏配置，实现必然覆盖

位置：`src/api/main.ts:100-110` 与 `147-153`

```ts
} catch (err) {
  if (code !== 'ENOENT') {
    console.error('...将以内存随机 token 启动，不覆盖磁盘上的损坏文件。');
    stored = {};   // <-- token/secret 必然缺失
  }
}
// ...
if (!stored.token || !stored.secret) {   // <-- 恒为真
  fs.writeFileSync(cfgPath, ...);        // <-- 覆盖
}
```

`stored = {}` 之后，第 147 行的条件恒成立，第 153 行直接把损坏文件覆盖成新配置。

影响：用户失去手工修复原文件的机会；日志与真实行为互相矛盾，排障时被误导（会去别处找“为什么配置变了”）。

修法：损坏分支置一个 `skipPersist = true` 标志，跳过本次落盘。

### BUG-006（P2）孤儿防护存在 PID 复用竞态

位置：`src/api/main.ts:37-50`

```ts
const ppid0 = d.getPpid();
const timer = d.setInterval(() => {
  if (d.getPpid() !== ppid0 || !d.alive(ppid0)) { d.exit(0); }
}, intervalMs);
// alive: process.kill(pid, 0) 成功即视为存活
```

每 500ms 只比对 PID 数值。父进程退出后若 PID 被系统复用给无关进程，`alive()` 恒为真，guard 永不触发。

影响：sidecar 变僵尸常驻，占端口、占内存，下次启动撞 EADDRINUSE。

修法：同时比对父进程启动时间（或父进程写心跳文件），不只看 PID 是否可 kill。

### BUG-007（P2）端口未校验，NaN 可传入 listen

位置：`src/api/main.ts:117`

```ts
const port = Number(process.env.DEEPSEEK_STUDIO_PORT ?? stored.port ?? 8760);
```

`DEEPSEEK_STUDIO_PORT=abc` 得到 NaN；`stored.port` 若被写成字符串同样得到 NaN。

影响：`server.listen(NaN)` 抛 RangeError。虽然被 `start()` 的 reject 捕获，但错误信息里没有“端口非法”的提示，用户看到的是 Node 内部异常；某些版本下还可能被当作 0 处理而监听随机端口，导致页端按 config 里的旧 wsUrl 连不上。

修法：`Number.isInteger(port) && port > 0 && port < 65536` 校验，非法则回落 8760 并告警。

### BUG-008（P1）powershell -Command 转 EncodedCommand 时丢弃后续参数

位置：`src/capabilities/shell.ts:280-287`

```ts
if (process.platform === 'win32' && (/^powershell(\.exe)?$/i.test(argv[0]) || /^pwsh(\.exe)?$/i.test(argv[0] || ''))) {
  const cmdIdx = argv.findIndex((a) => a === '-Command' || a === '-c');
  if (cmdIdx >= 0 && argv[cmdIdx + 1]) {
    const script = argv[cmdIdx + 1];
    const encoded = Buffer.from(script, 'utf16le').toString('base64');
    argv = [...argv.slice(0, cmdIdx), '-EncodedCommand', encoded];
  }
}
```

`argv.slice(0, cmdIdx)` 只保留 `-Command` 之前的元素，`argv[cmdIdx + 1]` 之后的全部参数被丢弃。

触发：`powershell -Command "Write-Output $args" a b c`，或 `pwsh -Command ... -NoProfile` 之类的尾随开关。

影响：静默丢参——命令执行成功但结果不对，属于最难排查的一类缺陷。用户传 3 个参数只看到 0 个，且没有任何告警。

修法：把 `argv.slice(cmdIdx + 2)` 追加到结果尾部；或仅在无尾随参数时走 EncodedCommand，否则保留原 argv。

### BUG-009（P1）显式 argv 传 cmd /c 时，元字符检查被整段跳过

位置：`src/capabilities/shell.ts:229-276`

两道防护的触发条件：

1. 内建命令检查（第 230 行）：`CMD_BUILTINS.has(argv[0].toLowerCase())` —— `argv[0]` 是 `cmd` 时不在集合内，跳过。
2. 脚本路由检查（第 258-275 行）：`resolveWindowsScript(argv[0])` —— `cmd` 解析到 `C:\Windows\System32\cmd.exe`，命中 `.exe` 分支返回 `null`，第 261 行的元字符循环整段不执行。

于是：

```json
{ "argv": ["cmd", "/c", "echo", "x&calc"] }
```

两道检查都不触发，`spawn('cmd', ['/c','echo','x&calc'])` 直接执行，`&` 被 cmd 二次解释，calc 被拉起。

影响：这正是第 231 行注释里点名要堵的“双引号内元字符命令注入”同一条路径，只是绕过入口从 `command` 字符串换成了 `argv` 数组。v1.9 的审计补丁只覆盖了“命令串被识别为内建命令”这一条路，漏掉了“用户显式写 cmd”这一条。

修法：在决定是否加 `cmd /c` 之外，独立加一道判定——只要最终 argv 的 `argv[0]` 是 cmd/cmd.exe，或其参数中已含 `/c`、`/k`，同样对其余元素执行 `CMD_METACHARS` 检查。

## 三、已排查并排除的疑点

记录在此，避免后续重复投入。

1. `shared/tool-loop.ts` 的 `runBefore` / `runAfter` / `emitAsync` 未包 try —— `tool-hooks.ts` 内部 before 阶段 fail-closed、after 阶段 fail-open；`tool-event-bus.ts:208-218` 每个 handler 独立 try/catch。**不外抛，不是缺陷**。
2. `shared/tool-call-dedupe.ts` 的 `stableSerialize` —— 同参必同签名，去重语义正确。
3. `shared/retry-policy.ts` —— 指数退避 + `attempt < maxRetries`，边界正确。
4. `api/server.ts` 鉴权顺序 —— 第 364 行的 Bearer 校验在所有 `/v1` 路由之前；`/agent` 静态页在 LAN 模式下过 `decideAgentAccess` 配对码闸门。**未发现未鉴权的 `/v1` 入口**。
5. `api/server.ts:650-693` 流式响应收尾 —— close / aborted / socket 监听在 finally 中全部 `removeListener`；`release()` 用 `released` 标志防重复扣减；`safeWrite` 判 `writableEnded` / `destroyed`。**资源释放正确**。
6. `api/auth.ts` —— 常量时间比较；令牌源函数抛错时 fail-closed 返回空集合。
7. `capabilities/shell.ts` 主体 —— `shell: false` 红线贯彻；`clampTimeout` 对 NaN/负数/0 回落默认值而非夹到 1ms；超时有 1500ms 宽限窗口防 Promise 永久悬挂；Windows 用 `taskkill /T /F` 杀进程树。这几处设计是稳的。

## 四、线索（未定论，供后续复核）

1. `capabilities/shell.ts:219-224` 的 cwd 越界校验用的是 `wsActive.contains(cwd)`，但 `cwd` 未先做 `path.resolve`。若 `contains()` 内部没有自行规范化，`params.cwd = "../../x"` 可能绕过边界。需复核 `host/workspace.ts` 的 `contains` 实现。
2. `shared/context-budget.ts estimateTokens` 的正则只覆盖 CJK 基本区，扩展区汉字、假名、全角标点按“4 字符 = 1 token”计，会低估上下文体积。属精度问题，非崩溃。
3. `shared/studio-execution.ts canonicalChatSessionKey` 只折叠一层 `chat:chat:`；正常链路不会产生三层，风险低。
