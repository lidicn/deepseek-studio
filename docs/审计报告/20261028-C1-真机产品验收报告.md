# 20261028 C1 真机产品验收报告

## 0. 最终结论

- **代码级：通过。**
- **产品级：不能关账。**

代码级已有专项、全量和门禁证据支撑；本轮真机也确认了审批、记忆生命周期、治理字段、多轮任务等主要路径可工作。但以下三项仍使产品级无法关账：

1. `memory.select` 自动预取在真实聊天中没有观测到任何自动工具调用，只有手动调用返回 `fallback`。
2. `memory_save` 工具卡显示“失败 / constraint failed”，但 DB 中数据实际正确落库，UI 与 DB 证据不一致。
3. 归档、恢复、彻底删除审批弹窗仍显示“该操作”与裸 ID，缺少面向用户的自然语言说明。

本报告只记录真机取证，不修改生产代码，不提交、不推送、不回退工作树中的其他席位改动。

### 3.5 `memory.select` 自动预取

#### 已确认可用部分

手动调用宿主工具隔离测试：

```json
{
  "manual": {
    "ok": true,
    "data": {
      "memories": [],
      "selection": "fallback"
    }
  },
  "calls": [
    {
      "invocationName": "memory.select",
      "params": {
        "taskText": "C1 验收：读取 package.json 前五行"
      }
    }
  ],
  "memories": null
}
```

结论：宿主侧 `memory.select` 工具存在且可调用，返回 `fallback` 正常。

#### 未闭环部分

页端安装观测包装器后读数：

```json
{
  "ok": true,
  "flag": true,
  "calls": 0,
  "ws": 0
}
```

随后发送新聊天：

```text
C1 验收：请只回复“预取检查”，不要调用任何工具。
```

等待 18 秒后，观测结果仍为：

```json
{
  "calls": [],
  "ws": [
    {
      "head": "{\"type\":\"log\",\"text\":\"[interceptor] xhr POST /api/v0/chat/completion isChat=true bodyType=string\"}"
    }
  ]
}
```

trace 为：

```text
turn 1 (1.0s)  DONE
  ├─ request.sent    6.9KB
  ├─ sse(chars): text×4 think×0 tool×0
  ├─ continuation.decision: no-tools -> triggered=false
  └─ turn.end stopReason=completed finished=true
```

没有出现 `memory.select` 自动调用。

进一步核对代码与注入顺序：

```text
boot.hasStudioAtInject = true
boot.flagAtInject = null
boot.ready = "complete"
boot.hasStudio = true
```

`src/desktop/entry.ts` 安装时只读取一次 `globalThis.__studioMemorySelect`：

```ts
configureMemorySelect({
  enabled: typeof globalThis.__studioMemorySelect === "boolean"
    ? Boolean(globalThis.__studioMemorySelect)
    : false,
  invoke: (taskText) => host.sendToolCall({
    invocationName: "memory.select",
    params: { taskText }
  })
});
```

而实际注入脚本执行时 Studio 已存在、flag 仍为 `null`，因此安装读取到的是 `false`。这说明“页端设置 flag 后重新注入”的路径本身没有满足初始化顺序。

此外，真实聊天请求走 XHR：

```text
xhr POST https://chat.deepseek.com/api/v0/chat/completion
```

`fetch` 路径存在 `awaitMemorySelectBudget(120)`，但 XHR 路径没有对应等待。因此即使 `kickMemorySelect()` 被触发，首轮请求也不会等待预取结果。

**判定：`memory.select` 自动预取未完成真机闭环。手动调用成功不能替代自动预取验收。**

## 4. 异常与残余风险

### A. 工具卡与 DB 不一致

`memory_save` 工具卡显示“失败 / constraint failed”，但 DB 实际存在正确记录。用户会误以为保存失败，这是产品级可见的错误反馈。

### B. FTS 孤儿

```text
rowid=31
name=PROBE-ACCEPT-20261026-C
content=内容丙
```

主表无 rowid 31。说明 FTS 与主表存在历史一致性缺口。本轮不改 DB，只登记。

### C. 审批弹窗缺少自然语言说明

归档、恢复、彻底删除的审批弹窗只显示“该操作”和裸 ID：

```text
该操作
mem-...
```

`TOOL_DISPLAY_MAP` 未覆盖 `memory.unarchive`、`memory.purge`，可能还缺少 `memory.listArchived`。这会让用户在批准高风险删除时无法从弹窗判断目标内容。

### D. `confidence=NULL`

治理探针和创建路径均出现 `confidence=NULL`。当前设计允许 NULL，本轮只登记，不直接判失败；但若产品要求“新记忆必须有 confidence”，则需另立缺陷。

### E. `chat-send` 工具缺失

当前真机工具集中没有 `chat-send`。如果该能力属于 C1 或 Bot 核心路线图必验项，则本轮无法取证。

### F. `python_exec` 审批策略

即使审批档位为“完全放开”，`python_exec` 仍要求高风险审批，并且没有“允许本会话”。这可能是有意的安全兜底，但与“完全放开”的用户预期存在冲突，需要产品口径确认。

### G. 多轮任务可用性摩擦

多轮任务最终完成，但执行过程中出现：

- shell 语法不支持
- `host-timeout`
- `spawn-failed`
- `timeout`
- `consent-denied`

这些错误不会直接导致 trace 断流，但会显著拉长任务时间并降低用户可预期性。

### H. MCP 工具加载失败证据

用户提供的行业日志显示 MCP 工具连续 10 次 `unknown-tool` 后失败，Agent 不再看到 MCP 工具。本轮没有独立复现该链路，因此只登记为“用户提供日志证据”，不把它当作已确认回归。

### I. `memory.select` 初始化顺序与 XHR 等待

目前同时存在两个问题：

1. 页端注入时 `__studioMemorySelect` 仍为 `null`，安装期读取为 false。
2. XHR 首轮没有等待 `awaitMemorySelectBudget(120)`。

这两项使自动预取在产品级不可观测，不能以“手动调用工具成功”替代。

## 7. 结论

**代码级：通过。** 真机确认了审批入口、基础文件读取、记忆删除链路、治理字段和长任务主路径；已有代码级专项、全量和门禁证据支持。

**产品级：不能关账。** 阻断项不是“测试没跑”，而是真机产品行为仍有可见缺口：

1. `memory.select` 自动预取没有自动调用，只有手动 fallback。
2. `memory_save` 工具卡显示失败，但 DB 实际成功，用户反馈与事实相反。
3. 记忆归档 / 恢复 / 彻底删除审批弹窗缺少自然语言说明。
4. FTS 孤儿说明记忆一致性仍有历史缺陷。
5. `python_exec` 在“完全放开”下仍需高风险审批，产品预期需明确。

建议将上述 1～3 定为 C1 关账前必修，4 单独立一致性卡，5 由产品明确策略后决定是否修。

本报告不修改生产代码，不提交、不推送、不回退工作树。
