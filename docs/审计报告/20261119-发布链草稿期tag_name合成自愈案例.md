# 发布链回归案例：草稿期 tag_name 被翻成 untagged-*（2026-11-19 立案）

本案例记录 v0.14.25 发布链上的一类确定性缺陷：GitHub 在 release 草稿存活期内会把草稿的
`tag_name` 翻成合成名 `untagged-<hash>`，而发布前拦截格一旦读到合成名就 fail-closed 删草稿，
使发布后的自愈永远够不着。修复（提交 `4d1409c`，取证时为 HEAD）把自愈前移到发布前闸内。

## 一、现象（两次真跑，同为 attempt 红点）

v0.14.25 首两发 Release run（取证时记录为 run 44458455865 的 attempt=1／attempt=2）都在
第 19 步「Re-assert draft binding at job end (bounded)」红并 fail-closed 撤稿。两发的合成名
不同——attempt=1 为 `untagged-eb331ff0517663dbd08f`、attempt=2 为
`untagged-9b6d7da3bf66f8a553d2`——证明合成名由草稿派生、每发不同，不是固定别名。

## 二、根因链

1. `release.yml` 由 **tag 所在提交**提供：tag 停在修复入库前的提交（`d5dba91`）时，重跑
   attempt 跑的仍是旧 workflow，永远在同一格红；修复必须随 tag 重打（`d5dba91` 是
   `4d1409c` 的祖先，重打不改版本内容，且 v0.14.25 当时从未公开发布）。
2. **草稿期 html_url 合成 ≠ tag_name 合成**：草稿态 `html_url` 恒为 `…/tag/untagged-…`
   形态，而 `tag_name` 多数为真值——判据若查 html_url 会永久假红；判据若只认
   「tag_name 真值」又盖不住被翻名的那些发。正确口径＝tag_name 为准、html_url 不进判定。
   独立探针（私聊PM 真机实测）：用真 tag 建草稿的**瞬间** `html_url` 即合成
   `untagged-2a5676c6076f19cf9f2e`，而 `tag_name` 连续观察 240 秒仍为真值——两字段
   语义不同源，发布后闸查 html_url 是**发布后语义**，不能照抄进发布前闸。
3. 发布后闸（`release-published.yml`，取证时约第 190-239 行那段）里的自愈
   （PATCH tag_name 重绑＋只删 untagged-* stray＋回读）形态已验证，但挂在发布后——
   发布前闸删了草稿，它永远够不着。修复＝同形自愈前移到发布前闸内。
   两条前置真机探针（私聊PM 实测，修复依赖它们成立）：① **PATCH `tag_name` 在未发布
   草稿上确实生效**——PATCH 前 `probe-pm-20261119-a` → PATCH 后 `v0.14.25-probe-x`，
   3 秒回读一致；② **GitHub 并未真创建 `untagged-*` tag ref**——`matching-refs/tags/`
   27 枚全为真版本 tag ⇒ 自愈步的「删 stray」多数会 404／422，catch 后 warning 不阻断
   是对的设计，不是缺陷。

## 三、修复后实机证据（真机 PATCH 生效）

发布 run 44468352056（head=`4d1409c`）注解原文逐行：

- `bounded re-reads exhausted: tag_name=untagged-fe838527629ea854edd4 synthetic=True
  target_commitish=4d1409c… target_ok=True`
- `self-heal PATCH ok: tag_name=v0.14.25`
- `self-heal verify: draft=True tag_name=v0.14.25`
- `self-heal ok: draft re-bound to v0.14.25 — continuing`

该发草稿 tag_name 确实被翻成第三枚合成名 `untagged-fe838527629ea854edd4`（前两发之外
再添一枚，进一步坐实「每发不同」），自愈重绑后发布三判据全过（tag_name=v0.14.25、
html_url=`…/releases/tag/v0.14.25`、`releases/latest` 推进），5 枚资产、digest 三向全等。

## 四、沉淀出的四条口径

1. 合成名识别一律按 **`untagged-` 前缀形态**，不锁具体 hash（锁具体名＝下一个假红点）。
2. 自愈 PATCH 的前提＝`target_commitish` 指向本 tag 的 commit；不对＝真异常，照旧 fail-closed。
3. stray 清理只删 `untagged-*` 形态 ref，绝不碰真版本 tag。
4. 回读校验只查 `tag_name`；草稿期 `html_url` 天生合成，进判定会永久红（见二.2）。

## 五、回放口径

复现/回归验判定格在 `tests/desktop/release-workflow-anchors.test.ts`（取证时 4,711 B、
4 passed），锚点锁为正向锁五条：必须有重绑 PATCH、必须有回读确认、必须有 fail-closed
throw、必须按 `untagged-` 前缀识别、必须校验 `target_commitish`。负控对照：改前
1 failed（合成名与旧 throw 形态不匹配）→ 改后 4 passed。
