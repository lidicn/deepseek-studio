## 5. C1-F1：memory.select 自动预取（⏳ READY-FOR-HUMAN）

**代码级成立**：`src/desktop/entry.ts:285` 已将 feature flag 改为运行期 getter：

```ts
enabled: () => Boolean((globalThis as { __studioMemorySelect?: boolean }).__studioMemorySelect),
```

全仓检索确认：`__studioMemorySelect` **仅在测试中被赋值**，生产代码无任何自动置 true 的入口（无 UI 开关、无 config 读取、无 env 注入）。

**真机阻断原因**：

1. Studio 未开放 CDP 端口，CLI 无法向页面 main-world 注入 `globalThis.__studioMemorySelect = true`。
2. `docs/C1-真机人工清单-20261028.md:58` 的步骤 `globalThis.__studioMemorySelect = true; location.reload();` 顺序有误——`src-tauri/src/main.rs:653-659` 在启动时把 entry.js 读成 String 一次性 `initialization_script()`，`location.reload()` 后执行的是同一份缓存脚本（含 getter，故 flag 逻辑本身可用），但 **reload 会重置页面上下文、把先设的 flag 清掉**。正确顺序应为：先 reload（或直接不 reload）→ 再在 Console 设 `__studioMemorySelect=true`（getter 实时生效）→ 发新消息。

**结论**：代码级闭环，真机需人工在 DevTools Console 设 flag 后抓 `msel_*` callId + ≤120ms 时序。CLI 无法完成，登记 `READY-FOR-HUMAN`。
