# Studio-UI 豆包施工计划 v1 评审

> 评审日期：2026-10-19  
> 评审对象：`docs/前端开发计划/Studio-UI-豆包施工计划-v1.md` v1.0

> 修订结果：v1.1 已把 H1-H8 / M1-M16 并入施工正文

## 结论

原计划的结构、硬约束、安全边界和“不造假能力”原则可以直接交给豆包执行，但 v1.0 有 8 处会导致施工失败、误判基线或无法回退的硬伤，另有 16 项必须补齐的工程约束。

本次没有只追加评审意见；v1.1 已按下列结论改正文。

## 必须补的 16 项

- M1：`ToolRunEvent` 与 `agent-loop-event.ts` / `tool-event-bus.ts` / `tool-record.ts` 的关系已写清，不替换旧契约。
- M2：`policy-contract.ts` 只搬迁 + re-export，禁止第二套定义。
- M3：扩展现有 `main-tray`，不新建托盘。
- M4：C8 是替换图标，列出尺寸与 hash 记录。
- M5：`entry.js` 基线 401,573 B，上限 450,000 B；`dist/agent-panel.js` 上限 120,000 B。
- M6：C4 增加 `src/inject/` 保留/迁移/废弃清单。
- M7：Workbench 走 `agent.css` + CSS 变量；Focus 走 Shadow DOM。
- M8：C6 增加组件 → 数据源映射表，禁止 mock。
- M9：C5 增加产物时效检查，源码新于 bundle 强制重建。
- M10：本期不做 i18n，中文集中定义。
- M11：Workbench 补焦点、ARIA、reduced motion。
- M12：L1/L2 降级必须有日志和可见状态。
- M13：每个 checkpoint 前 `git fetch`，不 rebase/merge。
- M14：C7 旧面板迁移收口，不允许两套 Shadow API 长期并存。
- M15：DOMPurify 精确锁 `3.4.17`，记录体积与 sanitize 方式。
- M16：契约/边界/覆盖率/空文件四项阻塞检查单独跑，不能因 gate 既有红灯跳过。

## 保留的优点

- 硬约束清单与 13 轮审计反复出现的问题模式对应，尤其权限词表、审批词、pointer-events、disposer 幂等、未知值兜底。
- “不把后端没有的能力做成假按钮”应原样保留。
- `account-block` 的 fail-closed 例外正确。
- “不要把三条失败写成全绿”的基线意识正确。
- “代码事实优先于旧文档，不自行扩大范围”应保留。

## C0 开工顺序

```text
C0-0 git fetch；记录 4afea0f 与 upstream 关系，不 rebase/merge
C0-1 实体备份 entry.js；临时 outfile 重建并证明源码可重建产物
C0-2 记录安全红线测试 passed/failed/skipped
C0-3 记录 mutable-workspace.test.ts 的历史文件名，不删除
C0-4 jsdom Shadow / adoptedStyleSheets 探针
C0-5 记录 entry.js / dist/agent-panel.js 体积与产物时效

```

C0-1 未 PASS 前，禁止进入 C4，禁止执行任何覆盖 `src-tauri/inject/entry.js` 的构建。
