Snapshot as of 2026-11-05 · 47 controls across 10 domains（域 13 预留不用）
This page shows exactly what each finding in this audit was measured against. It is a snapshot taken on 2026-11-05 — 取自 audit-software-project 1.0.1 的 references/audit-controls.md。该标准可能随时间细化，日后审计的 criteria 页可能与此不同。Findings link here by control ID (e.g. "control 3.1")。 Amber 为 Green/Red 之间的灰区（部分、不一致、中风险）；Not Verified 表示 证据不可达（非失败）；Not Applicable 须写明理由。所有判定校准于 intake 风险 画像（本仓：专有桌面工具、单人、本地数据面、无远程生产）。

1. Ownership and accountability

IDControlEvidence requiredGreenRed
1.1Named technical ownerCODEOWNERS、README maintainers、提交作者集中度可识别的责任人或值班轮换生产在用项目却完全无法识别责任人
1.2Decision record for significant changesADR 目录、PR 设计说明、架构文档重要技术决策某处有书面理由老/复杂项目对任何决策零记录且已造成真实风险
1.3Knowledge concentration (bus factor)git shortlog 全期 + 关键路径 scoped多人触达关键路径，或已知单人项目（明示）多人生产项目几乎全由一个已不活跃作者提交且无 CODEOWNERS 缓解

IDControlEvidence requiredGreenRed
3.1Branch protection on default branchgh api branches/{default}/protection保护开启且要求 PR + ≥1 评审默认分支接受无评审直推
3.2PRs actually get reviewedgh pr list --state merged --json reviews 采样多数被采样 PR 有评审保护名义要求但实际无评审，或自合并可见
3.3CI required to pass before mergebranch protection 必选状态检查 + workflowsCI 被要求且至少覆盖构建/测试CI 存在但非必选，或不存在
3.4No secrets committed to history标准搜索：跟踪树模式扫描 + *.env* AD 历史树与可达历史无活体形态密钥发现活体形态密钥——恒 Red、恒即时阻断
3.5.gitignore covers secrets/build artifacts.gitignore vs 跟踪文件.env*、凭据、构建产物被忽略且未跟踪（不完整为 Amber）
3.6Commit message hygienegit log -50 --format=%s 采样消息大体描述意图多贡献者项目多数消息无描述

4. Code quality and maintainability

IDControlEvidence requiredGreenRed
4.1Linting/formatting enforcedlinter 配置 + CI 步骤 + pre-commitlinter 在 CI 运行且失败挡合并多贡献者代码库完全无 lint
4.2Dependency currency锁文件日期、npm outdated、EOL 运行时依赖/运行时一年内或有活跃更新流程关键依赖/运行时落后多个大版本且已知 EOL、无更新流程
4.3No obvious dead/duplicated critical logic复制粘贴业务逻辑、注释掉的代码块抽查（软控制，仅当判断不窄时 Amber/Red）（同上）

4.5Configuration hardcoded in sourcegrep localhost/字面 IP/端口/分散环境分支环境值读自配置/env生产相关值硬编码、改环境需改码
4.6Unresolved TODO/FIXME debt in critical paths关键路径 grep TODO/FIXME/HACK未发现或仅为装饰性（Amber 层：关键路径已知不安全/未完成标记）
4.7Type safety on critical pathsTS strict / mypy 等覆盖关键路径关键路径静态类型化或语言固有静态类型多贡献者生产项目关键路径无类型工具

5. Automated testing and critical behavior coverage

IDControlEvidence requiredGreenRed
5.1Tests exist and run测试目录/框架 + CI 步骤测试存在且在 CI 执行完全无自动化测试
5.2Critical business paths are covered测试名/内容对照核心特性风险最高流有自动化覆盖关键流（资金/鉴权/数据丢失）零覆盖
5.3Tests aren't silently skipped/broken.skip/xit/@Disabled 标记、CI 历史（大量无跟踪原因的跳过为 Amber）（同上）
5.4Integration/e2e coverage on critical flows全流测试 vs 纯单测至少一条关键流有集成/e2e 覆盖（仅单测覆盖为 Amber）

6. Security, secrets, dependencies, and production access

IDControlEvidence requiredGreenRed
6.1Dependency vulnerability scanningDependabot/Snyk 配置 + 审计期 lockfile-only 扫描已配置自动扫描，或审计扫描无 high/critical无扫描且审计扫描命中 high/critical
6.2Production access control部署/生产访问文档、env 处理示例与真实密钥分离、访问流程有文档（通常 Not Verified——入 intake 问题）

7. CI/CD, deployment repeatability, and rollback

IDControlEvidence requiredGreenRed
7.1Deployment is defined as code/configCI/CD 管线、IaC、部署脚本 vs 手册部署脚本化、可复现部署依赖仅一人知道的未记录手动步骤
7.2Rollback path exists回滚文档、版本化 tag、迁移 down 脚本（通常 Not Verified——仓库难以确证）有肯定性证据表明回滚不可能（不可逆迁移且无备份策略）

8. Architecture, trust boundaries, APIs, and data

IDControlEvidence requiredGreenRed
8.1Trust boundaries are identifiable鉴权中间件、边界输入校验外部输入使用前被校验；敏感端点强制鉴权敏感端点（数据变更/管理动作）发现无可见鉴权
8.2Database migrations are safe and reviewed迁移目录、与其他代码同走评审迁移版本化且随代码同审（绕过评审为 Amber）
8.3Input validation at API boundaries校验层（zod/joi/pydantic 等）vs 裸消费 body敏感端点外部输入过校验层敏感变更（资金/鉴权/管理/PII）直接消费未校验输入
8.4Injection surface拼接 SQL、eval、命令解释器插值、innerHTML 喂用户输入无用户可达注入汇点，或用参数化/转义等价物用户可达路径把未净化输入喂给注入汇点
8.5Error handling discipline on critical paths空 catch/except: pass/未处理 rejection 扫描关键路径错误被显式处理（抛出/带上下文记日志/作为响应返回）关键路径静默吞错，失败对用户与运维均不可见

IDControlEvidence requiredGreenRed
9.1Monitoring/observability present日志配置、APM/错误跟踪 SDK错误跟踪与基础监控接入应用面向生产的应用零错误跟踪、零可见日志策略
9.2Backups exist for stateful data（几乎不可能从仓库确证）（默认 Not Verified——非失败）仅当仓库有肯定性证据表明备份被关闭/移除
9.3Alerting configured, not just monitoring installed告警规则配置 vs 仅 SDK 依赖；依赖 9.1 Green告警规则入仓或 owner 确认已配owner 肯定确认监控装了但无人被叫醒

11. Performance and scalability

IDControlEvidence requiredGreenRed
11.1Unbounded queries热路径数据访问无分页/LIMIT 扫描面向用户的列表端点有分页/上限面向用户端点返回可无限增长表的无界结果集
11.2N+1 query patterns循环内 DB 调用 vs 批量/JOIN（Amber 层：关键路径 N+1 形态）（同上）
11.3Resource limits on external-facing endpoints超时/体量上限/限流 全局或按路由超时与体量上限已设置（全局或逐端点）面向用户且未鉴权端点三无（超时/体量/限流）——兼作安全 DoS 项
11.4Caching on read-heavy paths缓存层 vs 昂贵聚合读；仓库内性能关注证据昂贵读处有缓存，或未发现昂贵读路径（永不为 Red——Amber 层）

IDControlEvidence requiredGreenRed

12.2Breaking changes are versioned or gated版本前缀、changelog、弃用头破坏性变更走版本升级或弃用窗口证据表明破坏性变更原地上线且无弃用通知
