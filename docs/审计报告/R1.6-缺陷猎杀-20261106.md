## 本轮扫过且 PASS 的缺陷类别（证据摘要）

1. **/g 正则状态 bug**：USER_HINT/ASSISTANT_HINT（`/i` 无 g）、CMD_METACHARS×3（`/[&|<>^]/` 无 g）、search-files 的 `re.test`（无 g 标志）——全仓 81 处 `.test(/)` 候选逐个验标志，**0 个 /g 状态风险**。
2. **限流器**：LRU 驱逐（delete+set 移尾，Map 插入序）+ size 有界断言（TD-12）——无内存泄漏。
3. **catalog-selection**：降级循环 `demoteAt<0 → break` 终止完备；`isPinned` 每次新建 RegExp 无 g 标志（无状态）；localStorage 负数/NaN 已有守卫。
4. **memory-store/storage.ts**：主表+FTS+审计同事务（BUG-012/013 修复形态）；**观察项**：`compact()`（VACUUM）失败仅 console.warn → Windows 多进程锁场景下 purge 的「物理清零」保证降级为 secure_delete 新页清零（已删条目旧页残留文件内）——与 14.2 的 Green 结论不冲突但建议文档化该降级条件。
5. **agent-loop**：看门狗/stopFlag 轮询/节流 abort/续跑超时空内容显式报错——全防御。
6. **发版线**：release-published 公开链路闸（latest.json→302→字节→签名，失败打回 draft）——fail-closed 完备。
