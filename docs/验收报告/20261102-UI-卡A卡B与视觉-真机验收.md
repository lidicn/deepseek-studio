## 1. 卡 A：工具卡「默认折叠 + 按状态自动展开」混合策略

| 判据 | 读数 | 结论 |
|---|---|---|

| ok 卡默认折叠 | `status=succeeded` → `rowExpanded=false`、`bodyHidden=true` | ✅ |

| 手动点开/收起可用 | 行：false→true→false，`data-ds-user-toggled=true`；组：`hidden` true→false→true，`data-user-toggled=true` | ✅ |
| 思考块现状保持 | 正文出现后 `open=false`（折起），未改 | ✅ |

### 1.1 过程中修掉的真缺陷

**首轮真机失败**：失败卡虽然展开，但**整组仍折叠**（`groupOpen=false`）——展开的红卡被折叠的组挡住，用户根本看不见。

**根因**：`updateSummary` 里「有 failed/denied 就展开组」的判断被 `data-user-toggled`（用户手动折叠过）压制；而用户手动折叠过一次后，这个标记会**一直留着**，于是**后来**出现的失败卡/执行中卡永远被折叠挡住。这违背「折叠着放错误等于藏 bug」的意图。

**修法**（`src/inject/tool-card-ui.redesign.ts`）：
- 卡片级：用户手动折叠只压制「无异常时」的展开态；状态变成 `failed`/`denied`/`running` 时**强制展开**。
- 组级：出现 `running`/`failed`/`denied` 时**强制展开组**（不再看 `data-user-toggled`）；只有「全部 ok 且用户没手动操作过」才折回一行。

回归测试新增 2 例（`tool-card-ui.redesign.test.ts`，共 **31 例全绿**）：
- 「手动折叠过之后新出现的失败卡仍强制展开」；
- 「用户手动折叠过整组后，新出现的失败卡仍把组强制展开」。

> 过程中我自己踩了一次坑：第一版新用例红了，**不是代码错，是测试断言用了旧 row 引用**——`renderItem` 用 `innerHTML` 重建行，旧节点已脱离 DOM。改正断言后绿。

## 2. 卡 B：XHR 延迟路径必须消费 memory.select 预取结果

### 2.1 真机读数

- 写入探针记忆：`ZZ-UI-PROBE-1793553437888`（id `probe-1793553437888`）→ 库行数 26 → 27。
- 页端打开 `__studioMemorySelect` 开关（默认关）。
- 发一条消息 → `memory.select` 帧发出（`callId=msel_1793553579960_f7lcfe`）。
- **本轮请求体 `hasMarker=true`**（10192 B）→ 探针标记**当轮**就在注入里，不等下一轮。

### 2.2 第一次 FAIL 是**脚本方法问题**，不是产品缺陷

首跑 `hasMarker=false`。查下去发现：`memory.select` 是**按任务文本检索**（宿主 `search(query)`，FTS bm25 → LIKE 兜底），探针名 `ZZ-UI-PROBE-…` 与我第一版任务文本「请复述一句：记忆探针」无交集 → **检索返回空**（响应仅 120 字节、无 memories 列表）→ 注入层拿到的就是空。
把任务文本改成含标记（`请查一下 ZZ-UI-PROBE-… 这条记忆，然后复述它`）后当轮命中。
**结论：注入层「拿到什么注入什么」的语义正确；空结果来自检索侧的任务文本，不是 XHR 延迟路径。**

### 2.3 清理

删探针后：**27 → 26 行**、`pinned=0`、残留探针 **0 条**，`memories.db` 回到基线（基线 26 行；C1 时的 23 行是旧基线，用户此后自己加过 3 条）。

### 2.4 代码口径（与 PM 方案的偏离，已报备）

PM 方案是把 `doDelayedSend` 直接改 `async`；**我没有那样做**——`proto.abort` 包装是**同步**调用延迟 send 的（要求「补发 origSend + origAbort」在同一同步块内完成，否则 `readyState=4` 回调链会悬），`async` 一 await 就会把 `origAbort` 推到微任务。

我的实现：
- 抽出共用 helper `consumeMemorySelect()`（**fetch / XHR 两条路径共用**，根治分叉）；
- XHR 正常路径：`consumePromise`（自带 **120ms 预算**）resolve 后才 `prepareChatSend()` → 本轮生效；
- XHR abort 路径：新增 `__dsDelayedSendSync` 入口，**同步**取已 settle 的结果（WeakMap 记）→ 同步完成 origSend+origAbort。

过程中我自己修掉两个坑：**①** 第一版无界 await 会把发送**永久卡住**（预取可能永不 settle）→ 改自带 120ms 预算；**②** 外层 `raceBudget(pendingSel,120)` 与消费预算叠加会等两遍 120ms → 改成只等消费函数。
