## 5. 预检发现的两个事实（已由 PM 裁决）

### 5.1 `handle.stop()` 在生产路径上目前**不可达** → **P2，不开卡**

- `src/desktop/entry.ts:330` 调用 `installMainWorldInterceptor({...})`，
  **丢弃了返回值**（handle）。
- 拦截器也**没有**注册成可 `dispose` 的 `ContentCapabilityController`
  （`entry.ts:135` 的 capability 列表只有 echo / chat-read / chat-insert / chat-send）。

后果：

- R4-H2 的修复代码本身正确、且被 `r4-inject-guards.test.ts` 覆盖；
- 但**真机上「用户点停止」走的是另一条路**：
  DeepSeek 页面停止 → `proto.abort()`（`main-world-interceptor.ts:1427`）
  → `loopState.abortedByUser = true`
  → `settleStreamEnd` 清 `autoContinueTimerRef`（`:1901-1912`）。
- 所以真机 h2 验的是**真实可达路径**（用户中止后不得有幽灵续跑/幽灵请求），
  **`handle.stop()` 的清理逻辑不会被真机直接验到**。

**PM 裁定（2026-11-02 08:19）**：按上述口径执行；本条**记 P2，不现在开卡**。
定性为**设计取舍，不是缺陷**——当前页面生命周期由 webview 管，
dispose 只有在 SPA 切换 / 热替换场景才有价值；届时连同 `stop()` 可达性一起接。

### 5.2 `stop()` 里有一处与 H2 目标不完全对齐的写法（已复核，非缺陷）

`stop()` 中 `loopState.abortedByUser = true` 之后，**没有任何路径会把它复位**。
复位只发生在 `onNewUserMessage`（`:2344`）。这是符合语义的（卸载即终止），
但意味着同一页内若将来把 handle 复用，`abortedByUser` 会一直为 true。
当前无复用场景，**仅记录，不改**（避免超出任务卡范围）。

#### ⚠️ 一个必须记录的实测事实：DeepSeek 当前版本**没有「停止生成」按钮**

这一条花了 6 轮探测才搞清楚，**结论对后续验收都有用**：

| 探测 | 做法 | 结果 |
|---|---|---|
| v1 | 按「位置 diff」找生成态新增按钮 | 被页面滚动破坏（选到屏外 `y=-734` 的按钮） |
| v2 | composer 容器内 + svg 指纹对比 | composer 里**恒为 2 个按钮**，生成态**不新增**控件 |
| v3 | 点发送按钮（生成态它是 `data-icon="spin"`） | 该按钮**带 `ds-button--disabled`**，点击**无效**；日志 `aborted by user` 出现 **0 次** |
| v4 | 生成态全页扫 `stop`/`pause`/`square` 图标 | **0 命中** |
| v5 | 逐帧采样（原生生成） | 发送按钮 idle=`filled`+纸飞机 → 发送瞬间=`spin` → 生成中=`filled`+无图标 → 结束=`outlined`。**全程没有独立停止按钮** |
| v6 | 全页扫 class/aria/title/data-testid/id 含 `stop\|abort\|pause\|停止` | **0 命中** |

⇒ **DeepSeek 这个版本不暴露「停止生成」按钮**（只能靠导航离开/刷新中断）。

**最终做法**：既然注入层的 `proto.abort` 包装在页里**确实生效**（实测其函数源码含
`__dsAborted` 标记与 `abortedByUser`），就在页内对**当前 in-flight 的 chat XHR**
调用其**原生 `abort()`** —— 这就是用户中止的等价真实路径，注入层会走
`abortedByUser=true` → 清 `autoContinueTimerRef` → 不再续跑。
**不是模拟**：调的就是页面自己的 XHR 实例的原生方法。

**一个实现坑**：注入层的续跑请求是**短命**的（算 PoW + 发完即结束），
外部 200ms 轮询抓不到 in-flight 窗口（`live: 0`）。
解法：**页内 5ms 粒度监视器**——一旦出现 `readyState` 在 1..3 的 chat XHR 立刻 abort。
