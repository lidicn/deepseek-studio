# 实机验收提示词（一次性跑全）

> 用途：发给 Studio Agent，一次性测 TaskLoop + 工具链 + consent 闸。
> 发完看 trace，每项打勾/打叉。

---

## 提示词（整段复制）

```
现在做一个综合验收，按顺序执行，每步做完告诉我结果：

1. 读一下当前工作目录下的 package.json，告诉我 version 字段是多少。
2. 在当前目录创建一个文件 test-m4.txt，内容写 "M4 passed"。
3. 列出 src/capabilities/ 目录下所有 .ts 文件的文件名。
4. 用 grep 搜一下 "createTaskLoop" 在 src/ 下出现了几次。
5. 记住：用户叫 lidicn，项目叫 deepseek-studio。
6. 最后总结一下：你用了哪几个工具，每步成功还是失败。
```

---

## 验收表

| # | 项 | 预期 | 结果 |
|---|---|---|---|
| 1 | file.read 工具调通 | 返回 version | ☐ |
| 2 | file.write 工具调通 | test-m4.txt 创建成功 | ☐ |
| 3 | listFiles 工具调通 | 列出 capabilities 下 5 个文件 | ☐ |
| 4 | grepFiles 工具调通 | 返回匹配次数 | ☐ |
| 5 | memory.save 工具调通 | 记忆保存成功 | ☐ |
| 6 | 多轮工具连续跑 | 6 步不卡、不崩 | ☐ |
| 7 | 最终总结 | 列出用了哪些工具、成败 | ☐ |

---

## 额外观察点

- consent 闸：如果弹审批，点通过/拒绝都试试
- 中文：消息里的中文是不是正常（不是问号）
- trace：每一步工具调用都能在窗口里看到
- 速度：6 步跑完大概多久
