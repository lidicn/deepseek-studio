## 3. 发现并修复的真缺陷：破图不降级

**现象**：坏图（`invalid.invalid`，宿主 4ms 返回 `dns_failed`）在页面上**留成破图**，不降级为占位。判据首轮 FAIL。

**定位过程**（全部真机实测，不靠猜）：
1. `img.dataset.dsProxyTried = "1"` → 说明 error 处理**跑过**，不是监听没挂上。
2. 直接调宿主 `image_fetch`：`{ok:false, error:'dns_failed'}`，**4ms 就 settle**，不是 promise 悬挂。
3. 于是问题只能在回调里：卡片是**先渲染在游离节点上**（`applyVisCards` 在 `msg.appendChild` 之前调用），回调回来时 `imgEl.isConnected === false`，旧代码 `if (!imgEl.isConnected) return;` 直接退出 → 永远不替换。

**修复**（`src/inject/vis-card.ts`）：
- 取图失败（`dataUrl === null`）时**不再要求 `isConnected`**，游离节点上也 `replaceWith` 占位（入文档后即为占位）。
- 补竞态兜底：监听绑定前就已经失败过的图（`complete && naturalWidth===0`）补走同一条降级路径。
- 回归用例：`vis-card.test.ts`「游离节点上的坏图也要降级成占位」。

修复后同一场景 **PASS**（§2 的读数）。

| **trace 记 `tool-text-unparsed`** | **单测锁定**，非真机复现 | ⚠️ 见下 |

实际渲染出的文本（原样）：
```
我先查一下目录。查完了，没有找到目标文件。
已隐藏 search_files 的调用原文（这条调用当时没有执行）
```

### 4.1 边界说明（按 PM 要求如实区分）

「trace 记 `tool-text-unparsed` 而不是 `no-tools`」这一条**没有在真机上复现**：它要求真的出现「模型吐出工具原文、解析器又没吃到」的回合，真机上不可控触发。替代证据是：

1. 判定逻辑抽成纯函数 `continuationReasonForReply()`（`src/inject/raw-tool-text.ts:119`），单测覆盖 3 例：普通散文→`no-tools`（含负控「只是提到 search_files 名字」）、真机原文→`tool-text-unparsed`、带属性漏解析形态→`tool-text-unparsed`。
2. **同一个函数在拦截器真实判定点被调用**：`src/inject/main-world-interceptor.ts:2523` → `reason: continuationReasonForReply(reply)`，即 `turn.end` 前那条 `continuation.decision` 的 reason 取值。

所以这条属「**代码路径 + 单测锁**」，不是「真机实测」。报告按此口径记，不混着写。

## 5. 过程中踩到的两个环境坑（避免后人重复）

1. **`entry.js` 重建后必须重启实例**：Tauri 的 `initialization_script` 在启动时读一次并复用，**页面 reload 不会重新加载新脚本**。我第一次重建后只 reload，跑的一直是旧代码，白验一轮。
2. **注入卡片会被原生历史水合覆盖**：`activateSession` 会拉 DeepSeek 原生历史并重建消息树，注入的卡片只闪一下。解法：注入的会话记录带 `historySyncedAt: now`（TTL 内跳过水合）。
3. 顺带：DeepSeek 的发送控件是 `div.ds-button--circle`（不是 `<button>`），按 `button` 找点不到。
