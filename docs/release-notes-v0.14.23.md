# v0.14.23 发版说明

发布日期：2026-11-16（tag `v0.14.23`，自 `v0.14.22` 起三笔）

## 这版修了什么

### 1. 登录取证的两处「静默丢失」闭合（`b984e88` ＋ `fb6e2c8`）

**现象**（2026-11-16 真机实测）：v0.14.22 装了整套登录取证日志，但装版里 `[auth]` 命中 **0 条**——不是没记，是记了之后在传输通道连上之前被无声丢掉了。这等于「下次掉线能归因」这一格没有真正交付。

**两处根因**：

1. 页面载入时的起手自检在文档就绪的那一刻就执行，**早于宿主 WebSocket 被接受**；而自检自己抛出的异常被一个空的 `catch` 吞掉，连错误痕迹都不留；
2. 通道层的发送函数在连接尚未 OPEN 时直接返回——**没有队列、没有计数、没有一行日志**。

**修复**：

- 起手自检不再无声失败：自身抛错改走 `[auth] boot-check-failed` 出口，有行可查；
- 通道层新增**预 OPEN 有界队列**（上限 256 条）：只允许「发完不管」的三类报文（诊断日志 `log`、链路跟踪 `trace`、完整性告警 `integrity-alert`）在连接建立前排队，OPEN 后按原序补发；
- 队列满时**丢最新**并在连接建立后补一行 `[transport] preopen queue overflow N`——理由：诊断里最值钱的是故障发生那一刻的第一手现场，后来的行多是同一状态反复重打；
- `integrity-alert` 有专门的行为锁：重连后**不重放**旧告警，避免把已经恢复正常的页面误判成篡改；而重连后**新发生**的告警照旧即时送达，不会因为「不重放」而对新的篡改失聪；
- 带待回执与超时的工具调用、以及驱动对话续跑的三类事件（`assistant-reply`／`stream-delta`／`finish-sentinel`）**一律不排队**——排队会让宿主去答复一个已经过期的请求、或者把两轮内容串在一起。这是一处有意保留的已知损失面，写在这里而不是藏起来。

**这一版的准确口径**：取证管线端到端**已在真机上验过**（dev 实例日志里能看到 `[auth] boot-check …` 与 `[auth] resp … HTTP 200`，同一路径上一发旧包跑时那一行是 0）；但**队列这条路径至今没有在真机上被自然撞见**——那次取证的通道比自检行先就绪，走的是直发。它现在由 7 枚单元测试锁住行为。所以本版说的是「两处无声丢失已堵住、闸全绿」，不是「已实测通过」。

### 2. `start-studio.bat` 去两处写死（零行为改动，`f67c124`）

- 目录改为脚本所在目录，不再写死某台机器上的绝对路径；
- 删掉 `STUDIO_WORKSPACE_ROOT` 覆盖（它会把工作区缩到仓库的子目录，让同盘别的项目被误报成「越界访问」）；
- 删掉 `STUDIO_POLICY_MODE=full` 覆盖（两棵配置根本来已是 full，这个变量只会让你在设置面板里改的档位被无声钉死）。

## 闸与证据

- CI 三 check 全绿；新增 7 枚队列锁与 11 枚 HTTP 状态码锁在 CI 里**均无 skipped**（即真跑）；
- 全量：317 个测试文件 / 3522 passed / 10 skipped / 0 failed；
- 产物指纹随本包重建（注入包内版本串已是 0.14.23，无 0.14.22 残留）。

## 已知未修（下版候选）

- 队列路径的真机证据等自然复现（出现 `overflow` 行、或自检行号早于通道就绪行即算现场证据）；
- 续跑三类事件在连接窗口期仍会丢（已知损失面，是否改成「按轮丢弃＋可见提示」待定）；
- 沿用上一版三条：设置面板显示登录态剩余有效期与临期提醒；dev 实例独立 `identifier`／独立 WebView2 档案目录；standalone 档位切换死锁的可见逃生门。

## 升级说明

标准 NSIS 安装包升级，配置与登录档案跨版本保留（卸载默认不删应用数据）。升级后如果再见掉登录，日志里的 `[auth]` 行应能直接指出是哪一跳把会话弄丢的。
