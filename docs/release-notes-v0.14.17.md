# DeepSeek++ Studio v0.14.17

本版本包含两项聊天界面的显示修复，以及发布流程自身的多处修复。

先说明一件事：从 0.14.12 之后的**四个版本号（0.14.13、0.14.14、0.14.15、0.14.16）都没能产出可用的安装包**，原因各不相同。所以如果你现在用的是 0.14.12，本版本是它之后的第一次正式更新，界面上的变化会一次性到位。

一、模型只调用工具、没有输出正文时，页面不再留下空白回复框。以前遇到这种情况（一轮里全部内容都是工具调用、没有给人看的文字），界面上会出现一个没有内容的回复框；现在会显示一句中性说明「本轮模型仅输出了工具调用，没有正文回复。」，不标注为错误，也不影响下一轮继续。

二、同一轮回复不再多出一枚空气泡。在「工具原文还在返回、随后本轮没有正文」这条路径上，以前会先后出现两枚回复框，其中一枚没有内容；现在这条路径只保留一枚，且收尾后不会残留闪烁的光标。这一条有单独的自动化用例锁住气泡枚数与光标状态。

三、发布流程的修复（不影响已安装版本的功能）。上面那四个版本号分别卡在发布链的不同环节：0.14.13 是打包工具的解压位置不对（工具下载和解压都成功了，但构建器在它期望的位置找不到它）；0.14.14 是我们发布脚本里有一处写法让构建在开始下载前就报错；0.14.15 走到了发布环节的最后一步才失败——回读刚写入的发布说明时只查一次就判定失败；0.14.16 再往后一步失败——查找刚创建的草稿时只按标签列表查了一次，没查到就直接放弃。**这四次失败暴露的是同一个结构性问题：发布链上新增的步骤只在「第一次被执行到」的时候才真正被验证过，而前面某一步失败时，后面的步骤从来没跑过。** 本轮的修法因此分两类：一是把这几处「一次定生死」的查询改成带重试的确定性查找（优先用上一步返回的草稿编号直接读取，读不到再退回按标签列表查找，两种查找都重试），二是让每一步失败时都把现场情况写进公开可读的诊断信息，这样下一次不用再靠猜。

四、0.14.15 那次失败的确切原因，我们目前仍没有定论——当时能确认的只有「前面 15 步都成功、第 16 步两秒即失败」，而失败原因没有写在任何能看到的地方。本轮已经补上了这条信息，所以下一次运行才能给出定论。

五、上一版新增的发布脚本自动检查也修了两处自身的局限：它原本会按报错文字的内容来判断，而同一条错误在不同系统语言下文字不同，会让本来正常的检查在英文系统上失败，现在改为只校验我们自己写入的结构标记；另外它自己有一处探针写成了「无条件报错」，会让一个其实成功的步骤在日志里留下红色错误行，本轮已降级为普通提示。

以上条目都有自动化测试覆盖。第一、二条属于界面显示效果，我们还没有在正式安装版上逐项手工走过；如果升级后你仍然看到空白回复框，或者一轮里出现两枚回复框，请把当时的对话内容发给我们，这属于要逐个核实的情况，不作「再也不会出现」的承诺。

建议从 0.14.12 或更早版本直接升级。
