# v0.14.26 发版说明

发布日期：2026-11-20（tag `v0.14.26`；本版修的是出资人实测报出的「Studio 使用有问题」三处真实缺陷＋一处模型自述失真，全部经真机取证与独立验收）

## 这版修了什么

### 1. 同一轮里的多个工具标签会真并发执行（护栏缺失，`c92caa4`）

**现象**：一轮里模型同时输出两个工具标签时，两枚会**同时开始执行**（真机实测：一枚 `local_file_read` 还在跑，另一枚 `local_file_read` 已经起跑，两条结果几乎同时回来）。页端注入的提示词里写着「一次只调用一个工具」，但那只是提示词，宿主侧零强制。

**为什么危险**：这次侥幸是两枚只读；两枚 `file.edit` 改同一个文件就是读改写交错、**静默丢改动**，用户完全看不出来。

**修复**：宿主侧加一道「单轮串行护栏」——同一轮里**同时最多一枚在跑**。只读调用排队等（按到达顺序），写类／执行类（写文件、改文件、跑命令）并发到达时**直接拒绝**并回明确可行动的提示（带终止信号，说明「未被执行，请等上一条结果后再发」）；同时对「本轮已执行过的完全相同调用」熔断，防模型原地打转。

### 2. 一次慢检索会白等 75 秒，且超时后还在继续读盘（`c92caa4`）

**现象**：`search_files` 检索一个大目录，跑了 **75 秒**才被页面端超时掐断；掐断之后**宿主那边的遍历还在继续读盘**——用户看到的是「超时了」，机器其实还在忙。

**修复**：三层同时上——① 遍历加预算（深度／目录项数／读文件数／耗时四道闸，超了就收口并**明说**「结果已截断、因为什么、建议怎么缩小范围」，而不是默默给半截结果）；② 补一条真正的**取消通道**：页面端放弃等待时会通知宿主真的停下，不只是「不再等」；③ 超时顺序修正为**先通知取消、再放弃等待**，反过来的话取消通知发出去也没人受益了。

### 3. 参数靠猜，两种常见错法都只回一个错误码（`c92caa4`）

**现象**：把一个**文件**当目录去检索、或者给了文件名模式却漏了关键词，两种都会在运行期才报错，而且只回一个干巴巴的 `invalid-argument`／`missing-argument`，模型不知道自己错在哪。

**修复**：两种错误都改成**可行动**的回复（说清错在哪、该改成什么），并把约束前写进给模型的工具说明（grep 时关键词与模式二者必给其一、检索根必须是目录、检索单个文件请改用读文件工具或把根指向父目录）。

### 4. 模型看不见自己上一轮干了什么，于是给出假的「自我检讨」（`c92caa4`）

**现象**：这一轮实际跑了 18 次工具调用、8 次读文件成功、耗时跨 302 秒；下一轮模型却自述「同一轮同时输出两个标签」「审计一步都没做，等于空转」——**三句都与记录冲突**。用户读到的是失真结论。

**根因**：续跑上下文里，工具记录会被窗口压成没有参数、没有耗时的摘要，超预算还会整条省掉——模型对自己本轮做了什么**没有事实依据**，检讨自然是编的。

**修复**：续跑上下文里加一段**本轮全部工具调用的单行摘要**（`#序号 工具{关键参数} → 成功/失败(耗时)`），覆盖本轮每一次调用、不受窗口与预算裁剪，插在完整结果之前。

### 5. 「撤销来晚了」被静默吞掉（`8f3a992`）

**现象**：页面端放弃一次已经在跑的调用时，如果宿主那边恰好已经跑完（快机器上很容易撞上），撤销就**没人认领**——页面端那边永远挂着 pending。这条在 CI 上被真跑出来过。

**修复**：撤销到达时分三种可判形态——真的在跑（回「已取消」）／已经跑完（**追加**一条「撤销来晚了、结果已按原回执送达」，**不改写**已发出的正常回执）／对不上号（回一条不带结论的撤销告知，**不静默**）。

## 升级说明

标准 NSIS 安装包升级，配置与登录档案跨版本保留（卸载默认不删应用数据）。

**从 0.14.25 升上来的用户请核验三点**：① 同一轮里连发两个工具标签时，第二个应当**排队等待**（只读）或**被明确拒绝**（写类），不再同时执行；② 检索大目录应当**十几秒内**带「已截断」原因收口，不再干等 75 秒；③ 续跑时模型应当能说清上一轮做过哪些调用。
