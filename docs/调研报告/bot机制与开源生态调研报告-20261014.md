## 一、Ekko Studio 的 Bot 机制

### 1.1 项目定位

**Ekko Studio**（原名 Hermes Studio / Hermes Web UI）是一个**本地优先（local-first）的多 Agent AI 工作区**，提供三种分发形态：

- 桌面应用（Windows / macOS / Linux）
- 自托管 Web 控制台
- Docker 镜像

- 仓库（待核实）：https://github.com/EKKOLearnAI/ekko-studio
- npm 主包名：`ekko-studio`

### 1.2 多 Agent 运行时：不止 Hermes

Ekko Studio 的核心能力是**在一个工作区里同时运行多种 Agent 运行时**，并归为三个 Agent Family：

| Agent Family | 运行时 | 负责的能力 |
|---|---|---|
| **Hermes** | Hermes | Profile、Provider、模型、技能、插件、记忆、任务、Kanban、渠道、MCP、终端 |
| **Ekko** | Ekko | 执行、审批、澄清、记忆、MCP、Provider Runtime |
| **Coding** | Claude Code、Codex、Pi、Grok、OpenCode、DeepSeek Harness(DSH) | Coding Agent 的安装、配置、代理、会话与进程执行 |

Studio 本体负责三个 Family **共用的能力**：单聊、群聊、Global Agent 编排、工作流、Webhook、会话、文件、TTS/STT、媒体、设备、日志、用量、认证、App 连接。

### 1.3 聊天室（Group Chat）机制 —— 结论：有

Ekko Studio **确实内置多 Agent 聊天室**，机制要点：

- **实时通信**：基于 Socket.IO
- **房间管理**：创建 / 删除房间、邀请码管理
- **@提及路由**：在群聊中 @某个 Agent，才触发该 Agent 的上下文回复；Agent 按需加入，非全部必答
- **按 Agent 配置**：每个加入房间的 Agent 可有独立 profile 配置
- **上下文压缩**：历史超 token 阈值时自动对话摘要
- **状态指示**：typing status、回复进度指示器

**典型用法**：同一房间加入多个 Agent（分析 / 编程 / 内容创作 / 文件处理），用 @Agent 指定当前任务主导者，各 Agent 可用不同模型。

### 1.4 平台渠道（把 Bot 接入外部 IM）

提供**统一配置页面**，一次性配置 10 个消息平台，各平台独立控制项：

| 平台 | 支持的 Bot 特性 |
|---|---|
| **Telegram** | Bot Token、提及控制、表情回应、自由响应聊天 |
| **Discord** | Bot Token、提及、自动线程、表情回应、频道允许/忽略列表 |
| **Slack** | Bot Token、提及控制、Bot 消息处理 |
| 其他 | WhatsApp、Matrix、飞书、钉钉、微信、企业微信、QQBot |

## 二、Hermes Bot

### 2.1 Hermes Agent 本体

**Hermes Agent**（Nous Research）定位为**会随使用不断成长的自我进化 Agent**，内置五层记忆系统、自主技能生成（Skill）、辩证式用户建模、FTS5 跨会话搜索。本体是**终端原生（terminal-native）自主代理**，内置 messaging gateway，可运行在 19+ 原生消息平台。

- 仓库（待核实）：https://github.com/NousResearch （需确认具体 Hermes Agent 仓库路径）
- 许可：MIT（待核实）

### 2.2 Bot Mode：把 Profile 变成具名 Bot

Bot Mode 为 v0.21.0 引入，**内置于桌面应用，默认开启**。核心设计极简：

> **一个 Bot = 一个 Hermes Profile**

Profile 位于 `~/.hermes/profiles/<name>/`（待核实路径），拥有隔离的配置、记忆、技能、凭据与聊天历史。Bot Mode 是此原语之上的 UI 层，CLI 同源（`hermes -p <bot> chat` 打开同一 Agent）。

| 普通 Profile | 有 Bot Mode 之后 |
|---|---|
| 一堆 sessions，需手动选 | 每 Bot 有**永久 Bot Chat**，点击即回同一对话 |
| 切 profile 才能换专家 | 所有 Bot 在一个 roster，显示头像/最新消息/未读 |
| **Profile 之间从不互通** | **Bot 可互相发消息，并共享群聊** |
| 定时任务在 `hermes cron`，与聊天分离 | 每 Bot 的 routines 就在聊天旁编辑管理 |

### 2.3 Hermes Bot Mode 的群聊机制

群聊为**串行轮次（serial rounds）**设计：

- **成员规模**：2–6 个 Bot
- **轮次上限**：一条用户消息触发**最多 3 个串行轮次**，每轮内最多 10 条成员消息
- **@提及**：@某 Bot 则只有它回复；不指定则所有 Bot 依次发言，每个 Bot 可选"简短回复"或"跳过（pass）"
- **并发与串行**：同一轮内 Bot 发言**并发**（`Promise.all`），轮次之间**串行**，使后发言者能看到前者回复，形成接力讨论
- **Bot 间消息**：不打断对方正在执行的任务，而在对方**下一次轮次**被拾取

### 2.4 关键区分：两个层面的群聊

| 层面 | 归属 | 管理对象 |
|---|---|---|
| **工作区层群聊** | Ekko Studio | 多种 Agent 运行时（Hermes、Claude Code、Codex…）的协作 |
| **Hermes 内部层群聊** | Hermes Bot Mode | 多个 Hermes Profile（Bot）之间的协作 |

两者**可叠加**：Ekko Studio 把 Hermes 当作一个 Agent Family 接入；Hermes 内部又可有自己的 Bot roster 与群聊。

### 3.2 代表项目详述

#### OpenClaw（原 Clawdbot / Moltbot）
- **定位**：星标之王，本地运行，经单一 Gateway 连接 50+ 消息平台（WhatsApp、Telegram、Slack、Discord、iMessage、Signal 等）
- **语言**：TypeScript
- **GitHub**：待核实

#### Hermes Agent
- **定位**：功能最完整的"自进化 Agent"。核心差异是**闭环学习回路**：从经验创建技能、使用中自我优化、跨会话搜索、深度用户建模。支持 200+ 模型
- **GitHub**：待核实

#### NanoBot（HKUDS）
- **定位**：极简范本，约 4000 行 Python 实现 OpenClaw 90%+ 核心能力。原生支持 MCP，支持 Telegram、WhatsApp、Discord、Slack、钉钉、飞书、QQ 等多平台
- **GitHub**：待核实

#### AstrBot
- **定位**：国内多平台聊天机器人代表，AGPL-3.0，Python 3.12+
- **核心理念**：把**平台适配层与 Agent 能力层拆开**——平台负责消息进出，Agent 负责理解决策，插件/MCP/知识库提供能力
- **平台**：QQ、企业微信、微信公众号、飞书、钉钉、Telegram、Slack 等；社区 1000+ 插件
- **GitHub**：https://github.com/AstrBotDevs/AstrBot

#### LangBot
- **定位**：企业级 IM Bot 平台，强调生产环境安全隔离——沙箱与 Runtime 分离，插件容器崩溃不影响主容器
- **平台**：Discord、Telegram、Slack、LINE、KOOK、Matrix、QQ、微信、企业微信、飞书、钉钉等
- **GitHub**：https://github.com/langbot-app/LangBot

#### MemOS
- **定位**：长期记忆引擎，长期记忆 + 人格一致性 + 跨会话身份演进
- **GitHub**：https://github.com/MemTensor/MemOS

## 四、选型建议

| 需求 | 推荐 | 理由 |
|---|---|---|
| 个人助手，跑在 50+ 平台 | OpenClaw 或 NanoBot | 前者生态最大，后者极简可读 |
| 想要会"成长"的 Agent | Hermes Agent | 自动学技能、持久记忆、闭环学习 |
| 多平台 IM Bot，国内平台为主 | AstrBot 或 LangBot | 国内平台适配最全 |
| 多 Agent 协作 + 统一工作区 | Ekko Studio | 桌面 + Web，统一管理多运行时 |
| 学习 Agent 框架原理 | NanoBot | 约 4000 行，可读性最佳 |
| 记忆基础设施 | MemOS 或 Letta | 记忆分层与跨会话演进 |

## 五、对 deepseek-studio 的启示

1. **Ekko Studio 的聊天室模式**值得对标：工作区层群聊 + @提及路由 + 多运行时统一管理，正是 studio 想做多 Bot 协作的可借鉴形态。
2. **Hermes Bot Mode 的"一个 Bot = 一个 Profile"** 是极简而强大的原语：身份、记忆、技能、历史全部隔离，却共享同一个 Agent 内核。studio 已有 ModelEngine(web/api 双引擎) + AgentLoop，只需再加"持久化 Session 存储" + "Bot 身份注册表"即可长出 Bot 能力。
3. **Hermes 群聊的串行轮次设计**（同轮并发、轮间串行、后发言者可见前者）是防止多 Bot 群聊混乱的实用模式，可直接借鉴。
4. **studio 的独特优势**：上述开源项目多绑定单一模型提供商或仅网页版，均无 studio 的 ModelEngine(web/api) 双引擎抽象。Bot 挂 ApiEngine 可并行且规避网页版风控。
