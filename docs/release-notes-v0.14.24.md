# v0.14.24 发版说明

发布日期：2026-11-16（tag `v0.14.24`，自 `v0.14.23` 起 20 笔，其中动到运行时行为的 3 笔）

## 这版修了什么

### 1. 会话档案不再明文记录凭证（安全修复，`af426af`）

**现象**：登录取证日志里的 `[auth] resp-body …` 一行会把认证端点的响应体原文（截 200 字符）落盘。也就是说，**每次页面载入只要拦到 `/users/current` 一类的响应，就可能再写一份明文令牌进诊断日志**。

**修复**：

- 落盘前先做**敏感值掩码**：认证面响应体里命中敏感键名表（`token`／`access_token`／`refresh_token`／`api_key`／`secret`／`password`／`captcha`／`verify_code`／`authorization`／`cookie`，共 10 枚）的字符串值改写成 `<len=长度 sha16=摘要前16位>`；**不删行**——"这一跳有没有发生、返回的是不是同一枚值"仍然可读，值本身不可还原；
- 认证端点面内的**非 JSON 响应体与 JSON 原始值**（HTML 错误页、纯文本、裸串/数字）一律整串摘要，不给明文留旁路；
- **fail-closed**：形似 JSON 却解析失败的响应体，宁可只落一行 `<omitted: mask-failed, body not written>`，也不把原文带出去；
- 会话键名射程收窄：原来凡是键名含 `token|user|session|login|auth` 都会触发日志，把 `__session_page_size__`（页面状态）与 `__tea_session_id_*`（第三方分析会话号）也算成登录键，既吵又误导；现在只认凭证形（`token`／`device_id`／`did`／`password`／`secret`／`api_key`），站点真正的会话键 `userToken` 仍然命中。

**这一版的准确口径**：改动在注入层，CI 干净检出全量闸绿、单测 18 枚锁住行为（含 corrupt 走省略行、非 JSON 走整串摘要两条安全出口）。**装版生效与否需在本次升级后按三条核据现场复验**：`[auth] resp-body` 行仍在、行内值形为 `<len=… sha16=…>`、产物内 `omitted: mask-failed` 锚命中 ≥2 且明文串锚为 0。本版不预写"已在装版上验过"。

### 2. 预 OPEN 丢弃从"看不见"变成"按型可数"（取证面，`6199674`）

上一版新增的预 OPEN 有界队列，对三类"发完不管"的报文（`log`／`trace`／`integrity-alert`）在连接建立前排队；**续跑三类事件（`assistant-reply`／`stream-delta`／`finish-sentinel`）不排队、会被丢弃**，这是有意保留的损失面。本版的改动是把它**变成可数的**：丢弃发生时按型分列落一行汇总诊断，便于回答"那三分钟到底丢了几条什么"。零行为改动，只加计数与一行日志。

### 3. 删掉一处"永远不会走到"的兜底（契约修复，`3f208c2`）

工具调用转发处原有 `call.id || 随机生成` 的兜底。生产者恒填非空 id、类型也是必填，所以这分支今天走不到。留着它的代价不是性能，而是**契约陷阱**：将来若有人把 `id` 放开成可选、或新增不填 id 的生产者，这一层会**静默随机顶替**，导致 callId 级去重与回执关联无声失效、且不报错。现在删掉兜底，改由类型系统兜住——`id` 一旦放开，使用点与契约锁同时编译报错（本仓已用负控实证：放开后 tsc 报 10 处）。同时把去重两层的**重置口径写进码内注释**（callId 认领只在新用户回合清、签名集每条流开始清），防止后来者把"跨流同签名"误当重复而吞调用的结算出口。

## 已知未续（下版候选）

- **档案正文里的第三方凭证不在本版射程**：取证确认本机凭据未落进会话档案（0 处），但模型正文若引用过一次外部高熵串，仍会明文留存——掩码用户可见内容属产品语义判断，待出资人定；
- 预 OPEN 队列的溢出路径仍等自然复现（出现 `overflow` 行即算现场证据），不人为造窗口；
- 卡⑫ 的按型丢弃读数需在本版装版上现取（0.14.23 的产物里没有这枚计数器）；
- 沿用：设置面板显示登录态剩余有效期与临期提醒；dev 实例独立 `identifier`／独立 WebView2 档案目录（取证已证实 dev 与装版当前共用同一份 WebView2 档案，这是"掉登录"归因的污染源）；standalone 档位切换死锁的可见逃生门。

标准 NSIS 安装包升级，配置与登录档案跨版本保留（卸载默认不删应用数据）。升级后如果再见掉登录，日志里的 `[auth]` 行应能直接指出是哪一跳把会话弄丢的，且**行内不再有明文令牌**。
