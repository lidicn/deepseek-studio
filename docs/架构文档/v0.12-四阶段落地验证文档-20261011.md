## 四、Phase 4：崩溃恢复全场景验证

### 4.1 验证环境

- exe 路径：`E:\NAS\deepseek-studio\src-tauri\target\debug\deepseek-studio.exe`
- 日志路径：`~/.config/deepseek-studio/logs/`
- 崩溃日志：`~/.config/deepseek-studio/logs/crash.jsonl`

### 4.2 验证脚本

```powershell
# 1. 启动应用
Start-Process "E:\NAS\deepseek-studio\src-tauri\target\debug\deepseek-studio.exe"

# 2. 等待 /healthz 就绪
$ready = $false
for ($i=0; $i -lt 20; $i++) {
    try {
        $r = Invoke-WebRequest -Uri "http://127.0.0.1:8760/healthz" -TimeoutSec 1
        if ($r.StatusCode -eq 200) { $ready = $true; break }
    } catch {}
    Start-Sleep -Milliseconds 500
}
Write-Host "Healthz ready: $ready"

# 3. kill daemon 测试自动重启
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
    Where-Object { $_.CommandLine -like "*src/api/main.ts*" } |
    ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
Write-Host "Daemon killed, waiting for restart..."
Start-Sleep -Seconds 3

# 4. 检查是否重启
try {
    $r = Invoke-WebRequest -Uri "http://127.0.0.1:8760/healthz" -TimeoutSec 2
    Write-Host "Daemon restarted: $($r.StatusCode -eq 200)"
} catch {
    Write-Host "Daemon NOT restarted"
}
```

## 五、已知限制

1. **tray-icon feature warning**：Cargo.toml 中 `tray-icon` 作为 feature 传入会有 warning，但功能正常。
2. **自动更新端点**：tauri-plugin-updater 已集成，但 endpoints 配置为占位 URL（https://example.com/updates/latest.json），实际部署时需替换为真实更新服务器。
3. **externalBin**：tauri.conf.json 中未配置 externalBin，Phase 1 默认走 DevTsx（cmd /c npx tsx），后续产出 Node 单文件打包后启用。
4. **崩溃日志路径**：Windows 上位于 `%APPDATA%\deepseek-studio\logs\crash.jsonl`（非 `~/.config/`）。
