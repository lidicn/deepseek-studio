# studio 版本号对齐表（2026-10-17 立）

> 目的：终结「四套编号并行」——package.json=0.4.0 / 版本路线图=v0.10 / 交接班=v0.31-v0.32 / 内核计划=M0-M3。
> 裁决：采用**双轨编号**，两轨互不换算，各自文档只引用本轨编号。

## 1. 为什么是双轨而不是合并

两条线的推进单位根本不同：
- **A 线（内核归位）**推进单位是「里程碑 M0–M3」——它们是对**同一批代码**的结构性改造，不是产品增量。硬塞进 vN 会误导（M2 做完产品功能没增加，但地基换了）。
- **B 线（Bot 平台）**推进单位是「产品版本 vN」——每一版对用户可见。

强行合并 = 每次内核改动都要决定「这是 v0.33 还是 v0.32.1」，纯浪费。

## 3. package.json 的 version 字段怎么办

当前 = `0.4.0`，与上述两轨都对不上。

**处置**：`version` 只作为 npm 打包/依赖解析用，**不作为产品版本对外宣称**。建议改为反映「仓库形态」的语义：

```json
"version": "0.4.0"
```

**保持不变**，但在文件头加一行注释语义（package.json 不支持注释，故记于此表）：

> `0.4.0` = 宿主地基版本（v0.1–v0.5 内核奠基 + v0.6 MAIN-world 拦截 时代的打包版本）。产品版本以轨 B 为准，内核以轨 A 为准。

**不改成 0.32**：因为 Bot 平台只是这个仓库的一条线，把仓库版本等同于 Bot 版本，会把 A 线锁死在 B 线的节奏上——正是本次要拆掉的耦合。
