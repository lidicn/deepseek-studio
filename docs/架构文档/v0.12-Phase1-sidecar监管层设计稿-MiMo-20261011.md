## 2 · DCD 四条修正条件 → 满足方式（验收 9）

| # | DCD 原文要求 | 本设计如何满足 | 验证测试 |
|---|---|---|---|
| 1 | 「sidecar.rs 必须持有 Child 句柄，try_wait() 轮询或 wait() 异步监听 exit；⛔ 不得沿用 spawn 完就丢」 | `SidecarSupervisor.child: Option<Box<dyn ProcessHandle>>` 全程持有；退出判定**只**来自 `ProcessHandle::try_wait()` 返回值，禁止 pid 探活判定崩溃。`main.rs` 里 `tauri::async_runtime::spawn(async move { ...spawn... })` 整块删除（见 §5 diff `-` 行） | T3、T4 |
| 2 | 「健康检查打 /healthz：GET http://127.0.0.1:8760/healthz，server.ts:215，免鉴权」 | `HttpHealthProbe` 手写最小 HTTP GET（`GET /healthz HTTP/1.1`），只认状态行 `200`；常量 `HEALTH_URL` 唯一来源；不发鉴权头（该端点在 server.ts 中位于 `auth.authenticate` 之前，免鉴权） | T1、T11、T12 |
| 3 | 「孤儿防护落在 Node 侧：src/api/main.ts 加父进程 PID 监控（ppid 变化或轮询）→ self-exit，约 30 行，必须写」 | §8 给出可粘贴 30 行块：2s 轮询 `process.ppid` 变化 **或** 父 PID 探活失败 → `process.exit(0)`。Windows ppid 陈旧问题用 `process.kill(pid,0)` 兜住 | S1–S4 |
| 4 | 「重启预算写死：崩溃后延迟 2s 重启，最多 5 次；超预算则停止重启并在窗口提示（⛔ 不得无限重启）」 | 常量 `RESTART_DELAY = 2s`、`MAX_RESTARTS = 5`；`Crashed → Restarting(n) → Spawning` 的推进严格由 `restarts` 计数器限流，`restarts == 5` 时第 6 次崩溃进 `GaveUp` 终态 + `Effect::GaveUp` → Tauri 事件 → 窗口提示 | T5、T6、T7 |

**计数口径（写死，消除歧义）**：`restarts` = 已执行的重启次数。崩溃发生时：`restarts < 5` → 重启（`restarts += 1`）；`restarts == 5` → `GaveUp`。即最多 6 次拉起、5 次重启，与「连续崩溃 >5 次 → 停止重启」（row 6）严格一致。

## 3 · 状态机（验收 6）

### 3.1 图

```
                    ┌──────────────────────────────────────────────┐
                    │  Spawning ──(/healthz 200)──▶ Running        │
                    │      │                          │            │
                    │      │ 健康超时/SpawnFailed/     │ try_wait() │
                    │      │ 启动期退出                │ = Some     │
                    │      ▼                          ▼            │
                    │   Crashed(ExitInfo) ◀───────────┘            │
                    │      │                                       │
                    │      │ restarts < 5                          │
                    │      ▼                                       │
                    │   Restarting(n=1..5) ──(2s 冷却)──▶ Spawning │
                    │      │                                       │
                    │      │ restarts == 5（即第 6 次崩溃）         │
                    │      ▼                                       │
                    │   GaveUp  ◀═══ ⛔ 终态：不再自动重启，窗口提示 │
                    └──────────────────────────────────────────────┘

  正交退出路径（不计预算、不算崩溃）：
    Running ──ShutdownRequested──▶ shutdown() ──▶ Stopped
    Spawning/Restarting ──ShutdownRequested──▶ shutdown() ──▶ Stopped
```

### 3.2 状态定义

```rust
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub enum SidecarState {
    Spawning,             // 子进程已创建，/healthz 尚未通过
    Running,              // /healthz 200，就绪
    Crashed(ExitInfo),    // 非预期退出 / 启动失败 / 健康超时
    Restarting(u8),       // 第 n 次重启冷却中，n ∈ 1..=5
    GaveUp,               // 超预算终态（⛔ 不得自动重启）
    Stopped,              // 优雅退出终态（正交路径）
}
```

> 说明：DCD 要求的链路是 `spawning → running → crashed → restarting(1..5) → gave-up`，五个状态一个不少。额外的 `Stopped` 只承载 row 4 的正常关闭路径——把它塞进 `GaveUp` 会污染「超预算」语义，故单列（见 §14 决策 D6）。

### 3.3 转移表

| 当前 | 输入 `LifecycleEvent` | 条件 | 下一状态 | 副作用 `Effect` |
|---|---|---|---|---|
| Spawning | `HealthOk` | — | **Running** | `Notify(Running)` |
| Spawning | `HealthTimeout` | restarts<5 | **Restarting(restarts+1)** | `WriteCrashLog`、`ScheduleRestart{2s}`、`Notify` |
| Spawning | `HealthTimeout` | restarts==5 | **GaveUp** | `WriteCrashLog`、`GaveUp{6}` |
| Spawning | `SpawnFailed(s)` | 同上两分支 | Restarting / GaveUp | 同上 |
| Spawning | `Exited(info)` | 同上两分支 | Restarting / GaveUp | 同上 |
| Running | `Exited(info)` | `!shutdown_requested` | **Crashed(info)** → 立即走重启分支 | `WriteCrashLog` |
| Running | `Exited(info)` | `shutdown_requested` | **Stopped** | `Notify(Stopped)`（不写 crash、不动预算） |
| Restarting(n) | `RestartDue` | now ≥ restart_at | **Spawning** | `Spawn` |
| 任意 | `ShutdownRequested` | — | 交 `shutdown()` → **Stopped** | 见 §10 |
| GaveUp | `ResetBudget`（人工） | — | Spawning | `Spawn`（默认不接 UI，见 §14 D7） |

### 3.4 不变量（代码里断言 + 测试锁死）

- **I1** `self.child.is_some()` 在 `Running`/`Spawning` 期间恒成立；退出只由 `try_wait()` 判定。
- **I2** `Spawning → Running` 的唯一通道是 `/healthz` 200；TCP 端口通 ≠ 就绪。
- **I3** `restarts` 单调不减且 `≤ 5`；`GaveUp` 后不存在任何 `Effect::Spawn`。
- **I4** 每次进入 `Crashed` 都恰好产生 1 条 `crash.jsonl` 记录。
- **I5** `ShutdownRequested` 之后不产生 `WriteCrashLog`（正常关闭不是崩溃）。

### 4.3 状态机核心（本轮唯一写满的逻辑，纯函数、无副作用）

```rust
/// 状态转移纯函数：输入当前状态 + 事件 + 预算计数，输出新状态与副作用序列。
/// 副作用由 SidecarSupervisor 逐条执行（写日志/发事件/睡 2s/拉进程），
/// 因此本函数可 100% 单测覆盖，不需要真进程。
pub fn transition(state: &SidecarState, ev: LifecycleEvent, restarts: u8) -> Transition {
    use LifecycleEvent as E;
    use SidecarState as S;

    // 关停优先：任何状态收到 ShutdownRequested 都收敛到 Stopped（不计预算）
    if matches!(ev, E::ShutdownRequested) {
        return Transition { next: S::Stopped, restarts, effects: vec![Effect::Notify(S::Stopped)] };
    }

    // 崩溃路径统一入口：受预算约束的「重启 or 放弃」
    fn crash_path(info: ExitInfo, restarts: u8) -> Transition {
        let mut effects = vec![Effect::WriteCrashLog(info.clone())];
        if restarts < MAX_RESTARTS {
            let attempt = restarts + 1;
            effects.push(Effect::ScheduleRestart { attempt, delay: RESTART_DELAY });
            effects.push(Effect::Notify(S::Restarting(attempt)));
            Transition { next: S::Restarting(attempt), restarts: attempt, effects }
        } else {
            effects.push(Effect::GaveUp { crashes: (restarts as u16 + 1) as u8 });
            Transition { next: S::GaveUp, restarts, effects }
        }
    }

    match (state, ev) {
        (S::Spawning, E::HealthOk) => Transition {
            next: S::Running, restarts, effects: vec![Effect::Notify(S::Running)],
        },
        (S::Spawning, E::HealthTimeout) =>
            crash_path(ExitInfo { code: None, kind: ExitKind::HealthTimeout, at_ms: now_ms(), stderr_tail: None }, restarts),
        (S::Spawning, E::SpawnFailed(s)) =>
            crash_path(ExitInfo { code: None, kind: ExitKind::SpawnFailed, at_ms: now_ms(), stderr_tail: Some(s) }, restarts),
        (S::Spawning, E::Exited(info)) => crash_path(info, restarts),

        (S::Running, E::Exited(mut info)) => {
            // I5：关停引发的退出不算崩溃（budget 不动、crash.jsonl 不写）
            info.kind = ExitKind::Exited;
            Transition { next: S::Crashed(info.clone()), restarts,
                         effects: vec![Effect::Notify(S::Crashed(info))] }
                .and_then_crash(restarts)   // 语法糖：立刻套用 crash_path 的预算分支
        }

        (S::Restarting(n), E::RestartDue) => Transition {
            next: S::Spawning, restarts, effects: vec![Effect::Spawn, Effect::Notify(S::Spawning)],
        },

        // 其余组合为非法转移：保持原状并上报（防御式，不让状态机进未知分支）
        _ => Transition { next: state.clone(), restarts, effects: vec![] },
    }
}
```

> 骨架声明：`and_then_crash` 是设计稿里的语义糖，实际实现为 `Running→Exited` 直接调用 `crash_path`（见 §15）。`now_ms()` 为 `SystemTime::now()` 毫秒数。

```rust
        if self.probe.probe(self.cfg.probe_timeout).ok            { self.apply(HealthOk); }
        else if now >= self.spawned_at + self.cfg.startup_timeout { self.apply(HealthTimeout); } // 验收 7
        // ⛔ 其它情况继续等，绝不因「慢」而判死
    }
    Running => {
        if let Some(info) = self.poll_exit() { self.apply(LifecycleEvent::Exited(info)); }
    }
    Restarting(_) => {
        if now >= self.restart_at { self.apply(LifecycleEvent::RestartDue); }
    }
    Crashed(_) | GaveUp | Stopped => return TickOutcome::Terminal / Continue,
}
```

## 8 · `src/api/main.ts` 孤儿防护（验收 5，~30 行，可直接粘贴）

```ts
// ── v0.12 Phase 1：孤儿防护（DCD 修正条件 3）──────────────────────────────
// 父进程（Tauri 主进程）消失 → self-exit，不留孤儿 Node。
// POSIX：父死后 process.ppid 变为 1（变化可判）；
// Windows：ppid 是启动时记录的陈旧值（父死后不变），必须再做 liveness 探活
//         （process.kill(pid, 0)：ESRCH=已消失，EPERM=存在但无权限）。
export type GuardDeps = {
  getPpid: () => number;
  alive: (pid: number) => boolean;
  exit: (code: number) => void;
  setInterval: typeof setInterval;
  clearInterval: typeof clearInterval;
  on: (sig: 'SIGTERM' | 'SIGBREAK', fn: () => void) => void;
  log?: (msg: string) => void;
};
export function installOrphanGuard(d: GuardDeps, intervalMs = 2_000): () => void {
  const ppid0 = d.getPpid();
  const timer = d.setInterval(() => {
    if (d.getPpid() !== ppid0 || !d.alive(ppid0)) {
      d.log?.(`[deepseek-studio] 父进程 ${ppid0} 消失，孤儿防护触发 self-exit`);
      d.exit(0);
    }
  }, intervalMs);
  const stop = () => d.clearInterval(timer);
  // 优雅退出：POSIX SIGTERM / Windows CTRL_BREAK(SIGBREAK)（验收 8 的 daemon 侧配合）
  for (const sig of ['SIGTERM', 'SIGBREAK'] as const) {
    d.on(sig, () => { stop(); d.exit(0); });
  }
  return stop;
}
installOrphanGuard({
  getPpid: () => process.ppid,
  alive: (pid) => { try { process.kill(pid, 0); return true; }
                    catch (e) { return (e as NodeJS.ErrnoException).code === 'EPERM'; } },
  exit: (c) => process.exit(c),
  setInterval, clearInterval,
  on: (sig, fn) => { process.on(sig, fn); },
  log: (m) => console.warn(m),
});
// ── 孤儿防护结束 ────────────────────────────────────────────────────────
```

- 轮询间隔 2s：row 5 无硬时限，2s 内必然发现；配合 Rust 侧 Job Object（父亡即杀树）基本即时。
- `EPERM` 判「存活」：避免权限边界误杀（边界用例 S4）。
- 退出码 `0`：孤儿退出属预期生命周期事件，不计崩溃、不触发任何重启。
- PID 复用：Windows 陈旧 ppid + 复用可能误判存活 → 2s 周期把误判窗口压到最小；彻底解法需父进程 start-time 比对，超出「约 30 行」预算（见 §14 D11）。

## 9 · 健康检查与超时（验收 7）

| 项 | 值 | 语义 |
|---|---|---|
| 端点 | `GET http://127.0.0.1:8760/healthz` | 免鉴权（server.ts 中位于 `auth.authenticate` 之前），200 + `{"ok":true}` |
| 探活方式 | 手写最小 HTTP GET over `TcpStream` | `connect_timeout=200ms`、`read_timeout=200ms`；只判状态行 `HTTP/1.1 200` |
| 探活节奏 | 每 `EXIT_POLL_INTERVAL = 100ms` 一次（Spawning 阶段） | localhost 端点 <5ms 响应，200ms 上限充裕 |
| **启动超时** | **`STARTUP_HEALTH_TIMEOUT = 10s`** | 从 `Spawned` 起算，10s 内 `/healthz` 未 200 → `HealthTimeout` → 记一次崩溃 → 走重启预算 |
| 稳态探活 | **不巡检** | 稳态存活只认 `try_wait()`（I1）。理由：巡检会把「慢/忙」误判成死，制造假崩溃 |
| 失败语义 | fail-closed on readiness | 探活失败绝不放行 `Running`；10s 是硬上限，无退避、无无限等待 |

**为什么是 10s**（而非 §1 旧代码的 5s TCP 等待）：`npx + tsx` 冷启动要解析 npx 缓存、加载 tsx loader、编译 TS，Windows 上常见 2~6s；5s 会把正常冷启动误判成失败并白白消耗重启预算。10s 覆盖 P99 冷启动且仍是有限预算（= 拉起失败必须在一个确定时刻暴露，验收 7 的要求）。

**为什么探活超时只要 200ms**：探的是回环地址的静态端点；200ms 连 Windows Defender 首次扫描都够。且必须 `probe_timeout < exit_poll × 2`，否则单次探活会拖慢 `try_wait()` 轮询，拉长 row 2 的检测延迟。

## 10 · 优雅关闭时序（验收 8 / 矩阵 row 4）

```
T0   窗口 CloseRequested ──▶ api.prevent_close()          （UI 暂不销毁）
T0+  supervisor.request_shutdown()（置 shutdown_requested=true，I5 生效）
T0+  imp::send_sigterm / send_ctrl_break(root_pid)        POSIX SIGTERM / Win CTRL_BREAK
T0+  每 100ms child.try_wait()
     ├─ Some(status) 且 elapsed < 5s ──▶ graceful=true, forced=false ─▶ Stopped
     └─ elapsed ≥ 5s 仍未退出 ────────────────────────────────────────┐
T5s  imp::kill_tree(root_pid)                                        │
       POSIX: SIGKILL 进程组                                        │
       Win  : TerminateJobObject(job) → 失败退化 taskkill /PID p /T /F│
T5s+ 再 try_wait() 收割 ──▶ graceful=false, forced=true ─▶ Stopped ◀┘
T末  window.destroy() 放行关闭；Tauri 退出（Job: KILL_ON_JOB_CLOSE 兜底清树）
```

```rust
impl SidecarSupervisor {
    pub fn shutdown(&mut self) -> ShutdownOutcome {
        self.shutdown_requested = true;                 // I5：此后退出不计预算、不写 crash
        let t0 = Instant::now();
        let Some(child) = self.child.as_mut() else {
            return ShutdownOutcome { graceful: true, forced: false, elapsed_ms: 0 };
        };
        let _ = child.signal_graceful();                // SIGTERM / CTRL_BREAK
        while t0.elapsed() < self.cfg.graceful_timeout {           // 5s
            if matches!(child.try_wait(), Ok(Some(_))) {
                self.state = SidecarState::Stopped;     // row 4 正常路径
                return ShutdownOutcome { graceful: true, forced: false,
                                         elapsed_ms: t0.elapsed().as_millis() };
            }
            std::thread::sleep(Duration::from_millis(100));
        }
        let _ = child.kill_tree();                      // 超时强杀（含进程树）
        let _ = child.try_wait();                       // 收割，避免僵尸
        self.state = SidecarState::Stopped;
        ShutdownOutcome { graceful: false, forced: true, elapsed_ms: t0.elapsed().as_millis() }
    }
}
```

| 保证 | 实现 |
|---|---|
| 5s 内优雅退出 | `graceful_timeout = 5s` 硬上限 + daemon 侧 `SIGTERM/SIGBREAK → exit(0)`（§8） |
| 超时必强杀 | `kill_tree`：Windows Job Object 主路径、`taskkill /T /F` 备路径；POSIX `SIGKILL` 进程组 |
| 不留孤儿 | Job Object `KILL_ON_JOB_CLOSE` + Node ppid 守护（三道防线见 §13） |
| 关闭 ≠ 崩溃 | `shutdown_requested` 置位后 `Exited` → `Stopped`，`restarts` 不变、`crash.jsonl` 不写（T13） |

```ts
import { test } from 'node:test';
import assert from 'node:assert/strict';

type Tick = () => void;
function fakeDeps(over: Partial<Record<string, unknown>> = {}) {
  let tick: Tick | undefined;
  const calls = { exits: [] as number[], cleared: 0, handlers: new Map<string, () => void>() };
  const deps = {
    getPpid: () => 100,
    alive: () => true,
    exit: (c: number) => calls.exits.push(c),
    setInterval: (fn: Tick) => { tick = fn; return 1 as unknown as NodeJS.Timeout; },
    clearInterval: () => { calls.cleared += 1; },
    on: (sig: string, fn: () => void) => { calls.handlers.set(sig, fn); },
    ...over,
  };
  return { deps, fire: () => tick?.(), calls };
}

test('S1 row5: ppid 变化触发 self-exit', async () => {
  const { installOrphanGuard } = await import('./main');
  const { deps, fire, calls } = fakeDeps({ getPpid: (() => { let n = 0; return () => (n++ === 0 ? 100 : 1) as number; })() });
  installOrphanGuard(deps as never);
  fire();
  assert.deepEqual(calls.exits, [0], '父 PID 变化必须 exit(0)');
});

test('S2 Windows 陈旧 ppid：alive=false 触发 self-exit', async () => {
  const { installOrphanGuard } = await import('./main');
  const { deps, fire, calls } = fakeDeps({ alive: () => false });
  installOrphanGuard(deps as never);
  fire();
  assert.deepEqual(calls.exits, [0], 'ppid 未变但父已死（ESRCH）也必须退出');
});

test('S3 边界：父存活时 3 个周期内不退出', async () => {
  const { installOrphanGuard } = await import('./main');
  const { deps, fire, calls } = fakeDeps();
  installOrphanGuard(deps as never);
  fire(); fire(); fire();
  assert.deepEqual(calls.exits, [], '父存活不得退出');
});

test('S4 边界：EPERM 视为存活（权限不足 ≠ 父消失）', async () => {
  const { installOrphanGuard } = await import('./main');
  const err = Object.assign(new Error('EPERM'), { code: 'EPERM' });
  const { deps, fire, calls } = fakeDeps({ alive: () => { throw err; } }); // 由实现映射 EPERM→true
  installOrphanGuard(deps as never, 2_000);
  fire();
  assert.deepEqual(calls.exits, [], 'EPERM 不得触发退出');

test('S5 row4: SIGTERM/SIGBREAK → 优雅退出并清理定时器', async () => {
```

## 14 · 关键设计决策（§7 要求）

**D1 数据结构与索引**：状态用枚举而非字符串 + 查表；预算用单计数器 `restarts: u8` 而非环形缓冲/时间窗（DCD 只要求「最多 5 次」，累计口径最贴文义）。崩溃记录用 `crash.jsonl` 追加式（可 `Get-Content -Tail`，天然索引=时间序），不做 DB/索引——本地单机、量级 <1e3/天。`SidecarState::Crashed(ExitInfo)` 直接携带退出信息，避免状态与日志双写不一致。

**D2 失败 / 降级语义**

| 场景 | 语义 | 理由 |
|---|---|---|

```rust
        Spawning => {
            if self.child.is_none() { self.spawn()?; }
```
