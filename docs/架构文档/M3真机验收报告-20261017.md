## 二、V1 环境确认

- `/healthz` = `{"ok":true}`。
- `engine.health()` = `{ok:true}`；**但必须加真页面校验**：无页面时 `chat-read` 走 Node rehydrate 兜底，返回 `{ok:true, snapshot:{...}}`，会骗过 health()。脚本里改判 `data.messages` 是数组才算在线。
- 发「请只回复两个字：你好」→ 真实回复 `你好`。

**发现 F1**：`engine.health()` 在无页面时假阳性。已在 `tools/metrics/lib/live-client.ts` 的 `isRealPageRead()` 里修。
**发现 F2**：首轮冷启动整轮 124s（撞 120s 看门狗，completion=truncated）。页面热身后恢复正常（~5s/轮）。

## 三、V2 nudgeRate（50 轮）

脚本：`tools/metrics/live-nudge-rate.ts --rounds=50 --timeout=60000`
原始数据：`docs/PM/progress/seat5-v2-raw.jsonl`

| 指标 | 值 |
|---|---|
| 总轮数 | 50 |
| complete | 46 |
| truncated | 4（第 17、28、39、50 轮） |
| disconnected | 0 |
| **nudgeRate** | **0.08（8%）** |
| 正常轮耗时 | ~4.7–6.3s |

- 模型每轮一个字回答（contentLen=1），无工具调用。
- 4 次 truncated 都 ~60s 撞看门狗，且 contentLen=1：**模型其实回了，但稳定性判定（连续 2 次读到相同末条）没收敛**。约每 11 轮一次，疑似 DeepSeek 偶发慢响应/流式尾巴，非断连。
- 0 disconnected = 页面连接稳定。

## 四、V3 流式 delta

脚本：`tools/metrics/live-delta.ts`，发「写一首关于秋天的短诗（~100 字）」。

| 指标 | 值 |
|---|---|
| completion | complete |
| onDelta 次数 | **2** |
| 累计 delta 字符 | 165 |
| 首 token 延迟 | 2498ms |
| 整轮耗时 | 7229ms |

**未达「onDelta ≥ 10 次」的验收线。** 增量文本确实收到了（2 块 ≈ 最终 142 字），但粒度是轮询（`pollIntervalMs=1500`）不是逐 token。

**发现 F3**：当前 WebEngine 靠宿主轮询 chat-read 差异来模拟 delta，不是把 page 端 SSE 流直接转发成 onDelta。要做到真·逐 token，需让 interceptor 把 DeepSeek 的流式 SSE chunk 直接推给 onDelta。

## 五、V4 工具回合

`POST /v1/agent/send`，让模型调 `shell.exec echo hello-from-seat5`。

- 耗时 11.8s，ok=true。
- 自驱全链路：send → shell.exec（退出码 0，stdout=`hello-from-seat5`，cwd=`E:/NAS`）→ 结果回填 → 模型引用 stdout 作答。
- 全程无人工 nudge、无格式纠错重发。shell.exec 在 auto 档 + 工作区内自动放行。
