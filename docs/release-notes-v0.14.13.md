本版本主要修三件事，另有两处加固。

一、调用外部工具（MCP）不再"发出去就没声"。此前模型发出的工具调用，如果标签写法与 Studio 约定的略有差异（例如少一个下划线），这个请求不会被执行、原样留在对话里，看起来像是工具坏了；现在这类写法会被识别并执行，同一参数即使写成两种样子也只执行一次。同时，服务器自己声明的工作目录现在会被纳入"是否越出工作区"的判定：配在工作区之外的目录会明确提示，而不是先跑了再说。

二、审批改用独立窗口，并把"始终允许"用在了正确的粒度上。此前同一对话里选择了"始终允许"，下一次同类操作仍会重复询问；现在"始终允许"覆盖整个对话，"仅本次允许"只覆盖这一次。完全放开档对这类允许类操作不再逐次询问。审批究竟发生在独立窗口、网页内弹窗，还是窗口不可用时被拒绝，都会被记录进日志，事后可以逐条查。需要说明的是：独立窗口这一形态我们还没有在装版上逐项手工验证过，如果你遇到窗口没有出现、或者操作被直接拒绝的情况，请把当时的操作内容发给我们，这属于要逐个核实的情况，不作"再也不会弹"的承诺。

三、工具跑得太多轮、或者模型回复不完整时，现在会给出原因。以前这两种情况会静默中断，只留下一个没有正文的回复；现在界面会说明发生了什么，并记录有多少条工具结果已经执行、但还没送回模型。

四、本地服务启动失败不再悄悄给出一个不可用的地址。以前在极端情况下，程序会认为监听成功却交出一个连不上的地址，调用方随即失败；现在拿不到监听地址会直接报错并说明原因。

五、发布链加固。持续集成现在会额外做一次 Rust 侧代码的编译检查；发布页正文会与随版本发布的说明文件逐字比对，缺失或不一致时构建直接失败，不会带着空正文或残缺正文发出去；签名密钥在构建开始前先校验一次。本次发布页正文即为完整说明，不再是之前那种几十字的残缺内容。

以上几条都有自动化测试覆盖，但这一版还没有在装版上逐项手工走过；如果你的实测与上面的描述不符，请把当时的操作发给我们，我们逐个核实。

建议从 0.14.12 或更早版本直接升级。
