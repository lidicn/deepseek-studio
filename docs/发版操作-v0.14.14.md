# v0.14.14 发版操作单（维护者用，不进发布页正文）

## 前置事实（本次为什么改发 0.14.14，不发 0.14.13）

- `v0.14.13` 的 Release run `42724494390` 红在 step 9「Fetch missing tauri packaging tools」，日志末行原文：
  `NSIS archive extracted but marker still missing: …\tauri\NSIS\Bin\makensis.exe`
  ⇒ 下载与解压都成功，失败在**解压落点与构建器期望的校验路径不一致**。
- 该分支此前**从未被执行过**：step 8 的 `actions/cache@v4`（`key=tauri-tools-v1-nsis3.11-wix314`）命中时工具已在位，step 9 直接走 present 分支。缓存未命中才暴露死路。
- ⇒ **重跑 `42724494390` 用的是 tag 里那份未修复的 workflow，必然同样红**；修复在 master（`c92b3f4`），**只有新 tag 才带得出去**。
- `v0.14.13` tag 保留不删、不重打（先例：0.14.10 弃用合并为 0.14.11）。


## 发布页正文

- 正文文件：`docs/release-notes-v0.14.14.md`，**必须先于 tag 入库**（workflow L312-322 是 fail-closed：文件不存在或纯空白 ⇒ 整条 release job 红）。
- 文件名由 tag 动态推导（L278 / L318 / L333 / L370 / L429 全部用 `$tag` 或 `github.ref_name`），**不需要改 workflow 里任何路径**。
- 正文只写用户可见行为；未在安装版上逐项手工验证的，必须写明「不作承诺、请把现场发我们」。
- `latest.json` 的 `notes` 是另一条链：剥 markdown → 截 500 字内最近「。」→ 应用内升级弹窗显示的是这份截断纯文本，与网页正文分别验收。

## 打 tag 前四查

```
git ls-tree <tag目标commit> docs/release-notes-v0.14.14.md      # 在树里
npm run typecheck                                                # 0
npm run gate                                                     # 绿，两行与预期逐位同
git tag -l v0.14.14                                              # 空＝未占用
```

annotated tag：`git tag -a v0.14.14 -m "<不带因果陈述的说明>"`；tag 注释只作备份，工作流会 PATCH 正文并逐字校验。

## CI 与草稿

1. 三条 job：`gate` ×2、`cargo-check` ×2、`release` ×1。`release` 最慢（Rust 编译＋打包＋签名＋上传）。
2. **报数必须带时长与缓存命中态**；`cargo-check` 的 step 日志匿名取不到命中态时只报时长。
3. `release` 绿后才会有草稿（fail-closed：构建失败时页面上没有 Publish 按钮）。
4. 草稿核对五件：资产 5 枚（`.exe`／`.exe.sig`／`.msi`／`.msi.sig`／`latest.json`）全 200、正文与文件逐字等值、`draft=true`、`tag=v0.14.14`、三向版本一致。

## Publish（用户的网页动作）

Releases → `v0.14.14 (Draft)` → Edit → 确认正文完整 → **勾上「Set as the latest release」** → Publish。
不勾 Latest ⇒ `releases/latest` 指针不推进 ⇒ 客户端收不到更新提示（已两次踩坑）。

## 发布后

- 查 `on: release` 的公开链路闸结论；若失败会把正式版打回 draft、latest 指针离开。
- 装新版前先退出旧实例（旧实例占 `127.0.0.1:8760`，两装并存新实例起不来）。
- 新版上补做真机取证：独立审批窗口首弹、`td05_*` 四枚 Rust 测试（端口空了才能跑）、MCP 调用重测、空白气泡与空气泡两条显示面。
