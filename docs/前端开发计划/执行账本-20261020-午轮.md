## 四、X3 · 主题链路闭环 + 孤儿模块处置（Codex 接手）

### 4.1 发现的两个真缺口（比清理本身重要）

**缺口 1：design tokens 从未生效（P0）**

`agent.css` 原来把 `--studio-*` 定义为 `var(--wb-bg-0, #0f1115)` 形式，而全仓搜
`--wb-[a-z0-9-]+\s*:` **只命中一条** `--wb-radius: 10px`。即 `--wb-bg-0` / `--wb-text-0` /
`--wb-border` / `--wb-primary` 被引用但**从来没有任何定义处**。

根因：唯一应该写入 token 的 `applyWorkbenchTheme`（`workbench-theme.ts`），唯一调用方是
`workbench-app.ts`，而 `workbench-app.ts` 自身 **0 调用方** → 该函数从未执行。

后果：`design-tokens.ts` 的 `color.light` / `color.dark` 两套完整配色是死代码，
整个工作台实际跑在 CSS 硬编码 fallback 上。改 token 对界面零影响。

**缺口 2：宿主主题适配器也是孤儿**

`host-theme-adapter.ts`（计划 §7.4，C2 交付）同样 0 调用方、0 测试。
它与 `workbench-theme` 职责互补却一直没接上：一个探测该用什么主题，一个把主题写成 CSS 变量。

### 4.2 主题闭环（新做，非清理）

新增 `src/ui/workbench/theme-toggle.ts`，把两半接起来：
- 默认浅色；无用户选择时按 `host-theme-adapter` 探测（宿主 `data-theme` → `prefers-color-scheme` → light）
- 点顶栏 🌗 切深色，写 `localStorage['ds-studio-theme']`，下次启动沿用
- 用户显式选过后立即退订 `matchMedia`，不再跟随系统
- `localStorage` 读写抛错（隐私模式/存储被禁）时降级为"仅本次会话生效"，不抛到调用方

**踩过的坑（已修，测试锁定）**：第一版无条件写 `documentElement.dataset.theme`，导致
"跟随系统"失效——`host-theme-adapter.getTheme()` 第 1 优先级就是读 `data-theme`，
于是它读到自己刚写的值，系统切深色永远透传不进来。

修正后规则：

| 场景 | 写 `data-theme` | 写 CSS 变量 |
| --- | --- | --- |
| 用户未选择、跟随系统 | 否 | 是 |
| 用户显式选择（点击 / `set()`） | 是 | 是 |
| 启动时发现上次选过 | 是 | 是 |

`data-theme` 语义收紧为"用户显式选择的标记"，不再当作通用主题状态。

**CSS 侧**：`agent.css` 的 `--studio-*` 从"引用不存在的 `--wb-*`"改为与 token 逐值一致的静态兜底
（`:root` 浅色 + `:root[data-theme="dark"]` 深色）。JS 未执行或失败时界面仍是可读浅色，不白屏/黑屏。
