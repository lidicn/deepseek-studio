# 端口冲突处置（2026-10-20 · W9）

## 结论：EADDRINUSE 明确报错，**不做静默换端口**

### 现象与修复前

8760（或 config.json 指定端口）被占用时，Node sidecar 的 HTTP server `listen` 抛
`EADDRINUSE`。修复前 `server.ts` 仅 `server.once('error', reject)`，把原始错误向上抛，
Tauri 侧直接退出，用户只看到「白屏 + 无任何提示」，不知道是端口被占、占的是哪个、去哪改。

### 修复后行为（server.ts + main.ts）

1. `src/api/server.ts` `start()` 识别 `EADDRINUSE`，把原始 err 转成结构化错误：
   - `code='EADDRINUSE'`，附 `eaddrHost` / `eaddrPort`；
   - 文案含**端口号、当前 host**，并明确「不自动换端口」。
2. `src/api/main.ts` 在 `await host.start()` 处捕获 `EADDRINUSE`：
   - 打印 `当前配置 host=… port=…`；
   - 打印 **config.json 绝对路径**（`~/.config/deepseek-studio/config.json`），提示改其中
     `port`，或先关闭占用该端口的进程；
   - `process.exit(2)`（非 0）。
3. `src-tauri/src/main.rs` `workbench_url()` 与 `load_studio_chat_config_script()` 都从**同一份
   config.json** 读 host/port（W1 已做，W9 复核未改），保证「用户改了 port，工作台窗口与页端
   wsUrl 跟得上」。

## 为什么不做自动换端口

核心约束：**main.rs 与页端使用的 wsUrl 来自 config.json，sidecar 自己换端口不会回写、不会通知 Tauri。**

- `main.rs` `load_studio_chat_config_script()` 读 config.json 的 host/port，拼出
  `ws://{host}:{port}/agent-ws` 注入页面；`workbench_url()` 同样读这份文件拼
  `http://{host}:{port}/agent`。
- 若 sidecar 在 listen 失败后私自换到「下一个可用端口」（如 8761），但 config.json 仍写 8760，
  则：页端按注入的 8760 连 WS 握手失败、工作台窗口打开的 `http://…:8760/agent` 也是死地址。
- 结果是「服务其实起来了，但用户和页端都连不上」——**静默失败比明确失败更糟**：用户看不到
  报错，只会反复重启，且错误被掩盖。因此 W9 选择明确失败、非 0 退出，把处置权交还用户。

## 要做「自动换端口」必须先解决的前置

1. **端口协商机制（main.rs ↔ sidecar 双向）**：sidecar 选定新端口后，必须有一条回写通道
   （写回 config.json，或经 IPC/事件把实际 host:port 通知 Tauri 主进程），main.rs 拿到实际端口
   后再注入页端 wsUrl、再开工作台窗口，消除「config.json 与实际监听不一致」。
2. **一致性顺序**：先协商出最终端口 → 再写 config.json → 再注入页端 → 再开窗，避免任一环节
   读到旧值。
3. **多实例竞态**：自动换端口需处理「两个 sidecar 同时挑同一下一个可用端口」的二次冲突，以及
   旧实例未退出导致的端口漂移。
4. **回退与可观测**：换端口必须在日志与 UI 明确打印「原 8760 被占，实际使用 XXXX」，不能静默。

以上未在 W9 实现，属后续架构项；本期保持明确失败。

## 硬边界

- 未改 `src-tauri/src/sidecar.rs`、未改 `src/host/**`。
- 不静默换端口、不自动改 config.json 的 port。
