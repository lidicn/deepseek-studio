## 2. JSONL 格式定义

每行一个 JSON 对象，用 `kind` 字段区分：

```json
{"kind":"loop","type":"status","text":"检测到未解析的工具调用，发送格式纠偏（第 1 次）…"}
```

- `kind:"bus"` + `event`（after-call/call-error/call-skip/before-call）→ 喂给 bus.emit
- `kind:"loop"` + `type`（tool/status/assistant/...）→ 喂给 harness.onEvent

详见 `tools/metrics/README.md`。

## 4. nudgeRate 是否完全复用 createHarnessMetrics()

**是。** `buildReport()` 内部 `createToolEventBus()` + `createHarnessMetrics(bus)`，逐行 dispatch 到 bus.emit / harness.onEvent，最后取 `harness.snapshot()`。测试用例 7 用同一批事件走两条路径（buildReport vs 直接喂 harness），四个字段（nudgeRate/toolRounds/nudgeRounds/toolCallsTotal）完全相等。

## 7. 阶段 B：D1 要真机取数，还差哪一步？

当前事件只在内存里（harness-metrics 是纯内存订阅器），跑完进程就没了。要让 D1 取到真机数据：

1. **web-engine 的 `recordToolCall()` 现在只推 `ToolCallRecord` 给 onToolCall 回调**（M2-2 刚加的），不写盘。需要在 hub 调用 `engine.recordToolCall(rec)` 的同时，把这行 append 到一个 JSONL 文件。
2. **改动位置**：不在 web-engine 里写文件（它不该有 IO 依赖），而在**调用 web-engine 的宿主层**（desktop-host / agent-loop 装配处）——那里已经有 onToolCall 回调，加一个 `createWriteStream` 把每行 JSON append 进去即可。
3. **谁该改**：这是 B 线（agent-loop / desktop-host）的接线工作，席3 不动 agent-loop。建议 B 线在装配 WebEngine 时加一个 file sink，把 bus 事件和 loop 事件都序列化进 JSONL。
4. **缺口**：loop 事件（type:'tool'/'status'/'assistant'）目前由 agent-loop 的 onEvent 消费，要持久化需要在那一层也加 tee。当前 harness-metrics 已经包装了 onEvent，可以在那个包装点加 JSONL tee。
