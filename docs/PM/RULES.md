# studio 规章制度

> 分两段：**常设铁律**（长期有效）+ **临时规则**（带失效日，过期自动作废）。
> 违反常设铁律的改动，无论多急，一律回退。

---

# 第一部分 · 常设铁律

## R-1 · 单写者原则

**同一文件，同一时刻只允许一个 agent 写。**

冲突热点（已确认，改动前必须查 STATE.md §2 看谁持有）：

| 文件 | 体积 | 为什么是热点 |
|---|---|---|
| `src/inject/main-world-interceptor.ts` | 63.5KB / 1212 行 | A 线 M3 要删纠偏；B 线刚改过推送点 |
| `src/host/agent-loop.ts` | 177 行 | A 线 M1-2 要改；B 线全部 bot 依赖其事件类型 |
| `src/host/bot/types.ts` | 26.9KB | 跨线接口锁定 |
| `package.json` | — | 多个任务都要加 script / 依赖 |

**当前分配**：前 3 周 `main-world-interceptor.ts` 归 A 线独占，B 线冻结该文件。

---

## R-2 · 唯一真相文档的层级

```
STATE.md（项目状态）
  └─ 指向各线任务文档（谁负责哪条线，就认哪份）
       ├─ A 线：docs/架构文档/内核归位开发计划-20261017.md
       └─ B 线：docs/claude/路线图-Claude-主开发引擎与宿主层-20261014.md
```

- A 线文档**只写 M0–M3**，不写 vN。
- B 线文档**只写 vN**，不写 M。
- 交叉引用只允许「引用」不允许「改写」。
- `docs/版本路线图.md` = 历史存档，**冻结不再更新**。
- `STATE.md` 是项目级状态唯一真相，但它**不替代**各线的任务文档——前者说「现在在哪」，后者说「怎么做」。

---

## R-3 · 每个交付必须带可复现命令

不能跑的不算 DONE。交付时贴**原始输出**，不贴结论描述。

标准三条：`npm run typecheck` / `npm run test` / 任务专属命令。

---

## R-4 · 状态值只有四个

`TODO` / `WIP` / `DONE` / `CUT`。改名不叫改状态。

---

## R-5 · 不许用描述替代数字

「测试基本通过」不算；写 `764 passed / 1 failed / 765 用例`。
数字变化必须重测并覆盖 STATE.md §5，不许只改文字。

---

## R-6 · PM 每轮必落盘

见 `README.md` §4。不写 = 这一轮等于没发生。

---

## R-7 · `docs/PM/**` 单写者

只有 PM 角色写。其他 agent 不写这里，只在自己窗口报，由 PM 转录。

# 第二部分 · 临时规则（带失效日）

## T-1 · 豆包冲刺时间闸门（失效：2026-10-17 16:00）

豆包 16:00 到期。规则：

| 时刻 | 动作 | 不可协商 |
|---|---|---|
| 12:30–13:00 | **合流闸门**：三席全停，跑全量 typecheck + test | ✅ |
| 15:00–15:30 | D2 裁决（pi-agent-core 能否接） | ✅ |
| 15:30–16:00 | **硬停开发，只写交接卡** | ✅ |

**为什么必须硬停**：16:00 之后豆包产出的代码全是未验证负债，且工作状态全在它上下文里，不写交接卡别人接不上。这 30 分钟不是浪费，是当日性价比最高的 30 分钟。

---

## T-2 · 合流闸门判据（失效：2026-10-17 16:00）

**规则：全量 typecheck + test 不绿，不许开下一轮。**

三席数字必须自洽，检查顺序：

1. **席 3 先报** → 红测试修好，基线应从 `764/765` 变 `765/765`
2. **席 1 报** → 新增 `harness-events.test.ts` 的用例数，全量应 ≥ `765 + 新增数`
3. **席 2 报** → `eval:golden` 可跑 + `pi-agent-core` 已装，`npm run test` 应仍全绿

**数字对不上 = 有人破坏了别人的改动 → 停下来定位，别开第二轮。**

**为什么要有这条**：豆包「快 + 额度足」的最大风险不是写不出来，是写得多、验得少。

---

## T-3 · 并行期禁止跑全量测试（失效：2026-10-17 12:30）

三席并行期间（10:30–12:30），**任何人不得跑 `npm run test` 全量**。

**理由**：三席正在改 `tests/` 与 `package.json`，此刻跑结果互相污染，红绿无意义；且全量 134s，会让慢速 agent 卡到闸门时间。

各席只能跑**自己那个测试文件**。

---

## T-4 · QD 不得处于关键路径（失效：另行通知）

QD 慢。绝不给它「我等你结果再决定」的位置，只能离线跑、下次看。

**允许**：纯静态审计、回归守门（跑测试贴红绿）。
**禁止**：开发任务、任何阻塞他人决策的任务。

---

## T-5 · 16:00 后的交接要求（失效：2026-10-18 00:00）

豆包到期后，接手人必须在 **15:30–16:00 期间**拿到：

1. 三席各自的任务交接卡（做了什么 / 验收输出 / 遗留问题）
2. `STATE.md` §5 硬证据更新（测试数字、依赖状态）
3. `log/2026-10-17.md` 末尾的断点标记

缺任一项，视为当日工作未完成。
