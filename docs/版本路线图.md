# DeepSeek++ Studio 版本路线图

> 版本：v0.6.0（2026-10-10 起，已交付）
> 基线文档：`docs/architecture.md`（v0.1）、`docs/architecture-review.md`（P0/P1 缺口清单）
> **产品定位（2026-10-10 方向修正后）**：**把 deepseek++ 浏览器扩展桌面化（浏览器化）**——用常驻宿主替代 MV3 background service worker，把扩展的用户可感能力（工具循环、本地技能、shell/python 沙箱、记忆、侧面板等）逐项复刻到 Tauri + WebView 桌面壳中。`deepseek-pp/src/core/**` 零修改复用。
> **方向修正记录**：用户裁定（2026-10-10）——此前路线图把重心放在「外部 agent HTTP 接口」（原 v0.6 独立模式 / v0.8 MCP stdio）属于跑偏。v0.5 已交付的 shell/file 能力、本地 HTTP API（8756）、令牌环、审计环**保留为基础设施**（它们恰好是复刻 background SW 能力的宿主侧地基），但版本序列重排为「能力复刻」主线，外部 agent 接口降级为可选外围（见 §2.11）。

## 0. 设计基线（已锁定，不可回退）

架构评审（2026-10-09）把 3 个 P0 缺口与 4 项风险定为 D1 之前必定的设计事实，当前 5 批内核已逐条落地：

| 评审项 | 决策 | 落地位置（已实现） |
|--------|------|--------------------|
| §1.1 双 world 桥 | 方案 b：双 bundle 照常注入，仅把 `runtime-boundary` 传输换成**同域直连** | `src/inject/direct-*` + `bridge-install.ts`（B2） |
| §1.2 background 归属 | 5,800 行 background 整体迁**常驻 JS 宿主域**，Rust 只做宿主 | `src/host`（authority）+ `src/api`（常驻宿主侧） |
| §1.3 grant 签发归属 | 常驻 JS 宿主签发 grant；Rust 只**校验**、特权执行前一次性 reservation 核销 | `src/host/authority.ts` + `grant-store.ts` |
| R12 单域伪造面 | 桥走同域直连，不暴露 `postMessage` | `src/inject/direct-bridge.ts` |
| R13 `chrome.storage.session` 语义 | 授权态单独一轨：进程内、不落盘 | `src/host/grant-store.ts`（in-memory） |
| §3.3 端口 | **8756**（避开本机 DeskPilot 的 8765） | `src/api/server.ts` + `main.ts` |
| U2 上游关系 | `deepseek-pp/` 零修改拷贝快照；运行期 `import()` 接入 | `tsconfig` 排除 `deepseek-pp`；两处动态 import |

**三条硬不变量（来自 AGENTS.md，全程遵守）**：
1. 每次生产工具执行必须先过 `src/host` 授权路径，再 rehydrate/执行。
2. capability 必须显式 `start/stop` 生命周期，资源所有权归上游 `replaceContentDocumentLifecycle`。
3. 页面/模型调用持有的 grant 必须绑定 document/session/requestId 且一次性消费。

## 2. 版本路线图（2026-10-10 重排：能力复刻主线）

> v0.1~v0.5 为历史交付（详见 §4 存档），此后版本号重新规划。

### v0.6 MAIN-world 拦截 + 工具调用事件桥（能力复刻起点）✅ 已交付（2026-10-10）
**目标**：打通「聊天页里的模型发起工具调用」的数据通路——这是与纯浏览器壳的本质区别。
**实际落地**：
- **MAIN-world 拦截**：`src/inject/main-world-interceptor.ts` 在页面 `document_start` 钩住 `window.fetch`/`XMLHttpRequest`，用 `src/inject/streaming-tool-parser.ts` 增量解析流式响应中的上游 XML 工具调用标签（`<shell_exec>` / `<local_file_read>` / `<local_file_write>` / `<local_file_stat>`），并把可见 XML 标签从流中剥离。
- **工具调用事件桥（反向）**：页端把解析出的调用经宿主 ws（`/studio`）以新增的 `tool-call` 消息投递给宿主；宿主 `page-runtime` 映射为 Studio 工具 id（`shell.exec` / `file.read` / `file.write` / `file.list`，见 `src/shared/tool-contract.ts`）后调用 `invokeTool`——**直接复用 v0.5 全链**（grant 签发 → registry/origin 治理 → 三档策略 → 同意闸门 → 审计环），真实执行 shell/file 而非 fake echo（用户裁定：接真实工具）。宿主回 `tool-call-result`（按 callId 关联）。
- **结果回注**：页端收到结果后，在下次对话请求的 `prompt` 中回填工具结果（`reinjectIntoPrompt`），形成「模型发起 → 宿主执行 → 结果回注」闭环。
- **注入自动装配**：`src/desktop/entry.ts` 在真实 WebView 环境（存在 WebSocket 且未装配）下自动 `installStudio()`，使拦截器随注入脚本加载即生效。
**验收**：`tests/desktop/tool-bridge.test.ts`（12 用例）覆盖契约映射、宿主 `executor` 路由、页端 `sendToolCall` 往返、拦截器解析与结果回注；既有 `page-runtime` / `host-client` / `desktop-entry` 测试无回归；`tsc --noEmit` 0 错误；`npm run build:inject` 产物含拦截器（54.4kb）。
**关键决策（v0.6）**：
1. **接真实工具**：用户裁定跳过路线图原定的 fake 回执，直接复用 v0.5 shell/file capability 经授权链真实执行。
2. **解析核心自包容移植（对「最大化 import 上游」红线的唯一偏离）**：上游 `core/interceptor/`（含 `request-interceptor`/`response-interceptor`/`hook-state` 等）依赖 WXT/`chrome` 运行时类型与上游自身更宽松的 lint 配置，无法在本项目严格 `tsconfig`（`noUnusedLocals`/`noImplicitAny`/`strict`）下编译；且 `tool/index.ts` 桶文件会把 `artifact`/`browser-control` 等无关模块一并拉入。故将上游流式 XML 工具调用解析算法逐行等价移植到 `src/inject/streaming-tool-parser.ts`（零浏览器扩展耦合、可单测）。事件桥与授权/执行复用 Studio 自有实现，不存在平行重写。运行时行为与上游客流一致。
**依赖**：v0.4（注入管线）、v0.5（授权链 + shell/file 能力）。

## 5. 关键不变量 / 红线（贯穿全版本）

1. **授权先于执行**：任何工具执行前必须持 `authority.verifyGrant()` 通过的 grant；`grant-store` 一次性消费。
2. **资源所有权归上游**：capability 的 `start/stop` 必须委托 `replaceContentDocumentLifecycle`，stop 后 `snapshot.total===0`，host 不直接持有 DOM 引用。
3. **fail-closed 优先**：origin 不在白名单、存储不可序列化、KV 持久化失败、grant 校验失败 → 一律拒绝，不得静默放行。
4. **上游零修改**：`deepseek-pp/src/core/**` 不改动；仅经动态 import 与类型对齐接入。**能力复刻的每一版都应最大化 import 上游模块，而不是自研平行实现**（v0.5 之前的能力自研是快照缺席期的过渡，v0.6 起纠正）。**v0.6 唯一偏离**：上游 `core/interceptor` 因依赖 WXT/`chrome` 类型与上游更宽松的 lint 配置无法在本项目严格 `tsc` 下编译，故将其流式 XML 工具调用解析算法等价移植到 `src/inject/streaming-tool-parser.ts`（自包容、零浏览器扩展耦合、可单测），运行时行为与上游客流一致；事件桥与授权/执行均复用 Studio 自有实现，未做平行重写。
5. **端口 8756**：本地 HTTP API 固定 8756，CORS 仅 localhost；不占用/冲突 DeskPilot 8765。
