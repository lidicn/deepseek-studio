# 组织模式 · 主进程制（2026-10-18 起替代旧三席制度）

> 编制：主进程（豆包工作）｜日期：2026-10-18
> 取代：旧 `seat1/seat2/seat3/seat4/seat5` 常驻路线图并行制度（D-005 那套）。
> 原则：**主进程自写主线，只把"规格封死的独立包"以一单一卡分发；QA 离线守门不阻塞。**

---

## 1. 角色与平台（主进程自主定）

| 角色 | 数量 | 平台 | 干什么 | 绝不做 |
|---|---|---|---|---|
| **主进程** | 1 常驻 | 豆包工作（本对话） | 主线 kernel/engine/接线/契约定义/合流跑闸门/派单 | 不把核心决策外发 |
| **辅助开发席** | 1（峰值 2） | **豆包另开对话** | 只做工单里契约封死的独立纯函数/工具包，自带单测，**不注册工具** | 不碰 kernel/engine/desktop-host/契约/package.json/闸门 |
| **QA 守门** | 1 常驻离线 | **Qoder（国内或国际任一）** | 后台跑 `npm run gate` + 全量 `npm run test` + `eval:golden`，贴红绿原始输出；静态核对是否符合工单契约 | 不写业务码；不站关键路径（不等它） |
| Claude（备用） | 0 常规 | Claude | 仅在遇到"需要熟悉旧引擎/注入层历史"的硬接线时临时启用 | 不排常规边角包 |
| CB | 停用 | — | D-007（内存开销不可接受），工单作废保留 | — |

### 为什么辅助席用豆包而不是 Claude/Qoder（自主决策记录）
- 工单是"输入输出已封死、独立文件、自带单测"的纯函数包，**不需要**对老引擎/注入层的熟悉度；豆包与主进程同工具链、同 `npm`/`vitest`/`gate` 命令、同路径，合流零翻译成本。
- Claude 质量高但慢，用来写边角纯函数不划算，留作硬接线备用。
- Qoder 性能弱、不能开发（既定事实），只配离线守门；慢正好不阻塞主进程。

## 2. 席位计数（在跑）

- 常态：主进程 1 + 辅助 1 = **2 个开发位**；QA 后台 1（不计入开发位）。
- 峰值：仅当 M5/M6 同时有两个互不依赖的独立包时，辅助开到 2；平时不开第 2 个。
- 共享文件（`package.json`、`tools/contract/check.ts` 白名单、`desktop-host.ts`、契约文档）**只有主进程能改**，这是不开更多开发席的硬原因。

## 3. 文件域（辅助席红线）

| 角色 | 只许写 | 绝不碰 |
|---|---|---|
| 主进程 | 全部，含接线/契约/闸门/共享文件 | — |
| 辅助开发 | 工单点名的**新文件**（纯函数模块 + 对应测试文件） | `src/host/kernel/**`、`src/host/engine/**`、`src/host/desktop-host.ts`、`src/inject/**`、`tools/**`、`package.json`、`docs/PM/roadmap/CONTRACTS.md`、任何既有文件 |
| QA | 只在自己窗口贴红绿；不写任何仓内文件 | 改代码/改测试/改配置 |

> 辅助席**只交付纯函数模块**，工具注册（挂进 `hostTools`）由主进程合流时完成。这样辅助席零机会碰到授权链/consent。

## 4. 一单一卡流程（替代常驻长路线图）

1. 主进程定契约 → 写工单 `docs/PM/orders/ORD-NNN-<slug>.md`（自包含：落点、入参出参类型、错误形状、禁止区、验收命令、红绿输出落 `docs/PM/progress/`）。
2. 把工单全文贴给一个豆包辅助对话；它只读本工单 + 点名的契约节，不开额外检索。
3. 辅助席交付：新模块 + 单测，自跑工单指定命令，把原始输出落 `docs/PM/progress/ORD-NNN-*.md`。
4. 主进程合流：跑 `npm run gate` 全绿 → 主进程自己把工具挂进 `hostTools` → 补接线测试。
5. QA 后台复跑闸门贴红绿，主进程下次看；红了由主进程定位，不阻塞派下一单。

## 5. 验收与硬门（沿用 R-3/R-5）

- 每个交付贴**原始命令输出**，不许用"基本通过"；测试数必须写实数（`X passed / Y failed / Z 用例`）。
- 合流硬门：`npm run typecheck` = 0 错；`npm run test` 全绿；`npm run gate` EXIT=0；新增单测独立可跑。
- 接口加值/改形状：先改 `CONTRACTS.md` → 改 `tools/contract/check.ts` 白名单 → 改代码 → 改测试（契约第 5 节流程），不许只改代码。

## 6. 待人工最小触发项（非席位能解决）

- 真实联网搜索通道、真实 API key、已登录网页：到 M6/M7 由主进程列一页最小操作单，请用户在场一次，不做开放测试。
