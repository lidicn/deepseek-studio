## 4. 必答

### 4.1 run() 最终签名

```ts
export function createTaskLoop(opts: TaskLoopOptions): TaskLoop;
// TaskLoop.run(userText: string): Promise<TaskLoopRoundResult>
```

核心循环（maxRounds 默认 1）：

```ts
async function run(userText: string): Promise<TaskLoopRoundResult> {
  history.append({ role: 'user', content: userText });
  let last: TaskLoopRoundResult | undefined;
  for (let round = 1; round <= maxRounds; round += 1) {
    const result = await engine.send(buildPrompt(history));
    history.append({ role: 'assistant', content: result.content });
    if (result.toolCallRecords) {
      for (const rec of result.toolCallRecords) {
        history.append({ role: 'tool', content: formatToolRecord(rec), toolCallId: rec.tool });
      }
    }
    const stopReason = computeStop(result.content, result.toolCalls, result.timedOut);
    last = { round, content: result.content, toolCalls: result.toolCalls,
             ...(result.toolCallRecords ? { toolCallRecords: result.toolCallRecords } : {}),
             ...(stopReason ? { stopReason } : {}) };
    if (stopReason !== undefined) break;
  }
  if (last !== undefined && last.stopReason === undefined) last = { ...last, stopReason: 'max-rounds' };
  return last as TaskLoopRoundResult;
}
```

### 4.2 toolCallRecords 为 undefined 时怎么处理

```ts
if (result.toolCallRecords) {          // 可选字段，缺省直接跳过
  for (const rec of result.toolCallRecords) { history.append({ role: 'tool', ... }); }
}
// 返回值里 toolCallRecords 同样条件性携带：
...(result.toolCallRecords ? { toolCallRecords: result.toolCallRecords } : {})
```
测试 4 专门覆盖：toolCalls:2 但 records 缺省时不崩、tool role 0 条、返回值 toolCallRecords undefined。

### 4.3 复用了 continuation-prompt.ts 的哪个函数

`extractTaskCompleteSignal(content)`。理由：卡 §4.4 明令「判停信号别自己发明、直接 import 复用」，且 `completed` 这个 stopReason 只能由它识别 `<task_complete>` 给出。优先级：timeout > completed > no-tool-calls > undefined。

### 4.4 阶段 B 建议与坑

- 已在实现里预留 `maxRounds` 循环：每轮重新 computeStop、轮间不漏回填；跑满仍无 stopReason → `max-rounds`。
- 坑 1：context 拼装现在是 `role: content` 的纯文本 join，M3 接真实 WebEngine 时必须换成真正的消息数组协议，不能直接 send 这种拼接串。
- 坑 2：多轮之间目前没有「工具结果回填后再触发下一次 send」的真实通道——假引擎是脚本化返回；接 WebEngine 时要复用 `waitForNextReply()` 而不是再发 continueNudge。

### 4.5 一次工具回合从 run() 进到 history 回填完，中间有没有「需要 nudge」的环节？

**没有。** 这是 D1 的定性结论：
- run() 内部一次 `engine.send()` 拿到的就是「本轮模型回复 + 本轮工具调用计数 + 工具记录」，工具执行发生在引擎/页面侧，TaskLoop 只负责落库。
- 中间没有任何「发提示词逼模型继续」的步骤；判停全靠模型回复本身（task_complete / toolCalls 数 / timedOut）。
- 也就是说：只要引擎侧的完成检测可靠（waitForNextReply 稳定拿到 auto-continue 的回复），宿主 TaskLoop 根本不需要 nudge——这正是 D1 想验证的「删纠偏」前提。
