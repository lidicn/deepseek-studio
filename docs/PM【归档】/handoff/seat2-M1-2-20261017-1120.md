## §4 harness-metrics 事件模型是否够用

**部分够用，缺一个方法。**

当前 HarnessMetrics 只有 `onEvent(event: AgentLoopEvent)` 一个输入口。recordToolCall 收到的是 `ToolCallRecord {tool, ok, error?}`，不是 AgentLoopEvent。我在 recordToolCall 里合成了 `{type:'tool', text:rec.tool, toolCalls:1}` 喂进去——这让 toolRounds 能涨，但：

- successCount/failureCount/skipCount 不变（它们只从 bus after-call/call-error/call-skip 涨）
- 一个 recordToolCall 算一个 toolRounds，语义上偏粗（应该一轮一次 tool 事件，不是一调用一次）

**需要 harness-metrics 暴露**（下一轮）：
- 一个 `recordToolCall(rec: {ok: boolean})` 或 `onToolResult(ok: boolean)` 方法，直接喂成功/失败计数，不必经过 bus。
- 或者：允许 WebEngine 直接 emit 到共享 bus（已经有 toolEventBus 选项）。

## §5 nudgeRate 能否真机跑出来

**还差 agent-loop 层的接线。** 当前 WebEngine.recordToolCall 喂的是 type='tool' 事件（涨 toolRounds），但 nudgeRounds 依赖 agent-loop 发的 status 事件里含「纠偏」二字。WebEngine 不发 status 事件——那是 agent-loop 的职责。

要 nudgeRate 有真实数据，需要：
1. desktop-host 装配时把 metrics 传给 createAgentLoop（包装 onEvent）
2. 或者 agent-loop 直接持有 metrics 引用

B 线（只答不改）：**应该改**。agent-loop.ts 应该从 ModelEngine 拿 metrics（或自己持有），因为 nudgeRate 的数据源是 loop 事件不是 engine 事件。engine 只负责 toolRounds 计数，nudgeRounds 只能 loop 自己统计。但 agent-loop.ts 是禁止区，本轮不动。
