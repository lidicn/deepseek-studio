### 1.2 首行必须钉"规则版本"（A7 原要求，这一节把它变成可执行字段）

- 为什么：本席 13:02 实测 `boundary.ts` 从 EXIT=1/14 条翻到 EXIT=0，其中 **13 条是靠 13:00:43 加的 `R4_EXEMPT` 豁免表消掉的**（被豁免的 import 一条没少）。若趋势表只记 exit code，下一个人会把"尺变宽"读成"债清零"——这正是跨域第 17 条／A6 条件② 的棘轮问题。
- 规格（每行 JSONL 的 `ruleRev` 对象，四枚 sha 短格式）：
  ```
  ruleRev: {
    boundarySha:  <sha1sum tools/audit/boundary.ts  前 8 位>,
    symbolsSha:   <sha1sum tools/audit/symbols.ts>,
    m3cleanSha:   <sha1sum tools/audit/m3-clean.ts>,
    contractSha:  <sha1sum tools/contract/check.ts>,
    r4ExemptLen:  <grep -c ... R4_EXEMPT 的元素个数，现读 4>
  }
  ```
  取法建议实现为 `createHash('sha1')` 读四把尺的字节面；**⛔ 用 `git rev-parse HEAD` 代替**——尺没提交时（本席 13:00 那次就是未提交状态 `M`）HEAD 会把两次不同的尺读成同一版本。
- 另加一条**反空集腿**（承 A2 票里"注入未生效就判 FAIL"那族形状）：若 `ruleRev` 四枚 sha 全等或全空 ⇒ history.ts 直接 FAIL，⛔ 落该行。

### 1.3 建议字段表（⛔ 实现，只定形状）

`ts`（ISO8601＋时区）/ `commit`（`git rev-parse --short HEAD`）/ `dirty`（`git status --porcelain` 行数，**含⛔ 干净时的 0**）/ `leg` / `cmd` / `exit` / `ms` / `observed`（各腿自己的数：vitest 的 `collected/passed/failed/skipped`、eval 的 `total/pass/fail`（`tools/eval/run.ts:452` 那行 `total: X pass: Y fail: Z` 正好可正则锚）、coverage 的 `kernelPct/enginePct`）/ `sampleDriven` / `live` / `ruleRev{…}`。

- ⚠️ `dirty` 这一列此刻**有实战价值**：16:11 那次 `git reset --hard` 之后全树"干净"，而"干净"的成因是工作被抹掉（第 30 条）。趋势表若只记测试数、⛔ 记工作树面，事故轮的数据点会与正常轮无法区分。
- `--since=3d` 输出：纯文本表、⛔ 画图（PM 原列要点）；**表头必须带 `ruleRev` 变化标记**（四枚 sha 中任一枚与上一行不同 ⇒ 该行后插一行「⚠ 尺变更」）。
