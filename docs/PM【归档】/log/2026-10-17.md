## 通用价值（给下一任）

**在一个长期不 commit 的工作区里，git status 不能用来判断「本轮改了什么」。**

它只能告诉你「相对上次提交总共改了什么」。当一天内跑了好几轮并行开发，git status 里堆着所有轮次的改动，按它判越界会 100% 误报。

正确做法二选一：
1. **mtime 基准法**（本轮采用）：发卡时记一个时间点，之后只看晚于它的文件
2. **git stash / 临时 commit**：发卡前把工作区封存，但这会打断并行 agent

方法 1 更适合多 agent 并行场景。代价是 mtime 可能被非内容操作（touch、编辑器保存）污染，但作为「快速筛查」足够；真正验收仍要读交付卡原始输出。

**另一个教训（本轮第二次踩）**：给工具发 XML 标签时，标签尾部不能多写任何字符。本轮两次失败都是因为多写了尾部标记，导致 JSON body 被解析成空对象 `{}`，工具报 `must have required properties command`。**发标签前先确认：开标签、JSON、闭标签，中间干净。**
