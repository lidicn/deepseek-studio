## 3. 任务（严格按你自己的 M1-1 方案，additive）

### 3.1 加字段（不改现有语义）

`src/host/engine/model-engine.ts`：

```ts
export interface EngineSendResult {
  readonly content: string;
  readonly toolCalls: number;        // ← 保持不变！老调用方继续读
  readonly timedOut?: boolean;
  // 新增，可选，additive
  readonly toolCallRecords?: readonly ToolCallRecord[];
}
```

### 3.2 WebEngine 侧累积

`WebEngineOptions` 的 `toolCallCounter: { current: number }` **保留不动**（可能是别人传的），
新增可选 `onToolCall?: (rec: ToolCallRecord) => void`；WebEngine 内部累积本轮记录，在 `send()` 返回时填进 `toolCallRecords`。

若 `onToolCall` 未提供，`toolCallRecords` 不填（`undefined`），行为与今天完全一致。

### 3.3 测试

`tests/desktop/engine-tool-records.test.ts`，≥ 6 个用例：

1. 不传 onToolCall → toolCallRecords 为 undefined（向后兼容）
2. 传 onToolCall 且无工具调用 → toolCallRecords 为 []
3. 一次工具调用 → records.length === 1 且 toolCalls === 1
4. 三次工具调用 → records.length === 3 且 toolCalls === 3
5. records 里每条含 tool/ok 字段
6. 连续两次 send，第二次的 records 不包含第一次的（每轮清空）
