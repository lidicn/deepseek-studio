## 6. 任务分解

### A-1 · 定义日志格式（写进 README）

JSONL，一行一个事件。字段**必须能直接喂给 `HarnessMetrics.onEvent`**。

在 `tools/metrics/README.md` 里写清：每行是什么、一条记录长什么样（贴真实示例）、谁负责产出这份日志（现在是手工/离线，将来是 web-engine）。

### A-2 · 实现 report.ts

输入：一个 JSONL 文件路径（argv[2]）
输出：人可读报告，至少含

1. 总事件数 / 解析失败行数
2. `toolRounds` / `nudgeRounds`
3. **`nudgeRate`（百分比，保留 2 位）**
4. **D1 判定**：`< 5%` → 打印 `D1 = PASS (可直接做 M3)`；`>= 5%` → 打印 `D1 = FAIL (先补 web-engine 完成检测)`
5. 样本量提示：`toolRounds < 20` 时额外打印 `WARN: 样本量不足，结论仅供参考`

退出码：D1 PASS → 0；D1 FAIL → 1；文件不存在/解析全失败 → 2。

**必须复用 `createHarnessMetrics()`**，不许自己重算 nudgeRate（否则等于写了两份实现）。

### A-3 · 示例数据 + 测试（>= 8 用例）

`tools/metrics/samples/` 放两份：
- `healthy.jsonl` — nudgeRate 明显 < 5%
- `unhealthy.jsonl` — nudgeRate 明显 >= 5%

`tests/desktop/metrics-report.test.ts` 覆盖：

1. healthy 样本 → 退出码 0、输出含 PASS
2. unhealthy 样本 → 退出码 1、输出含 FAIL
3. 空文件 → 退出码 2
4. 文件不存在 → 退出码 2
5. 含非法 JSON 行 → 跳过该行、计入「解析失败行数」、不崩
6. `toolRounds < 20` → 输出含 WARN
7. nudgeRate 计算与 `createHarnessMetrics().nudgeRate()` **完全一致**（同一批事件两条路径比对）
8. 百分比格式化成 2 位小数

**测试怎么调 CLI**：建议把核心逻辑抽成 `export function buildReport(events): ReportResult`，测试直接调函数；CLI 只做读文件 + 打印 + exit。这样不用 spawn 子进程。

### A-4 · 加 script
