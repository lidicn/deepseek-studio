# v0.14.12 发版操作（给你在网页上点的那几步）

这份不是 Release 正文。正文在 `docs/release-notes-v0.14.12.md`，本文件是内部操作说明，不要粘进 GitHub，也不要当正文读。

## 本版起的一个变化：正文不再需要手工粘贴

从 v0.14.12 起，发版流水线自己带正文：Draft 创建时读 `docs/release-notes-v0.14.12.md`（`body_path`），并且在建 Draft 之前先校验该文件存在且非空白——缺失或空就在构建阶段报红，构建的 `Preflight` 还会检查 Draft 的正文非空。此前 v0.14.8／v0.14.11 两次都要靠你手工粘一次，那是流程缺口，已补。

## 前置（由私聊 PM 完成，你不用做）

1. 第 32 次全量闸绿，且跑在终态上（版本号笔＋正文＋各席位收口件都在树里之后再起跑）。
2. `docs(release)` 正文笔**先于** `chore(release)` 版本号笔入库（正文文件必须在 tag 那个 commit 里存在，否则 `body_path` 读不到）。
3. 三向一致：tag ＝ `package.json` ＝ `tauri.conf.json`（不等会被 `release.yml` 的版本门直接挡下）。`Cargo.toml` 的 `0.4.0` 是 crate 版本，不跟版、不许动。
4. annotated tag `v0.14.12` 已打并推送；CI 三条 job 全绿（build+sign、published 闸、gate）。
5. `releases` 里出现 `v0.14.12 (Draft)`，资产齐全：两个安装包＋两个 `.sig`＋`latest.json`。

## 你要点的（大约三十秒）

1. 打开 https://github.com/lidicn/deepseek-studio/releases
2. 找到 **v0.14.12 (Draft)** → 右侧 **Edit**。
3. **先看一眼 Describe your release 输入框**：正常应当已经带着正文（就是那份说明文件的内容）。
   - 有正文：什么都不用改，直接下一步。
   - 空的：说明 `body_path` 没生效，这次仍按老办法把 `docs/release-notes-v0.14.12.md` 全文粘进去，**并且回来告诉我**——那意味着这次发布把刚补的缺口又暴露出来了，我要当场查而不是当作正常。
4. 勾上 **Set as the latest release**（这一勾必须勾；不勾则 `releases/latest` 指针不推进，Studio 收不到更新提示，这一点已踩过三次）。
5. 点 **Publish release**。

## 发版前有一件必须先确认（本条 2026-11-08 更新，旧版写的是"等你点头才动"）

装版收口五步里，**S1（清跟随键默认值）与 S4（改开始菜单快捷方式指向）已于 11-08 做过并实测复核**：跟随键现读已指回正常安装目录，装版 exe 的 FileVersion 与目录一致，快捷方式也不再指向测试目录。留底在 `logs/s1-followkey-backup.reg` 与 `logs/s4-shortcut-backup.lnk`。所以**"点更新会把新包装进测试目录、日常版不升级"这条风险已解除**，可以直接发。

**只剩 S5 等你点头**：删两个已无用的旧目录（一个历史测试安装目录、一个 0.14.8 的孤儿目录——它有 exe 但没有卸载注册项，卸载器管不到它）。这两枚删不删都不影响发版，也不影响升级。

数据根（`com.deepseek.studio` 的两个目录）无论 S5 做不做都**不动**——登录态、配置、历史都在那里，卸载器默认不清是设计保留、不是缺陷。
