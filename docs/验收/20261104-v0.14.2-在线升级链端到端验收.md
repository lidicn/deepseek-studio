## 4. ② 卡片出现（不过 → 根因定位）

**三轮实例时间线**（tag `v0.14.1-upgrade-e2e`，exe `9CD4F4A3…`）：

| r2 | 29060 / 19:17:18（指针修复后） | Rust 侧首查撞 GitHub 连接 RST（本机今日多次）→ fail-safe 行 `[studio] updater check failed (fail-safe, ignored): error sending request for url (…latest.json)`（唯一实质行，`app-stderr-i191712.log`）→ **一次性缓存把失败锁死整个进程** | exitMs=2,557ms |

**决定性探针（r3 期间，19:28，CDP 页端同世界）**：

```
updater_check  => "Command updater_check not allowed by ACL"   （8ms，复探稳定）
updater_progress => "Command updater_progress not allowed by ACL"
updater_install  => "Command updater_install not allowed by ACL"
```

**根因（逐层坐实）**：

1. 全仓唯一 capability 文件 `src-tauri/capabilities/default.json`：
   ```json
   { "identifier": "default", "windows": ["main","workbench"], "permissions": ["core:default"] }
   ```
   `updater_check` / `updater_install` / `updater_progress` 三个自定义命令**不在任何 allow 清单** → Tauri v2 default-deny → 页端所有 invoke 被 IPC 层拒。
2. 页端 `checkUpdate` 的 `.catch(() => null)` 把 ACL 拒绝串当「无更新」静默吞掉（fail-safe 本为网络错误设计，这里顺带吞了配置错误）→ **卡片永不出、且无任何可见线索**。
3. Rust `spawn_startup_check` 走进程内直调（不经过 IPC/ACL）所以能跑（r2 的 fail-safe 行即其产物），但结果缓存**页端永远读不到**。
4. **回归缺口**：`tests/desktop/updater-callsite.test.ts` 四条全是源码文本级（main.rs 注册文本 / updater.rs 模式 / 页端 `invoke(` 正则）——**不碰 ACL 层**。14/14 全绿与真机 100% 死透并存，正是缺一条「ACL 白名单」断言。
5. **影响面**：`git show v0.14.2:src-tauri/capabilities/default.json` 与当前 HEAD 逐字一致（`git diff v0.14.2..HEAD` 对 capabilities/updater.rs/main.rs 为空）→ **0.14.2 与当前树同病**；不修的话，任何带 updater 的发布版用户都收不到更新。

## 6. P1 缺陷单（建议归 Core）

**缺陷**：updater 三命令未进 ACL 白名单，UI 更新链真机全死（0.14.1/0.14.2/HEAD）。

**修复建议**：
1. `src-tauri/capabilities/default.json` 的 `permissions` 补三命令的 allow 项（准确权限标识以构建期生成物 `src-tauri/gen/schemas/desktop-schema.json` 的 ACL 段为准；命令名 `updater_check` / `updater_install` / `updater_progress`）。
2. **新增真回归断言**（补 §4.4 缺口）：`tests/desktop/updater-capabilities.test.ts` —— 解析 `src-tauri/capabilities/default.json`，断言 `permissions` 含三命令 allow 项；负控 = 从白名单删一项必红。
3. （可选）页端 `checkUpdate` catch 里对字符串结果（ACL 拒绝）打 `console.debug`，让这类配置错误不再静默。
4. 发修复版（0.14.3 或 0.14.2.x）+ GitHub Latest 指针指到它后，**我重跑全链**：卡出现（断言 `#studio-update-card` 文案「发现新版本 v0.14.3（当前 0.14.1）」）→ 立即更新 → `updater_progress` downloading(带 downloaded/total)→done → 关窗重启 → 断言 PE 0.14.3 + healthz 200。

## 8. 诚实台账（本段自己的错与假证）

- **P32 复发**：`node -e` 内嵌 `\"` 转义在 PowerShell 一次写爆（`Expected unicode escape`）→ 全部改写成 `.cjs` 文件执行（P33 教训：CJS + 落盘，不落 `node -e`）。
- **`*eepseek*` 进程模式假阳性**：一次零态检查匹配到 10 个 DSH 自身进程（`DeepSeek Harness`），studio 实际 0 —— 零态判断一律用 launch 脚本的精确名 `deepseek-studio` + webview2 命令行归属，不再用宽模式裸数。
- **缓存锁死教训**：r2 首查 RST 被一次性缓存锁死整个进程后，我一度仍在「等卡片」，是 r3 的 stderr 静默 + ACL 探针才拼出全图。设计后果如实记：**首查瞬时故障 = 该次运行永久静默，重启才恢复**（fail-safe 与一次性缓存的叠加效应，是否加「失败不锁缓存」策略归 Core/PM 裁，不属本卡）。
- 本机 GitHub 连接全天不稳（curl 多次 RST / 21s 超时），端点内容每次多试 + 双通道（API 指针 + 端点原文）核对，未单点定论。
