## 二、「判取证面端到端通」最小读数集合

> 先分两件事：**「inject auth 取证活着」（`#1`/`#3` 落盘即证）与「transport 预 OPEN 队列 flush 两段通」（必须合取、不能拿一行直发日志顶）**。发布过关 = 前者成立 ＋ 后者要么按合取坐实、要么明确记「未证」。

**① 必须见（正信号，各 ≥1 行）**
- `#1 [auth] boot-check …` ≥1 —— **只判 inject 侧 auth 取证活着**；它不证明队列路径：该行补发还是直发取决于落行时 socket 是否 OPEN，**直发的一行对队列路径零证据**。
- `#3 [auth] resp … HTTP <status>` ≥1（status 任意）—— auth 响应取证在真实响应上触发；同样只证 auth 响应面、**不证队列路径**。

**② 「两段通」＝合取（口径不放宽）**
- 须满足其一：**(a)** `#1`（或 `#3`）**行号早于 `[peer] ws upgrade accepted`**（该行是 pre-open 补发、确走队列）；**或 (b)** 出现任一 `#4/#5` 行（`preopen dropped` / `preopen queue overflow N`，直接命中队列机制）。
- 两条都拿不到 ⇒ 记「**队列路径未证、等自然复现**」，**不得判「两段通」**（即 13:3x 收窄掉的"竞态运气"定字：旧版没有、本次有 ≠ 修复证据）。

**③ 缺失即正常（0 行＝健康，>0 行＝需归因）**
- `#4 [transport] preopen dropped …`、`#5 [transport] preopen queue overflow N` —— 0 行＝pre-open 无丢失（正常）；>0 行＝真丢失，转「丢失归因」（注：这 >0 行同时是 ②(b) 的正面证据之一）。

**④ 不得见（出现即非健康）**
- `#2 [auth] boot-check-failed …` —— 出现＝boot-check 本体抛错，登录态/诊断链异常。

**最省冒烟只到 ①**：`#1` 落盘 = inject auth 取证活着，**到此为止**。**「两段通」没有单行冒烟**——它天然是 ② 的合取；拿不到就记「未证、等自然复现」，**不许拿一行直发日志顶上去**。
