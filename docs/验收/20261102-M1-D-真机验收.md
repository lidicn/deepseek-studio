## 6. 缺陷清单

### D1（阻断 M1-C 收尾）注入层没有 `finish-sentinel` 上报方 ⇒ `interrupted` 端到端不可达

- **现象**：真实无哨兵断流（§3.2）与全部 10 轮正常请求，宿主 `sawFinishSentinel` 恒 `undefined`；`decideCompletion` 的 `sawFinishSentinel === false` 分支**永不命中**。
- **根因**（三处缺口，缺一不可）：
  1. `src/inject/main-world-interceptor.ts` —— 有哨兵判定（`loopState.streamSawDone`，:1351/:1395/:1750/:1796；判定函数 `deepseek-sse-frame-decoder.ts:134`），但结论只进本地 `interceptorTrace`（:2564-2570），**未发给宿主**；
  2. `src/desktop/host-client.ts` —— **缺** `sendFinishSentinel` 方法（对照 `sendAssistantReply` :408、`sendStreamDelta` :411）；
  3. 注入产物 `entry.js` 中 `finish-sentinel` 命中数 0。
- **建议落点**：注入层在「本轮流结束」处（`settleStreamEnd` / `finishStepFlow` 邻近）判定并上报 `sawFinishSentinel`；`host-client` 增加 `sendFinishSentinel({round, sawFinishSentinel})`；协议类型 `PageToHostMessage` 已有该 type，无需新增。
- **必须一并满足的语义**：
  - `readFinishSentinel(botId, sinceMs)` 用 `sinceMs` 挡陈旧记录（`page-runtime.ts:641-646`）⇒ 上报时刻必须 ≥ 本轮开始；
  - `decideCompletion` 的 `interrupted` 还要求**本轮有可见输出**（`web-engine.ts:615` `sawNewText && lastText.trim().length>0`）⇒ 空流仍应归 `empty-response` / `read-no-data`；
  - **风险**：一旦接通，**正常轮次若误报 `false`，正常回复会被打成失败**（`requireTaskLoopReply` 直接抛 500）。建议口径：**只在确实判定「流结束且无哨兵」时上报 `false`；判到哨兵上报 `true`；无法判定则不上报**（保持 `undefined` 的老行为兼容）。
  - **回滚**：已有 `STUDIO_TERM_STRICT=0` 开关（`web-engine.ts:77-80`）可作二级保险。

### D2（非阻断）Tauri 内部 API 无法关闭窗口

`core:window:allow-close` / `core:app:allow-exit` 未在 capability 中授予，页内 `__TAURI_INTERNALS__.invoke('plugin:window|close' | 'plugin:app|exit')` 均被拒（原文见 §5）。目前只能由外部发 WM_CLOSE（`Process.CloseMainWindow()`）。属可用性/可运维性，不阻断主线。

### D3（流程）原两支只读复现脚本已失去真实性

`logs/td-repro/r301-conversation-allow.mts` 与 `td01-search-outside.mts` 是修复前的「坐实缺陷」脚本，复跑结论不可作为验收依据（详见 §4）。建议由作者按新口径更新，或明确标记为历史件。
