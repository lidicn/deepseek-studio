## 3. 根因（定点取证，决定性证据）

### 3.1 宿主 chat-read 实际读到的 3 条消息（`inspect-chatread.mjs` 原始输出）

```
ok= true  sessionId=33507439-d490-4054-bbbc-dcd3d4d6f37a  count=3
  [0] role=user index=0 id=33507439-... len=9779   head="[studio-tool-capability] ## 角色 你是 DeepSeek Studio 的本地工具代理…"
  [1] role=user index=1 id=33507439-... len=10052  head="[studio-tool-capability] ## 角色 …"
  [2] role=user index=2 id=33507439-... len=10123  head="[studio-tool-capability] ## 角色 …"
```

**三条全是 user，索引 0/1/2 —— 就是这个会话**最早**的三条消息；`role` 里没有任何 assistant，宿主的「最后一条消息」就是它。**

### 3.2 页面侧挂载情况（同一次取证）

```json
{"vlistExists":true,"mounted":3,"mountedLens":[9779,10052,10125],
 "mountedClasses":["_81e7b5e","_81e7b5e","_81e7b5e"],
 "totalItems":2,"scrollTop":0,"scrollHeight":180,"clientHeight":180,"atBottom":true,"printableItems":1}
```

- 该会话 **26 条消息**（`parent_message_id` 已到 26），DOM 里**只挂 3 条**；
- 挂的这 3 条就是**最老的一屏**（能力前导提示在每条用户消息开头，故三条都长 ~10k）；
- **`scrollHeight == clientHeight == 180`**：这个 `.ds-virtual-list` 里**没有未渲染项的占位高度**，所以**滚它永远滚不动**；`atBottom` 因此恒为 `true` —— 任何「已在底部 / 已是最新」的启发式都会**反向撒谎**。

### 3.3 模型其实答了（排除「模型没答」）

同一次运行的宿主 stdout（`logs/verify-f1f2/app.stdout.log`）：

```
[interceptor] xhr chat body injected len=10214
[interceptor] xhr resp[…]: event: update_session … "role":"ASSISTANT" … "status":"WIP"
[interceptor] xhr extracted[9]: F1V3-MVWH
[interceptor] … {"p":"response","o":"BATCH","v":[{"p":"quasi_status","v":"FINISHED"}]}
[interceptor] … data: {"p":"response/status","o":"SET","v":"FINISHED"}
```

→ **请求发出去了、模型回了、流已 FINISHED**，而宿主的 DOM 读取**始终看不到这条回复**（因为回复没被虚拟列表挂载）。

> ⚠️ 顺带纠正一条前提：Core 说「普通轮 SSE 恒空」——但上面日志里**普通轮**的拦截器**确实从 SSE 抽出了文本**（`extracted[9]: F1V3-MVWH`，正是本轮标记片段）。`autoReplyText` 那个字段为空 ≠ SSE 里没有答案文本。**SSE 通道在普通轮可能可用**，值得 Core 复核——若可用，它是比「DOM + 虚拟列表」稳得多的答案源。

### 3.4 给 Core 的修复方向（按证据排序）

1. **判「是否最新」不要用滚动指标**：`scrollHeight==clientHeight` + `atBottom=true` 会撒谎。用**内容/标识**判（`index`/`id` 单调、本轮是否出现新的 assistant 条目）。
2. **要让最新消息真正挂载**：
   - 该滚的是**外层滚动容器**（`.ds-scroll-area`，实测在 x≈1057 / w≈240 / h≈122），不是那个 180px 的 `.ds-virtual-list`；
   - 或者**走数据层**（`ds-virtual-list-items` 背后的数据），别依赖渲染窗口。
3. **过滤非对话内容**：每条 user 消息开头都被注入 `[studio-tool-capability] …`（~10k），会污染「最后一条消息」的判断；应按角色/来源过滤，只认真正的 assistant 轮。
4. **优先复核 SSE 通道**（见 §3.3）：普通轮拦截器已能抽出答案文本，若可用则应作为主通道，DOM 仅作交叉校验。
