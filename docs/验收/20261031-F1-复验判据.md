## 1.1 三档判定规则（避免假 FAIL / 假 PASS）

| 情形 | J2 / J5 记法 |
|---|---|
| 页面上的真实答案里**含大写标记**（模型照做了） | 按正常判据判 PASS / FAIL |
| 页面上的真实答案里**不含大写标记**（模型没服从指令） | **记「待测」**，换一轮重跑，**不算实现 FAIL** |
| 证据缺失（字段为 undefined/null） | **记「待测」**，**绝不当成 PASS** |

> **「页面上的真实答案」怎么取**：扫**真实 DOM 消息节点**（主区、排除左侧栏），**不能只看 Studio 镜像 `ds-sc-markdown`**——普通 send 轮拦截器不累积 SSE（`main-world-interceptor.ts:2093`），镜像恒空，用镜像判断会永远 false，把 J2/J5 误判成待测。探针同时给出命中节点的**祖先链**，可佐证答案在页面里的真实位置。

> **J7 与 SSE 通道的相容性**：若答案当时**不在 DOM** 里（虚拟列表卸载）但 J2 已过（说明本轮走的是 SSE 通道），J7 记**「待测」**而非 FAIL——这与 Studio-PM 的通道口径（auto-continue 轮 SSE 有值就以 SSE 为准）一致；J7 的 FAIL 只在「J2 也没过 + 答案不在 DOM」时判定。

> 探针实现：`pageAnswerHasUpper`（页面侧 DOM 采样）决定走哪一档；判据表 `f1-verdict.mjs` 已按此实现，并用两份反证样本验过：①修复前的旧产物 → FAIL 且无假 PASS；②构造「模型没照做」样本 → J2/J5 记「待测」而非 FAIL。
