→ 两个原文件的指纹已记录在上表（便于你复核），**我没有读取或外传其全文**，只做了字节数/哈希/字符构成/关键词计数与首行截断。

### 1.3 脚本

| 脚本 | 作用 |
|---|---|
| `logs/verify-f1f2/gen-attach-samples.mjs` | 生成上述两个合成样本并打指纹 |
| `logs/verify-f1f2/attach-e2e.mjs` | CDP 驱动：`--phase e2|e1|e3`；`DOM.setFileInputFiles` 上传 + 发消息 + 采集读数 |

`attach-e2e.mjs` 的能力与纪律：

- **上传**：优先复用页面现成 `input[type=file]`，没有就造一个隐藏 input，再用 `DOM.setFileInputFiles` 塞文件；随后回读 `input.files[0].name/size` 与页面上的文件 chip，确认**文件确实挂上了**。
- **发消息**：填 textarea → 先试 Enter、再回退点 `div.ds-button--circle`（UI 踩过的坑：发送控件是 div 不是 button，Enter 在某些页面态不触发）。
- **读数**（全部结构化，不含会话正文）：`Network.responseReceived` 里 `/api/v0/chat/*` 的状态码与耗时；页面错误/提示元素**原文**（`[class*=error]` / `[class*=toast]` / `[role=alert]` 等，截 300 字符内）；模型回答节点数与长度。
- **E3 加码**：倍率阶梯 ×1/×2/×3，每级记录累计字节 + 错误原文；一旦报错即停。
- 退出用 `ws.terminate()` + 120ms 收尾（P12 修法，避免 libuv 断言污染读数）。

## 2. 阶段 2 执行计划（**待 PM 放窗**）

严格按卡面顺序，**E2 先**：

1. **探活**：先发 1KB 小消息；若返回「消息发送过于频繁」/限流文案 → **立即停**，不再撞（避免延长冷却），报告只记「限流中，本轮无效」。
2. **E2（对照）**：新会话、**不传附件**，发那条 256,036 字符消息 → 记录是否接受、耗时、状态码。
3. **E1（实验）**：新会话、**只上传 456,775 B 附件**（先确认 `input.files[0].size` 对得上），再发**同一条**消息 → 记录同上。
4. **E3（加码）**：倍率阶梯递增，记录累计字节 + 错误文案原文。
5. 每条之间 **5–10 秒**间隔；每级都开**新会话**（避免历史预算污染）。

**判定**

| 结果组合 | 判定 |
|---|---|
| E2 接受 且 E1 拒绝 | 450KB 墙存在且附件不计入预算 → **附件通道值得立项**（PM 卡面即此判据） |
| E2 拒绝 且 E1 拒绝 | 墙存在且**附件计入**预算 → 附件通道价值大幅下降 |
| E2 接受 且 E1 接受 | **450KB 墙不存在或远高** → 之前撞的是限流，附件通道不成立为独立议题 |
| 任一轮出现限流文案 | 该轮**作废**，记「混入限流因素」，不判结论 |
