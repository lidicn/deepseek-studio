## 1. 过程与勘误

- **② 的勘误（P36，读侧错误）**：我前两遍解析输错了平台键名（把 Tauri 实际的 `windows-x86_64` 查成了别的写法），误读为「无 url/无 signature」。以 `logs/verify-v0140/latest-endpoint.json` 原始 JSON 为准：`platforms."windows-x86_64"` 下 **url 与 signature 俱在**（signature 为 tauri 签、内嵌 `version:0.14.0`）。误判全部发生在我读侧，包侧与端点无问题。
- **HKCU 共享键连带效应（如实报）**：装 v0.14.0 前，HKCU `Uninstall\DeepSeek++ Studio` 键的 `InstallLocation = "E:\NAS\_install_node"`（Core TD-04a 复测遗留死链，即他 04:0x 报的孤儿键在 0.14.0 安装前已被他自己的 `_install_node` 安装更新过一次）；本轮经自带 `uninstall.exe` 卸载后该键整体消失 → **Core 的 `_install_node` 死链随本轮卸载被清**（目录 `E:\NAS\_install_node` 本体未动，若仍存则属 Core 另行清理项）。
- 旧→新跨版本升级链（0.14.0 → 0.14.1）按 PM 指示留待下版本验证；0.14.0 本身即「旧版本」基线，本轮不构造跨版本升级（且 ④ 缺陷未修前也验不了：没有调用点）。
