## 五、须出资人裁决的一项（PM 不代决）

**审批面在页面 DOM 内。** `src/ui/consent.ts` 的 `showConsent` 直接在聊天页里建 `div.ds-consent-overlay` 挂进 `document.body`；宿主侧对应分支（`src/host/desktop-host.ts` 约 2611–2618 行处「**普通审批** ⇒ 页内模态唯一路径」）也是这么分的。

> **分支定位订正（Core 从源码核出，我采纳）**：我原文写「非越界高风险 ⇒ 页内模态」**不准确**。
> `memory.purge` 走的是**「普通审批」支**，不是「非越界高风险」支——判据在 `desktop-host.ts` 约 522–529 行 `isHighRiskConsent`
> （只认 `outside`／`hardRule`／`allowConversation`／`riskFlags` 非空），purge 四项都不命中 ⇒ 落到约 2611 行的 else 分支。
> **这与现场日志尾部原文一致**：`（普通审批：暂无独立窗口支）`＝该行（`desktop-host.ts` 约 2617 行）。
>
> 四格结构现状（源码原文）：
>
> | 分支 | 位置 | 审批面 |
> |---|---|---|
> | 越界高风险 | 约 2559–2576 行 | **强制宿主侧独立窗**，起不来即 `host-unavailable-deny`，明写「绝不回退页内」 |
> | 非越界高风险 | 约 2577–2589 行 | 页内模态为主路径，页不可用才降级宿主窗 |
> | **其余（普通审批）** | 约 2612–2618 行 | **页内模态唯一路径**，注释自陈「这就是 AGENTS 要禁的那一支，等拍板前继续服役」 |
> | 手势校验 | `src/ui/consent.ts` 约 431–434 行 | 只校 `e.isTrusted !== true` ⇒ CDP 的 `Input.dispatchMouseEvent` 恒 true，能代点 |

而 `AGENTS.md` 明写：「审批界面须独立于当前页面 DOM，agent 不得控制或影响其内容」。

本轮能确证的后果：`src/ui/consent.ts` 约 424–436 行的防伪判据只校验 `e.isTrusted === true`，而 **CDP 自动化输入产生的事件 `isTrusted` 也是 `true`** ⇒ 自动化能替人点掉审批卡。本轮那次「放行」正是我的 CDP 点击被当成了真实用户手势（见第六节）。

⇒ 这不是新缺陷（是既有设计），但它与 AGENTS 那条硬规则相抵触。**改哪一边归出资人拍板**：改产品（高风险类改走独立原生窗 `src/ui/consent-panel.ts` 那条路）还是改规则（承认「完全放开」档下页内模态可接受）。PM 不代决。

> **威胁面定性（Core 从源码核出，我采纳并独立认同）**：**页内脚本仍然伪造不了**——JS `dispatchEvent`／`.click()` 产生的事件 `isTrusted` 恒 `false`，被约 431–434 行拦下 ⇒
> 「**agent 控制页面自答审批**」这条威胁**没有破**。能点掉的是**页外本地驱动**（CDP 要在本机起调试口、要本机进程权限），
> 而**同一权限已足以直接读 config token 绕开一切审批** ⇒ 这是**纵深防御缺口**，不是远程可利用。
>
> **补做成本不高**：`askHostSide()`＋`hostConsentQueue` 那条**宿主原生窗路径已经现成**（越界支在用），要改的是约 2611 行那个 else 的路由；
> 但原生窗**当前不显示档位与 canonicalTarget**（`desktop-host.ts` 约 2427 行注释自陈），这是选它当主路径前的**必补项**。
> 且该路由正好靠卡㊾ 修好的轮询器送 pending ⇒ **两条修复同源**。

## 六、一次自认（照实记）

我原计划用「点『拒绝』」验拒绝路径。执行时审批卡已不在（`present=false`），脚本如实报了 `[MISS]`，没有伪造点击。**真删是更早一步发生的**：我点「彻底删除」后 1.5 秒，卡片还在（原文已取到）；再跑拒绝脚本时卡片已消失、审计显示 `outcome=executed`、`durationMs=4659`。

根因（读源码坐实）：`src/ui/consent.ts` 约 432 行的 `trustedGesture` 只看 `e.isTrusted === true`；CDP `Input.dispatchMouseEvent` 产生的事件 `isTrusted` 为 `true` ⇒ **我的自动化点击被页端当成了出资人的真实手势**，点了「允许一次」。

**教训（我自己的）**：用自动化驱动审批类 UI 时，必须先确认「自动化输入会不会被当成真实手势」——本仓这处只查 `isTrusted`，对 CDP 输入无效。**下次验拒绝路径，得用 DOM 层注入或改走宿主 `/v1/consent/reply` 接口，不能靠真实鼠标事件。**

## 七、顺带查实的三条事实

1. **审计不跨实例存活**：`GET /v1/tools/audit` 的数据在宿主内存态，实例一重启即清空（本轮重起后查 `memory.purge` 历史条目＝0 枚，尽管库里 `memory_log` 仍有 `op:"purge"`）。⇒ 审计取证必须在**同一实例生命周期内**取。
2. **记忆写库是双闸**：`memory.save` 从 HTTP 直调会被两层拒——先「内容含任务句式／工具名」被拒（`memory-save-task-snapshot`），再「宿主无法定位本轮用户消息」被拒（`memory-save-no-user-turn`）。两次拒绝都带 `terminate: true`（正是案甲修的那条路径在真实产品里生效）。⇒ 自动化**建不出**测试记忆，验证只能用既有记忆。
3. **`memory.delete`（归档）在「完全放开」档下免审批**（审计 `reason=full-mode-allow`），而 `memory.purge` 不在 `FULL_MODE_STILL_ASKS` 之外的那一侧 ⇒ **不可恢复操作才留闸**，与设计意图一致。

## 七之二、另有一枚对「卡㊾-补案甲」夹具的自查（UI 提出疑点，我独立复核后落定）

UI 在群里提出：`tests/desktop/studio-chat-ui.test.ts` 的 132 行夹具 `driveToolResult` **手拼卡形 result**

**我独立复核的结论分两半**：

- **「真链落 undefined」不成立。** 链路逐段现读：`src/shared/tool-result-format.ts` 约 55 行 `ToolExecutionResult.terminate` →
  `src/desktop/host-client.ts` 约 409 行透传 → `src/inject/main-world-interceptor.ts` 约 3093 行 `terminate: r.terminate` **填进卡形 result 的 `terminate` 槽** →
  `src/inject/tool-card-ui.ts` 约 48 行那个槽本就是 `ToolCardData['result']` 的合法字段 →
  `src/ui/studio-chat-ui.ts` 约 1027 行 `terminate: result.terminate` **顶层出事件**。**数据源是通的。**
- **「夹具驱动面手拼」成立。** 我的夹具确实没有走真实执行段。

⇒ **我补了一枚自查夹具** `tests/desktop/pmg-probe-terminate-chain.test.ts`（**不改任何业务源码**）：
第 1 段用**真实业务代码** `runToolCall`（`src/shared/tool-loop.ts`，其 before 钩子拦截分支会 `skipResult.terminate = true`）产出 `terminate=true`；
第 2 段按 `executeTool` 真返回形态组装卡形 result；第 3 段走**真实 `finishToolCard`** 断言事件顶层 `terminate===true` 且 payload 内不再有 `terminate`。
现跑：**1 file／1 passed／EXIT=0**。

> 过程中我踩了一个坑并修正（照实记）：首版自查夹具**没有把 `ui.container` 挂进 DOM** ⇒ `finishToolCard` 里的
