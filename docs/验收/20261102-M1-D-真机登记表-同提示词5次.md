## 阶段 1：同提示词 5 次

**固定提示词**（每次一字不改，建议用需要长输出的题目以便观察哨兵）：

```
请用中文详细讲解 SSE 流式响应中的完成信号（FINISHED / [DONE] / task_complete）各自的语义与差异，
每种至少给一个例子和一个常见误用，输出不少于 800 字。
```

**执行纪律**

- 每次**新会话**（避免上下文与预算互相影响）；
- 两次之间间隔 **8–15 秒**；
- 每轮记录：发送时刻、HTTP 状态码、**响应字节数**、宿主终态（`completion=`/`reason=`）、耗时、**页面侧哨兵结论**；
- 若某一轮返回「消息发送过于频繁」→ **停止剩余轮次**，在 §登记 写明「第 N 轮限流中止，已完成 N−1 轮」，不重试。

## 阶段 2：判读口径

| 观察 | 判定 |
|---|---|
| 5 轮全部有哨兵、宿主终态全 `complete` | 基线正常，**未观测 ≠ 不存在**（长流无哨兵仍可能存在，只是本提示词不触发） |
| 出现「无哨兵」轮次且宿主终态为 `truncated`/`unknown`/超时 | **哨兵缺失可复现**，M1 的 `interrupted` 判定有实证支撑 |
| 出现「无哨兵」轮次但宿主终态仍是 `complete` | 哨兵缺失**未影响判停**（可能走了 `task_complete` 旁路或页面侧兜底），需回看该轮页侧日志 |
| 任一轮限流 | 本轮**作废**，只记已完成的轮数，**不下结论** |
