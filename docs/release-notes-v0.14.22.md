# v0.14.22 发版说明

发布日期：2026-11-15（tag `v0.14.22`，自 `v0.14.21` 起三笔工程批次）

## 这版修了什么

### 1. 「同一调用被反复拒绝刷屏」根治（⑨ 系，`9cc0df8`＋`be72e12`）

**现象**（2026-11-15 真机实测）：让 Studio「用 AutoForge 查询客厅设备」，模型却先去"保存记忆"，被记忆硬闸正确拒绝后**不知停手**——同一轮内换了 129 种写法重发 `memory_save` 共 **135 次、约 3 分钟**，红字刷屏，你真正要的工具一次都没被调用。

**根因**：硬闸拒绝时只回了错误文案，没发"停止"信号；注入层现存的停止闸读错了字段（读 payload 内部，实际在同级的被丢弃字段上），兜底只剩 25 轮上限——135 ≈ 25 轮 × 每轮 5 枚，正好撞顶。那 8 条旧测试只测了"生产环境永远不会出现的输入形状"，所以测试全绿、机制零效力。

**修复**：
- 所有"参数再试也不会变"的策略性拒绝（终局族）统一携带机器可读停止信号（`terminate`，与结果同级）；
- 双轴熔断：同一轮内同一 `(工具, 拒绝码)` **终局拒 3 枚**或**非终局失败 5 枚**即熔断并给可见交代——任何写法都刷不出 135 枚；
- 两句可见文案语义冻结：终局轴明说**"这条不会再重试"**；非终局轴（如页面未就绪）明说**"这不是对该调用的拒绝，可能自行恢复"**——不会把"等环境就绪"误报成"永久失败"。

**修复后你看到的差别**：最多 3 条红字就停，并出现一句人话解释，不再刷屏 3 分钟。

### 2. 登录态掉线可归因（⑩，`86bc134`）

2026-11-15 17:04 出现第三次登录态掉线。本机侧全排除后初判为服务端会话作废，但此前日志**只记响应字节数不记 HTTP 状态码**，掉线时刻无法精确归因。本版给注入层加五格取证：

- 所有 DeepSeek API 响应记录 HTTP 状态码，**401/403 单独成行**（`[auth] HTTP 401 on …`）——掉线时刻精确到秒、哪个接口；
- 登录/MFA/登出等 auth 接口请求与响应留痕（脱敏：只记参数键名与 `device_id=present|absent`，**明文密码与验证码值不落盘**）；
- 会话 cookie 的设置变动逐条留痕（只记名字与过期时间，不记值）；
- 每次页面载入记一行起手登录态自检（`[auth] boot-check …`）；
- 站点代码读取会话存储失败时留痕（`[auth] ls-read-fail …`）。

**下次掉线的判案口径**：起手自检正常＋无存储读取失败＋401 前无本地异常 ⇒ 服务端作废（与我方代码无关）；反之按行号直接溯源我方缺陷。
