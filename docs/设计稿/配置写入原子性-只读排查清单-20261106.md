## 0. 为什么有这份清单

一条被现场串起来的静默数据丢失链（PM 裁定二十/二十一/二十二）：

```
非原子写 → 磁盘满/中断 → 文件剩半截 JSON
        → loadMcpServers catch 折叠成 {} → 面板显示「一台都没有」
        → 用户保存一台 → saveServer catch 又吞掉 parse 失败、从 {servers:{}} 起写
        → 用户其余 MCP 配置全部静默丢失，无日志
```

三条单独看都「还行」，串起来是一条完整链路。所以判据是**两条**，不是逐处打补丁：

1. **IO/解析失败必须与「空状态」可区分**（`ENOENT` = 空表合法；parse/read 失败 = 显式错误）；
2. **关键文件写入必须原子**（`.tmp` + `rename`）。
