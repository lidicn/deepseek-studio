## 〇、结论

1. **推荐方案甲**：给 **dev 树一个独立 identifier**（开发专用 tauri 配置，打包/发布路径不动）。它一次性解决两件事——**互斥量名**与 **WebView2 档案根**——因为两者都由 identifier 派生。

4. **不做**：改装版 identifier、动发布链、fork/patch 插件、在本卡起实例。

## 二、为什么这是验收阻塞项（两条，都很具体）

1. **锁互挡**：装版与 dev 同 identifier ⇒ 同 `com.deepseek.studio-sim` ⇒ 装版开着时起 dev，**第二个进程被插件拦下、只把装版窗口提到前台**。今天 13:0x 那次放窗就是这个前提（PM 先现查装版进程＝0 才敢让我起）。
2. **档案混血 ⇒ 归因不可靠**：同一份 `EBWebView` 里既有装版的 Cookie／localStorage，也有 dev 会话写进去的东西。11-14 的登录 422 与"两天掉两次登录态"当初分不清，根因之一就是这层混血；而**判据表 §二 要判的恰恰是"哪一次 401 属于哪棵树"**。

## 三、候选方案与改动面

### 甲（推荐）：dev 专用 identifier ＋ dev 专用日志根

**做法**：新增一份**开发专用** tauri 配置（例如 `src-tauri/tauri.conf.dev.json`，只覆盖 `identifier`），由 dev 启动脚本用 `--config` 合入；`tauri.conf.json`（打包用）**一字不改**。

| 面 | 甲之后 | 对装版的影响 |
|---|---|---|
| 互斥量名 | `com.deepseek.studio.dev-sim` | 无（装版仍是 `com.deepseek.studio-sim`） |
| WebView2 档案根 | `%LOCALAPPDATA%\com.deepseek.studio.dev\EBWebView` | 无 |
| 配置根 | `~/.config/deepseek-studio`（dev 分支不变） | 无 |
| 日志根 | 需显式 `STUDIO_LOG_DIR` 指 dev 专档（否则仍共用第 5 行） | 无 |
| `app_data_dir` | dev 拿到的仍是"未打包"分支 ⇒ 不进 `resolve_config_dir` 的装版分支 | 无 |

**碰哪些文件**：`src-tauri/tauri.conf.dev.json`（新）＋启动脚本／`package.json` 的 dev 命令（加 `--config`）＋（若采纳日志分档）dev 启动时的环境变量一处。**不碰** `src/**` 业务码。

### 乙：只分离档案，不分离 identifier

**做法**：给主窗口显式指定 `data_directory`（Tauri builder 已有这条能力——多 bot 窗口就是用 `dataDir` 隔离登录态的，`src-tauri/src/main.rs` 约第 409–415 行注释与 `BotWindowConfig.data_dir` 字段现读），或用 `WEBVIEW2_USER_DATA_FOLDER`。

- **效果**：Cookie／localStorage／IndexedDB 分开。
- **硬伤**：**锁名仍由 identifier 派生（第 2 行）⇒ 与装版仍互挡**。单做乙**不满足 Verify 的需求**，只能作为甲的补充或过渡。

### 丙：运行时开关（同一个 exe 按参数切档案与锁名）

**否掉**，代价最高且当前不可能：Windows 侧锁名由插件在 `windows.rs` 里用 identifier 直接构造，**该版本没有公开的改名 API**（`lib.rs` 里唯一的 `dbus_id` 只作用于 Linux，现读其注释即"Set a custom D-Bus ID, used on Linux"）。要做得 fork 或 patch 插件——为一张"铺路稿"付这个代价不值。

## 五、推荐值、默认取值与回退口径

- **推荐**：甲（dev 专用 identifier）**＋** dev 专用 `STUDIO_LOG_DIR`。理由：一次改动同时解开锁与档案两处，且这两处本来就由同一个键派生；再叠一个日志分档，取证时"哪棵树写的"不再需要推断。
- **默认取值（PM 不回话时按此走）**：甲＋日志分档。
- **回退口径**：若 PM 判断"dev 树改 identifier"风险大于收益（例如担心开发/打包配置分叉），则退到**乙单独做**；但必须在台账里写明**乙只分离档案、不分离锁**——装版开着时 dev 仍起不来，Verify 的合取 (a) 仍要等"装版关闭窗口"。
- **验收前置（写给下一次真机验收）**：分档落地后，起 dev 实例**不再需要先关装版**；但请**不要把"分档"当成"(a) 已经拿到"**——分档解除的是"能否起一个干净 dev 实例"的**准入**阻塞，预 OPEN 窗口仍需自然出现（或在合规范围内由既有读数求得）。

## 八、端口分档与 wsUrl 同源跟随（2026-11-17 Core 出稿；上面历史小节一字未改）

> **性质**：仍是零实现的设计稿，为**下一张代码卡**铺路。本节六问全部基于写作时**现读**的行号；路径为仓库相对路径，行号写在叙述文字里、不作活锚。
> **与 §七 的关系**：§七 的结论「identifier 分档解开锁与档案、**解不开端口**」**仍然成立**——端口不在 identifier 的派生链上。本节补的是后半句：端口由 `config.json` 的 `port` 单源决定，dev 与装版现在读到同一个值，**给它换一个值即可**，不必碰 identifier、不必碰发布链。

### 8.0 先把"第二处互斥"的机理说准

§七 写「8760 是 dev 与装版的第二处互斥」，方向对、结论对，但**机理只覆盖一半**。完整机理是两条**互不相干**的派生链：

- 锁名 ← `bundle identifier` ← `tauri.conf*.json`（甲之后分档，见 §四／§五）
- 端口 ← `config.json` 的 `port` ← `DEEPSEEK_STUDIO_PORT` env（**identifier 不参与**）

所以「分档后 dev 与装版可同时跑」要成立，必须**两条链同时分档**：identifier 那条已由卡㊴ 落地，端口这条本节给口径。只做前者不做事后者，dev 仍会被装版挡住（不是被锁挡，是被端口挡）。

### 8.2 六问

#### ① dev 侧端口取什么值、由谁决定、与 TD-06 单源怎么接

- **取值**：`8761`。理由：装版占 `8760`（产品常量，`sidecar.rs` 约第 23 行），另两个相邻端口 `8756`（豆包沙箱）与 `8765`（DeskPilot）按 `src/api/main.ts` 约第 6 行的注释已在避让。`8761` 已在卡㊶ 第二跑被实测可用（dev 宿主在 8761 正常应答）。
- **由谁决定**：`DEEPSEEK_STUDIO_PORT` env 优先 → dev 的 `~/.config/deepseek-studio/config.json` 的 `port` → `8760`。现读 dev 那份 config.json：**190 B／mtime 2026-11-14 10:33:24，`"port": 8760`**——与装版同值，这正是互斥的根。
- **与 TD-06 怎么接**：单源已存在，**不需要改解析链**。dev 侧只要让「dev 读到的 port」变成 8761，Rust 的解析链自然产出 8761，并在 spawn 时注入子进程 env（约第 836 行），node 侧第一优先级命中同一值 ⇒ 四处同一端口。两条落地路：
  - **(a) 改 dev 的 config.json**：`port` 改 `8761`（持久、不依赖启动命令）。写盘只在「缺 token 或缺 secret」时发生（`src/api/config-loader.ts` 约第 178 行的 `if (!configFileBroken && (!stored.token || !stored.secret))`），dev 那份现已具备两者 ⇒ **改 port 不会被宿主覆盖**。
  - **(b) dev 启动脚本设 `DEEPSEEK_STUDIO_PORT=8761`**：Rust 约第 146 行的 `std::env::var(HEALTH_PORT_ENV)` 会读到 ⇒ 同样单源。
  - **推荐 (a)+(b) 并用**：env 保证本次，config 保证下次（用户直接跑 `cargo run` 也不会回弹到 8760）。
- ⚠️ **与 `STUDIO_LOG_DIR` 不是同族**：那个 env 只有 node 侧读（Rust 不读父进程 env），所以 §七 才判它「把本来同源的一处日志拆成两处」；`DEEPSEEK_STUDIO_PORT` 是 Rust 与 node **双读同一 env**、Rust 还在 spawn 时再注入一次 ⇒ **不存在分叉**。这一点要写进那张代码卡，免得后人拿 §七 的结论类推到端口上。
- ⚠️ **测试面副作用**：dev 跑 `cargo test` 时若该 env 在位，td05 那组装置会 panic——`sidecar.rs` 约第 1428–1460 行的 `assert_8760_free_or_die` 要求端口解析结果就是 8760（约第 1440 行的报错文案写明「请先 unset `DEEPSEEK_STUDIO_PORT`」）。这是测试面的事，不是生产面；代码卡要写清「设 env 只作用于 dev 启动，不进 `cargo test`」。
- **顺带发现一处文字与运行时不符（须随代码卡改）**：`src/ui/studio-settings-panel.ts` 约第 185 行把「宿主端口」**写死**成 `8760`，无任何动态绑定 ⇒ 端口分档后这行显示错值。属 UI 席位文件，本稿只记不改。

#### ② 页端与聊天室的 `wsUrl` 如何同源跟随——传参路径逐枚

先把两条**不同**的 ws 通道分开，它们不是同一条：

**(a) 聊天室（`chat.deepseek.com` 页内 overlay，多 bot 编排）——已经同源**

**(b) 桌面注入脚本 → 宿主 `/studio`——唯一真硬编码**

⇒ 这是端口分档后 **dev 会串到装版**的那一处：dev 宿主听 8761，注入脚本却连 8760（装版）。

**(c) 工作台面板 → 宿主 `/agent-ws`（独立 origin）——天然同源**

`src/ui/agent-panel.ts` 约第 178 行用 `${proto}://${location.host}/agent-ws?token=...`，端口取自 `location.host`；而工作台窗口 URL 由 Rust 的 `workbench_url()` 决定（`src-tauri/src/main.rs` 约第 1157–1160 行走 `studio_host_port()`）⇒ **不需要额外机制**。

#### ③ 审批面不受损：轮询地址、信任边界、K2 闭环

- **轮询地址随端口迁移**：`src-tauri/src/consent_window.rs` 约第 575 行 `let (host, port) = studio_host_port();` ⇒ 轮询的是 `http://{host}:{port}/v1/consent/pending`（路径段常量 `CONSENT_PENDING_PATH` 在约第 54 行，只含 `/v1/consent/pending`，不含端口）。窗口 URL 与页面 origin 同样同源：`consent_window_url(host, port)`（约第 72–75 行，注释自认「与工作台、MCP 设置窗同源」）＋ 注入脚本里的 `window.__STUDIO_API_ORIGIN__`（约第 155 行）。⇒ **端口迁移后审批面自动跟随**，不需要改机制。
- **必须改的文字（两处，过时口径）**：同文件约第 19 行的示意图与约第 25 行的「这样 8760 仍是唯一信任边界」**已与运行时不符**——实际边界跟随 `studio_host_port()`，不再是固定的 8760。按本仓「文字与运行时一致」的纪律，这两处注释须随代码卡一并改（本卡不改代码，只记）。
