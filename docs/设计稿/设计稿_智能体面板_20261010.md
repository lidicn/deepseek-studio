日期：2026-10-10
状态：需求已定稿，待排期实施

## 1. 需求定稿（访谈结论）

| 决策点 | 结论 |
|---|---|
| 产品定位 | 完整智能体，对标 Workbuddy / Qoder / Trae |
| 主入口 | Studio 专用对话面板（宿主驱动 agent loop）；chat.deepseek.com 网页 tab 保留备用 |
| 模型引擎 | 可插拔：MVP 用网页引擎（chat.deepseek.com 当后台模型，零成本），预留官方 API 引擎随时切换 |
| 任务形态 | Trae 式：每次「打开文件夹」进入项目，智能体在其中读代码/改代码/跑构建测试 |
| 写审批形态 | Trae 式 diff 卡片（M2 落地；MVP 先用简单审批弹窗） |
| 权限 | 三档可随时切换：①仅工作区读写 ②风险才审批（默认）③完全放开 |
| 用户核心诉求 | **不需要自己敲命令**——自然语言下指令，智能体自主多步执行 |

## 2. 总体架构

```
┌─ Tauri App ──────────────────────────────────────────┐
│  面板 UI（AgentChat webview，M1 新建）                 │
│    会话流 / 工具执行卡片 / 审批弹窗 / 状态栏(权限档位)    │
│  Host（Node 宿主，v0.5 已有地基）                      │
│    AgentLoop      驱动 引擎↔工具 循环，多步连续执行      │
│    ToolRegistry   file.read/write/list/stat、shell.exec│
│    PolicyEngine   三档权限 + 审批闸（扩展 policy.ts）   │
│    AuditRing      全终态审计（已有）                   │
│  ModelEngine（可插拔接口）                              │
│    WebEngine  后台隐藏 webview → chat.deepseek.com     │
│               （复用现有注入拦截器做响应解析）            │
│    ApiEngine  DeepSeek 官方 API（原生 function calling）│
└──────────────────────────────────────────────────────┘
```

关键思想：**引擎差异被隔离在 ModelEngine 层**。AgentLoop 只面向统一的内部 ToolCall 格式，WebEngine 的 XML 标签协议与 ApiEngine 的 function calling 都在各自引擎内转换。

## 3. ModelEngine 接口

```ts
interface ModelEngine {
  name: 'web' | 'api';
  chat(req: { system: string; messages: Msg[] }): Promise<{ content: string }>;
  health(): Promise<{ ok: boolean; reason?: string }>;
}
```

- **WebEngine**（MVP）：
  - 后台隐藏 Tauri webview 常驻加载 chat.deepseek.com（登录态复用现有网页 tab 的会话）。
  - 发送：向页面注入用户消息并触发发送（chat-send 能力已有）。
  - 接收：复用 `src/inject/main-world-interceptor.ts` 的响应解析与工具标签提取。
  - 协议：工具调用 = XML 标签（`<local_file_read>{...}</local_file_read>` 等），与现有拦截器一致。
  - 纠偏：回复中标签 JSON 解析失败 → 自动附带纠错提示重试 1 次；仍失败 → 向用户报错。
  - 卡死看门狗：单步超时（默认 120s）→ 中止该步并提示。

- **ApiEngine**（M3）：
  - DeepSeek 官方 API，原生 function calling，工具 schema 直传。
  - 配置项 `engine: 'web' | 'api'` + `apiKey`，设置页可切；失败自动降级提示。

## 4. AgentLoop

```
用户消息 → [system prompt: 工具清单+格式+当前工作区路径]
  └─ 循环：
       engine.chat(messages) → 解析 ToolCall[]
         ├─ 无 ToolCall → 输出最终回答，回合结束
         └─ 有 ToolCall → 逐个过 PolicyEngine
              ├─ 放行 → 执行 → 结果以 tool-result 追加回 messages → 继续循环
              ├─ 需审批 → 弹窗（M2: diff 卡片）→ 允许则执行 / 拒绝则把拒绝原因回填
              └─ 拒绝(档位1越权) → 把拒绝原因回填，模型自行调整
```

防失控护栏：
- `max_steps`（默认 15 步/回合，可配）
- 用户「停止」按钮随时中断（中断后上下文保留，可继续）
- 单步工具超时（shell 30s/上限 120s，沿用 v0.5）
- token/消息长度预算，超限触发历史压缩（M2）

## 5. 工具集（MVP）

| 工具 | 说明 | 权限 |
|---|---|---|
| `file.read` | 读文件（文本） | 档位2/3 工作区内自动；出区审批；档位1出区拒绝 |
| `file.write` | 写/覆盖文件 | MVP：审批弹窗；M2：diff 卡片；档位3 自动 |
| `file.list` | 列目录/搜索文件 | 同 read |
| `file.stat` | 文件元信息 | 同 read |
| `shell.exec` | 执行命令（argv、超时、截断，沿用 v0.5 shell 能力） | **所有档位除③外都审批**；档位3 自动+审计 |

复用 v0.5 既有实现：`capabilities/file.ts`（realpath 防软链）、`capabilities/shell.ts`（argv spawn 禁 shell:true）、`host/policy.ts`、`host/workspace.ts`、`host/audit.ts`、`host-token.ts` 令牌环。

## 6. 三档权限（扩展现有 policy.ts）

| 档位 | 名称 | 行为 |
|---|---|---|
| 1 | 仅工作区 | 读写限于工作区目录内；shell 拒绝；出区拒绝 |
| 2 | 风险审批（默认） | 工作区内读/写自动（M2 写改 diff 卡片）；shell、删除、出区 → 审批 |
| 3 | 完全放开 | 全部自动执行，仅审计留痕 |

- 会话内随时切换，状态栏常驻显示当前档位（如 🟢工作区 / 🟡审批 / 🔴放开）。
- 工作区 = 「打开文件夹」所选目录（Tauri dialog API），打开即权限边界，替代现在的 `STUDIO_WORKSPACE_ROOT` 环境变量（保留作为无头默认）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 网页引擎易碎（改版/风控/掉登录/限流） | health() 探测 + 明确错误提示引导切换 API；看门狗防卡死；登录态检测 |
| XML 标签协议偶发失守（网页模型忘格式） | system prompt 强约束 + 解析失败自动纠偏重试 + ApiEngine 兜底 |
| 模型多步执行失控 | max_steps + 停止按钮 + 三档权限兜底 + 全终态审计 |
| 命令执行破坏性 | 沿用 v0.5：argv 直spawn 禁 shell:true、超时、输出截断；档位2 一律审批 |
